# GUI 重设计：实施结果

日期：2026-10-16。状态：S1–S5 已实施，日常本机 App 已替换并恢复采集。原始设计稿、HTML 动效预览和当前原生合成截图均保存在本章；未提交、未推送。

## 实现与最终参数

| 部位 | 实现 |
| --- | --- |
| 菜单栏 | `NSStatusItem` 以 `999 T/s` 为 47 pt 基准，更长数值按需扩宽，异常值上限为 70 pt；等宽数字，非负速度四舍五入到整数 `T/s`，移除波形与约等号 |
| 思考 | 三个 4 pt 小点，依次轻跳约 2.5 pt；周期 1.35 秒，错开 0.18 秒 |
| 执行 | 系统 `hammer.fill` 单色锤子，绕握柄连续两下敲击、回弹、停顿；周期 1.65 秒 |
| 时钟 | 动画最高 30 Hz，仅重绘；数据沿用约 1 Hz，采集和分词频率不随动画提高 |
| 面板 | 内容宽 420 pt；默认两条活跃聊天加折叠近期项实测高 229 pt，展开首条高 334 pt；列表上限 `min(520 pt, 可用高度的 60%)` |
| 列表 | 两行聊天、按需指标 / 活动 / 子代理；稳定身份与会话内排名；近期终态约 10 分钟内最多 10 项，默认折叠 |
| 设置 | 顶部唯一齿轮，保留配置、恢复、登录启动、退出及原管理条件；恢复说明自适应完整换行 |
| 位置 / 收起 | 原生 NSPopover，显式内容尺寸、按屏幕坐标限制窗口在按钮下方；外部点击、失去应用激活、入口切换和 Esc 统一关闭，内部关联菜单及确认框有边界保护 |

超过菜单栏基准宽度的数值先按实际文本扩宽；超过 70 pt 容量的异常数值显示 `>上限 T/s`，完整整数留在悬停说明；面板极端值显示 `>99999 T/s`。实测 `1e100` 没有撑宽或显示貌似完整的截断数字。普通值保留完整整数。减少动态效果时保留静态三点 / 锤子及可访问状态文字。

### 语义与计量边界

核心新增可选版本化 `menu_presentation`：`version / mode / reason / active_conversation_count`，总速仍读取现有 `overview`。它复用明确活动与流生命周期，不解析中文，不用速率是否归零判断阶段。单主聊天按生成 → 确认执行 → 确认思考排序；多主聊天始终总速，部分覆盖 / 不可靠状态为 `—`。活动生成短暂停顿保持生成，已结束流的残余速率不延迟工具图标。

按同一 scope 内明确父子身份统计主聊天；父已完成、子仍工作也保留组。镜像去重、独立流加总、旧 `active_thread_count`、Output 包含 Reasoning、推理均速定义与原始数值精度不变。TUI 格式未修改。旧快照无新增投影时降级为可靠数值，未知契约版本 / 模式和过期快照不会播放动画。

主要代码为 [menu_presentation.py](../../src/codex_progress_monitor/menu_presentation.py)、[Snapshot.swift](../../macos/Sources/MonitorModel/Snapshot.swift)、[DashboardView.swift](../../macos/Sources/MonitorApp/DashboardView.swift)、[PopoverController.swift](../../macos/Sources/MonitorApp/PopoverController.swift) 和 [StatusContentView.swift](../../macos/Sources/MonitorApp/StatusContentView.swift)。管理事务继续调用原实现。

原生动画短片由 `--preview-status` 中的同一 `StatusContentView` 截图序列生成，是固定样本渲染证据，不是整个系统菜单栏录像或帧率基准。全屏验证只对 Preview 自身设置临时 presentationOptions，未改系统菜单栏、Dock、减少动态效果或外观偏好。

检查过程中发现 SwiftUI hosting 自动尺寸与显式 popover 尺寸会竞争；现在关闭 host 自动 sizing，以内容测量设定尺寸，并用按钮所在屏幕的坐标约束完整窗口。外部输入监听仅在面板显示时注册，关闭后释放；不吞目标鼠标事件、不申请额外输入监控权限。上述实现和原生记录支持修复结果，不把某个原有标志单独称为旧问题的唯一根因。

自动化工具读取 App 状态时可能通过 reopen 重新打开面板。因此关闭证据依据事件顺序和 `shown=false / monitor_count=0`，不把后续被工具重开的 AX 树当作关闭失败。

## 后续调整：三位数基准与动态扩宽（2026-10-16）

用户进一步确认以 `999 T/s` 为常用容量，取消此前全状态固定 70 pt 的方案。现用同一 12 pt 字体测得基准文本宽 42.66 pt，含左右各 6 pt 留白后为 55 pt；四位、五位、六位数分别按文本扩展至 63、70、78 pt，回到三位数以内或动画 / 未知状态时收回 55 pt。异常长数值沿用有界提示，最大保留 78 pt；完整值仍可悬停查看。只在所需长度变化时更新 `NSStatusItem.length`，已打开面板同时刷新锚定区域，原生预览使用同一宽度函数。

## 后续调整：减少内容留白（2026-10-16）
