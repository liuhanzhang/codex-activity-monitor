# 系统性 Code Review

审查基线：`6314547`，2026-10-22。开始时工作区干净。覆盖产品 Python、Swift、资源、入口脚本、回归测试组织和仓库开发入口；历史实验用于核对设计约束，不把历史报告当作当前验收。

结论：保留现有「原版后端 + 可丢弃观察通道 + 独立聚合 + 只读历史」架构。最需要修正的是身份关联、历史事实的可撤换性、异步详情的一致契约，以及运行存活与磁盘新鲜度的混用。没有证据支持为了优雅而整体重写采集协议、引入通用事件框架或更换 UI 技术。

本轮已完成下列确认问题的修复和有针对性的职责拆分。**这次审查完成，不等于产品已经满足公开发行条件。** 未完成的发行和设计事项列在后文。

## 仍需安排的工程工作

这些是明确保留的设计债务或证据缺口，不作为已经修复的缺陷报告。

1. **GUI IPC 与阻塞型磁盘 I/O**：CR06 解决可抛出的写盘错误和重复启动，不解决主循环在慢磁盘上的阻塞。下一步应做独立实时通道、心跳、有界最新状态发送及恢复持久化。不要继续加大 freshness 超时掩盖问题。详细目标沿用 [TODO](../TODO.md)。
2. **统一子进程执行器**：`BackendClient` 缺少统一超时／取消，stdout 与 stderr 顺序读取有潜在管道互等；`QueryProcess` 有截止时间但只发 SIGTERM。建议一个可注入执行器并发排空输出、限制大小、处理取消和超时。当前未注入“写满 stderr / 忽略 SIGTERM”场景，不能把风险写成已观测卡死。
3. **分页源版本契约**：本轮验证身份与游标，但协议没有内容 revision。相同活动在两页之间被来源重写时，客户端还不能证明两页属于同一内容版本。应增加可稳定比较的 section revision，再定义拒绝旧页／重新加载行为；不能使用每次新建 provider 的随机 generation 作为跨进程游标。
4. **长期规模与内存预算**：桥接队列、正文、部分缓存有上限；单个长期 rollout 的全部索引元数据、活动 turn 的 item 身份以及 tokenizer 待处理任务仍需规模测试。先测峰值、延迟和元数据量，再决定分段索引或 tombstone 预算；不能随意删 ID 后允许迟到事件重新打开活动。
5. **边界类型与格式约定**：部分 Python 字典仍承担协议、领域和展示多种角色。优先给公开读接口和持久化记录补稳定类型／契约；后续按修改范围统一现有密集格式。没有在本轮做全仓机械格式化，也没有引入第二套领域状态或通用框架。
6. **GUI 投影性能**：Snapshot 的分组和祖先计算在多个 getter / 行中重复执行。当前受控 UI 样本不足以证明大量活跃会话的性能；可对不可变快照预建分组索引，但应先保留真实规模测量。
