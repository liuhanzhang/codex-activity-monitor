# 英语支持：验收计划

日期：2026-10-22。状态：本轮资源、定向检查和隔离原生验收已执行；结果及未覆盖的发行／自然使用边界见[实施结果](implementation-results.md)。下文继续作为验收标准。

## 1. 资源与格式化

| 场景 | 预期 |
| --- | --- |
| 资源完整性 | Python `zh-CN / en` 的 key、模板参数完整；GUI 两种语言覆盖所有使用中的自有文案。缺 key、缺参、不支持的模板在资源检查中明确失败。 |
| 正式语言发布 | 可用列表仅包含完整的 `zh-CN / en`，不包含测试语言；不能靠中文副本通过英语完整性检查。 |
| 数量与嵌套消息 | 0／1／2 个聊天、并行活动、子智能体、额外文件等英文语法正确，嵌套活动同样使用当前语言。 |
| 跨端格式化 | Python 与 Swift 对共用活动样例输出一致，覆盖目标前缀、数字格式、单复数、嵌套和缺值回退；导出资源可重复且未过期。 |
| 非法输入 | 未知 key、错类型参数、非法消息和旧字段缺失均不崩溃、不暴露内部 key；显示当前语言通用提示。 |
| 内容边界 | 合成中文标题、输入、路径、工具结果与 JSON 正文保持原样；只有 Monitor 自有外围文案改变。 |
| 格式 | 终端不足一秒、分钟／小时边界保持既有规则；GUI 短活动、未知耗时、紧凑指标与辅助功能表达符合对应场景。 |

资源 key 一致性只能证明结构完整，英文是否自然、是否误复制中文需要结合源文案清单和人工阅读。全文搜索中文命中需判断来源，不将原始内容判为漏翻。

## 2. 参数、偏好与错误

- 默认中文；保存英语后重启对应界面仍为英语；显式 `--lang zh-CN` 只覆盖当次终端启动。
- 覆盖 CLI 命令前及 `watch` 后的语言参数、帮助说明、非法代码；`--` 之后转发的原 CLI 参数不被解释为 Monitor 语言选择。
- 真实交互终端按 `l` 切换并保存，页脚提示与错误同步变化；`--once` 英文渲染正确。`--json` 的机器字段、语义和内容不因语言变化改写。
- GUI 切换即时生效；快速连续切换后，内存和最终保存值以最后一次选择为准。先后或并发修改语言／登录启动不会丢其他偏好。
- GUI 和终端偏好互不隐式写入；损坏 JSON、错误类型、未知语言、旧版本和不可写文件按需求降级，保存失败不显示成功。
- 只读预览／隔离 runtime 使用独立偏好，前后确认日常偏好及接入配置未变化。语言入口不调用配置、恢复、观察租约或采集启停。
- 已知管理错误包含正确动作语义和参数；未知错误使用本地化解释并保留原始诊断。切换后已显示的自有错误同步更新。
- 自动检查使用注入的失败／合成管理响应，不为检查译文实际恢复或清理日常接入。

## 3. 动态消息与兼容矩阵

| 数据／版本组合 | 验收点 |
| --- | --- |
| 新核心 + 新 GUI，两种语言 | 准备、运行、编辑、生成回答、完成、失败、阻止、断连等消息正确；同一数据只改变文案。 |
| 旧快照 + 新 GUI | 有明确语义时本地化；只有中文旧标签时英语使用通用提示，来源详情可保留原标签；无崩溃、无状态猜测。 |
| 新核心 + 旧读取方 | 旧字段仍保留，新增可选字段不破坏现有 JSON 消费；必要时复用旧模型样例／基线解码做有限兼容检查。 |
| 历史与实时合并 | 主子时间线、协作等待、历史详情、实时补充及未保留内容提示均覆盖；不改活动身份、来源内容或完成状态。 |
| 管理及详情旧记录 | 只有旧错误／标题文本时能降级；已知 code、状态与新消息优先级明确，不丢原始诊断。 |
| 同一数据切换前后 | scope／thread／turn／phase／call ID、选中项、原始 JSON、计数、质量、时间与指标相同；只有本地化展示不同。 |

保留未知与部分观测的 `—`，不能因为语言切换把未知值变为零。准备阶段不能被翻成已运行，失败、停止、被阻止和未执行不能混用；Output 与其中 Reasoning 的关系正确，已移除的推理均速不重新出现。

## 4. 原生界面与阅读状态

复用只读合成 preview，至少实际检查以下表面：

1. 主面板：无任务、单个／多个活跃聊天、最近完成、未归属子智能体、断连与部分覆盖。
2. 时间线：主子智能体双轨、轮次入口、输入按钮、缩放、回到最新、协作动作、选中和短活动的 Help／辅助功能描述。
3. 同时打开的 Activity Viewer、活动详情与输入浮层：切换后自有标题和提示更新，正文保持原样，窗口不关闭、阅读位置不回到开头。
4. 设置菜单、恢复确认与错误：两种语言下操作可见、选中标记清楚；重新打开菜单／对话框使用当前语言，模拟错误保留细节。
5. 中文与英文系统环境／可控语言覆盖下，Monitor 自有界面遵循显式选择与中文默认，不被系统自动切为其他语言。

在默认紧凑宽度、较窄／较宽视口及浅／深色下抽查英语长句、长标题、多文件和复数场景。不得出现操作按钮被挤出、固定高度裁字、轨道内容错位或无从查看的关键提示。允许合理换行和截断，但完整内容应能通过详情或 Help 获得。

切换前后检查当前聊天／轮次、选中活动、详情滚动、缩放和跟随状态。30／60／120 秒参考比例、面板分段跟随、独立查看器原有行为继续正确；只针对本次语言刷新和文案尺寸影响做必要回归，不重复整套分页实验。

## 5. 验证入口与证据边界

优先扩展 `tests/test_usability.py` 和受影响的 CLI／管理／历史详情测试；Swift 扩展 `SnapshotTests`、`TimelineTests`、`AgentTimelineTests`、`PresentationTests`、`PanelUXTests`、`InputPopoverTests` 及实际触及的生命周期用例。为跨端资源完整性、降级和语言状态新增有意义的专门检查，不对每句静态译文逐条写镜像测试。

后续示例入口，按实际新增用例和项目测试约定调整：

```sh
PYTHONPATH=src .local/venv/bin/python -m unittest discover -s tests -p 'test_usability.py'
swift test --disable-sandbox --cache-path .local/swift-cache --package-path macos \
  --filter 'SnapshotTests|TimelineTests|AgentTimelineTests|PresentationTests|PanelUXTests|InputPopoverTests|LocalizationTests'
bin/build-gui --preview
```

窗口环境检查沿用项目已有门控并串行执行；英文 fixture 应使用可控输入，不能依赖等待真实业务活动或持续 sleep。无实际受影响的采集链路变更时，不重复全部采集、历史合并和自然使用矩阵。

实施结果分别列出：资源／模板检查、Python 与 Swift 定向检查、原生实际操作、隔离构建、日常 App 构建及实际加载状态。截图证明布局，实际切换与偏好重开需要操作证据；仅编译通过不能证明即时刷新完整。

若后续进行有限真实来源观察，仅核对动态标签、原始内容边界和指标语义，不为产生测试活动派发额外业务任务。原始输入、快照、录屏及诊断放在 Git 忽略的本机目录，文档仅保留脱敏结论、合成截图及必要构建身份。本机结果不等同于长期自然使用、公开发行或其他设备验收。
