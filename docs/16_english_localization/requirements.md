# 英语支持：需求与决策

日期：2026-10-22。状态：本轮实现与定向验收完成；需求继续作为行为约定，证据与限制见[实施结果](implementation-results.md)。总览见 [README](README.md)，执行与检查分别见[实现计划](implementation-plan.md)和[验收计划](validation-plan.md)。

## 1. 覆盖范围

| 编号 | 范围 | 要求 |
| --- | --- | --- |
| R01 | 菜单栏与主面板 | 概览、聊天列表、连接与覆盖说明、状态、空状态、统计、设置、Help 和辅助功能文案支持中英文。 |
| R02 | 时间线 | 主子智能体、轮次入口、模型／工具轨道、活动类别、执行状态、协作动作、缩放与跟随提示支持中英文。 |
| R03 | 详情 | Activity Viewer、输入浮层、活动详情的界面标题、段落标签、缺失／截断／未保留等提示支持中英文；内容遵循第 4 节边界。 |
| R04 | 配置与恢复 | 首次接入、配置、登录启动、恢复确认、等待清理、退出和失败提示支持中英文。只改文案与展示，不改操作条件或配置归属。 |
| R05 | 终端 | 看板、活动详情、表头、页脚、空状态、CLI 自有帮助说明、安装／启动／停止／恢复等用户提示支持英语。 |
| R06 | 动态消息 | 数量、文件名、命令名、路径和错误上下文使用参数，支持英文单复数及完整句式，不通过中文拼接或字符串替换翻译。 |
| R07 | 使用说明 | 实施完成后在现有使用文档补充语言入口、语言代码、优先级和保存位置；整套仓库文档翻译不属于本轮。 |

CLI 子命令、参数名、协议字段和标准库自动生成的语法元素保持既有形式。Monitor 自有的帮助说明与错误解释纳入翻译；macOS 或第三方库提供的原始错误详情可能遵循其自身语言，见第 4 节。

## 2. 语言选择与保存

| 编号 | 决策 |
| --- | --- |
| D01 | 对外语言代码为 `zh-CN` 和 `en`。Swift 资源目录分别映射到 `zh-Hans.lproj` 和 `en.lproj`，不要求用户使用资源目录名称。 |
| D02 | 无有效保存偏好时默认中文；本轮不增加“跟随系统”。在英文系统或系统为 App 指定其他语言时，Monitor 自有界面仍遵循此规则。系统控件与系统原始错误不作同样保证。 |
| D03 | GUI 顶部齿轮内提供语言子菜单，选项固定自称「简体中文」「English」，并标记当前选择。语言入口本身随当前语言显示；管理操作进行中或恢复清理待完成时暂不可切换，避免清理后异步保存重新创建数据目录。 |
| D04 | GUI 切换无需重启，已打开的主面板、独立窗口和浮层在下一次正常 UI 更新中改用新语言；重新打开的菜单和对话框使用新语言。切换不发起采集启停或配置操作。 |
| D05 | GUI 在现有应用数据目录的偏好文件中保存语言；写入与登录启动等已有偏好合并，不能覆盖其他字段，也不能仅为改语言创建接入或启动采集。 |
| D06 | 终端优先级继续为显式 `--lang` ＞ 当前运行目录保存偏好 ＞ 中文；显式参数只覆盖本次启动。交互看板按 `l` 切换并保存选择。 |
| D07 | GUI 和终端各自保存偏好，互不隐式改写；不增加实时同步服务。只读预览／隔离测试可切换展示语言，但保存必须隔离，不得写日常偏好。 |
| D08 | 偏好损坏、类型错误、版本不支持或语言已不可用时，显示中文并允许重新选择。保存失败时本次切换仍生效，以当前语言提示未保存；不能声称下次启动会保留。 |
| D09 | CLI 显式指定不支持的代码时继续清楚报错并列出可用语言，不静默回退。偏好无效的恢复路径与显式输入错误区别处理。 |
| D10 | 只有完整资源可供用户选择；英文完成并通过完整性检查后，才向产品注册 `en`。不允许用复制的中文资源充当完整英语。 |

语言切换保留当前聊天、轮次、选中活动、展开状态、输入／详情阅读位置、时间线缩放档和跟随状态。程序不得通过整体重建 store 或关闭所有窗口实现切换。菜单栏数值、动画模式及几何只在文案宽度实际需要时按原有规则更新。

## 3. 动态内容与旧数据

1. Python 核心继续使用稳定消息 key、参数和语义状态；GUI 解码并渲染结构化消息，不以采集器的中文 `display_label` 作为新数据的首选展示。
2. Swift 的 `Chat.title`、时间线类别／状态／协作说明、管理状态等展示属性改为按选定语言格式化。身份、排序、可见性和活动判断只依赖语义字段。
3. 历史查询与详情中的 Monitor 生成标题、空缺原因和实时补充说明同样纳入本地化。原始历史不改写；需要新增消息字段时采用可选的兼容扩展。
4. 已知消息缺失时，先按已有明确语义字段生成通用文案；不得从中文文本、文件名或时间接近程度反推状态、身份或关联。
5. 新旧 GUI／核心混用时，保留旧字段及现有协议版本的兼容性。老数据只有中文标签、缺乏可确定语义时，中文界面可沿用旧标签；英语界面显示本地化通用状态，旧标签可作为原始详情保留并标明来源。
6. 未知 key、缺参数或非法模板不得崩溃，也不得在正常界面露出内部 key。按当前语言显示可确定的通用提示；参数中的用户数据保持原样。
7. 管理错误优先传递已有错误 code 对应的消息 key 与结构化参数。不能只把不同情境下的同一 code 强行映射为一个丢失含义的句子。未知错误显示本地化说明并保留原始诊断详情。

## 4. 内容与语义边界

| 内容 | 处理方式 |
| --- | --- |
| Monitor 自有界面、状态、占位、说明和错误上下文 | 提供完整中英文资源。 |
| 聊天标题、项目名、模型名、用户输入、回答和推理正文 | 按来源原样显示，不自动翻译。未命名占位属于 Monitor 文案，需要翻译。 |
| 工具／服务展示名、命令、参数、路径、文件名、补丁、工具结果 | 保留来源内容；外围动作和数量提示翻译。工具名称继续沿用统一解析规则，不增加手工别名。 |
| JSON／JSONL 字段、ID、状态码、质量标记、错误 code、来源时间和原始日志 | 保持稳定；需要可读说明时由展示层另行提供。`--json` 等机器输出不因语言变化改写。 |
| 系统或第三方提供的原始错误 | Monitor 的解释和操作建议翻译，原始诊断保留；不保证原始诊断语言。 |

语言切换不改写快照、历史、活动 ID、call ID、主子关系、质量判定、时间来源、用量或实时速度计算；旧兼容中文字段仍可保留。未知／部分观测继续展示 `—` 并说明原因，Output 包含 Reasoning 的关系继续明确。

面板沿用第 15 章的 30／60／120 秒参考比例、默认 60 秒和分段跟随；独立 Activity Viewer 继续自己的布局与跟随方式。英语长度不能成为改变时间比例或丢掉详情的理由。

## 5. 文案与格式约定

| 中文语义 | 英文基准 |
| --- | --- |
| 聊天／回合／子智能体 | Chat / Turn / Subagent |
| 准备中／运行中／处理中 | Preparing / Running / Processing |
| 思考中／生成回答 | Thinking / Generating response |
| 工具参数生成／工具执行 | Tool input / Tool execution |
| 编辑中／编辑文件 | Editing / File edit |
| 已暂停／已完成／失败／已停止 | Paused / Completed / Failed / Stopped |
| 未执行／已阻止，未执行 | Not executed / Blocked, not executed |
| 观测缺口／部分观测 | Observation gap / Partial observation |
| 回到最新 | Back to latest |
| Output／其中 Reasoning | Output / Including reasoning |

表中是统一术语基准，具体句式按上下文与空间调整，不机械逐字翻译。准备／运行活动继续采用 `Preparing · python`、`Running · python` 形式；数量使用完整模板，例如 `1 chat / 2 chats`、`Editing · a.py (+1 more)`。零、单数、复数和嵌套消息均需可验证。

终端已有 `12s`、`1m02s`、`1h02m03s` 和不足一秒留空的规则保持不变。GUI 可读耗时、相对时间、数量和辅助功能句子按选定语言格式化，同时保留现有精度、未知值及时间线短活动的表达；不可把终端规则直接覆盖所有 GUI 场景。既有 `T/s`、`k/M` 等紧凑指标单位保持一致，不引入系统语言导致的小数格式或比例变化。

## 6. 完成条件与范围外事项

完成条件是：英语资源覆盖本轮全部可控用户文案，动态数据可按所选语言展示，切换与保存符合上述规则，旧数据可保守降级，原生布局和受影响语义通过定向验证，并分别记录构建、隔离预览与日常加载状态。

本轮不增加其他语言、自动检测或在线翻译，不翻译用户原始内容，不变更采集协议语义、接入配置或历史存储，不重做 UI，也不包含公开发行与其他机器的兼容性认证。
