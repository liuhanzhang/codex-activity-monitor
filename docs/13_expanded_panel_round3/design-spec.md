## 1. 信息层级

| 层级 | 用户要回答的问题 | 展示 |
| --- | --- | --- |
| 面板 | 有哪些聊天在工作？ | 活跃数量、统一聊天列表、整体连接与覆盖状态。 |
| 聊天 | 当前在查看谁？它正在做什么？ | 标题、项目、当前动作／动作耗时、可靠生成速度、稳定选中态。 |
| 轮次 | 这次交互怎样推进？ | 原生轮次入口、用户输入入口、所选轮次的活动和统计。 |
| 智能体 | 每个成员何时在工作？ | 有来源的名称、状态和紧凑双轨；共同时间轴。 |
| 活动 | 具体发生了什么？ | 点击来源活动，打开已有独立查看器。 |

窗口使用中性原生背景、统一对齐和克制的选中态。标题、动作、说明形成主次；不再用大号输出量或推理均速压过当前工作。不使用多层卡片包裹各个对象。

## 2. 统一聊天列表

### 2.1 内容与排序

每个顶层条目代表一个有来源的主聊天及其已确认子任务组。名称相同的聊天仍按完整身份区分，不按标题、项目或时间接近程度合并。

- 第一行：聊天标题、可靠实时生成速度。未知速度可省略；已知零值与未知保持区别。
- 第二行：项目、当前动作和动作持续时间。结束条目显示真实结束状态；只有明确结束时间才显示“2 分钟前”等相对时间。
- 活跃条目保持稳定顺序，不按瞬时速度、每秒进展或标题重排。新活跃主聊天按稳定顺序加入。
- 最近记录按现有候选与保留范围接入；行文案保留“已完成／失败／已停止／状态未知”等真实含义，不把所有非活跃条目改称成功完成。
- “显示最近完成（N）”位于列表底部；展开后在同一列表追加条目，入口改为“收起已完成”。不新增第二个列表容器或详情页面。
- 仍沿用现有最近窗口和候选上限。列表显示 5 行是视口规则，不是只获取 5 个聊天，也不是将最近候选上限改成 5。

首次显示默认只列活跃主聊天。最近记录首次出现不自动展开；没有最近候选时不展示空入口。结束项使用较轻的文字，仍可选中和读取自己的轮次轨迹。

### 2.2 选择、刷新与完成

| 事件 | 行为 |
| --- | --- |
| GUI 会话第一次打开 | 选择稳定顺序中的第一个活跃主聊天；最近记录隐藏。 |
| 同一 GUI 会话重新打开 | 优先恢复仍活跃的上次选择，否则选择第一个活跃主聊天；不恢复隐藏的结束项。 |
| 无活跃聊天且未显示最近记录 | 展示“当前没有活跃聊天”和最近完成入口；不保留大块空的活动区。 |
| 点击聊天 | 更新唯一选择；下方活动、轮次、输入和统计属于新选择。 |
| 点击显示最近完成 | 追加候选，不抢走当前选择；此前无选择时可以选中第一条最近候选。 |
| 普通快照／速度刷新 | 保留选择、列表滚动位置和正在阅读的时间线位置。 |
| 选中聊天结束 | 在本次展示内保留选中行及其详情，行标明真实结束状态；不重复计入活跃数量。 |
| 手动收起最近记录且所选对象是结束项 | 切回第一个活跃主聊天；没有活跃聊天则进入空态。该操作是用户主动改变列表范围。 |
| 选中来源从快照消失 | 保留必要的阅读身份；内容无法确认时明确降级，不持续显示旧的实时状态。 |
| 选中的归属待确认子任务获得明确父关系 | 本次阅读保留，条目改为带“子任务”标记的保留行，不计主聊天数；切换或关闭后回归主聊天列表，不因关系补齐抢走阅读位置。 |
| 主面板关闭 | 关闭输入／说明浮层并停止面板轮询；已打开的独立活动窗口按既有规则继续存在。 |

本次展示中保留的已结束选中行，与展开后的最近候选按完整身份去重。主动切换离开后，若最近记录仍隐藏，该结束行不再固定展示。跨 GUI 重启不新增选择偏好持久化。

## 3. 高度与滚动

宽度沿用 420 pt。最多 5 行是列表视口上限：不足时按实际内容缩小，超过后列表滚动，不能用固定 5 行空白撑高窗口。

原生行高初始可在 52–60 pt 范围标定；线框的 60 像素不是已验收的原生行高。长标题按紧凑规则截断，并提供完整可访问名称／提示；项目保留辅助级别。用实际行高计算 5 行高度，不按示例文本估算。

屏幕可用高度是窗口硬边界：保留菜单栏下方锚定和屏幕边距，优先分配顶栏、列表与活动操作区；小屏空间不足时允许更早出现列表滚动。大量智能体时限制轨迹区高度，避免把整窗推出屏幕。

列表垂直滚动只影响列表；轨迹区的垂直滚动使成员名称与对应轨道一起移动。所有成员共用一次横向时间滚动，不能各行分别偏移。输入浮层内的长文本拥有自己的滚动区域，不改变主面板高度。

## 4. 活动区操作行

同一行从左到右组织：

1. 轮次选择控件，其当前文字是“本轮活动”；结束聊天可显示“最近一轮活动”，历史轮次使用可区分的时间／序号文字。
2. 紧邻轮次入口的用户输入按钮。
3. 右侧缩放动作与只读时间范围。

聊天列表选择的是工作对象；轮次入口选择的是该聊天内的一次处理过程。例如第一轮“设计方案”结束后，再提交“开始实现”，可分别查看两轮轨迹。轮中 steering／回答并不因显示为用户输入就自动构造新轮次，轮次以来源身份为准。

轮次控件复用 SwiftUI 原生 `Picker` 的菜单样式，显示系统提供的可操作外观和菜单指示，不把纯文字仅加手势当作选择入口。只有一轮时保留清晰标题，控件可禁用；加载或缺少可用轮次时不提供假的可选项。

选择历史轮次后，时间轴、输入、成员范围与统计一起切换；聊天列表仍显示当前聊天状态。轮次文字要让用户看出正在读历史；可保留一个次级“回到当前轮”入口，不挤占默认操作行。

## 5. 原生加减缩放

右上角采用原生减号／加号按钮和只读范围值，目标阅读顺序是“减号、当前范围、加号”。不使用选择控件或滑杆，不让范围文字本身再打开菜单。

- 减号缩小时间线，进入更长的 60 秒参考档。
- 加号放大时间线，进入更细的 30 秒参考档。
- 到达当前缩放边界，禁用对应按钮；提供“放大时间线／缩小时间线”的辅助功能名称和帮助说明。
- 使用 SwiftUI `Button` 配合 `ControlGroup` 和原生小号控件样式；`ControlGroup` 是分组容器，并非通用专用 `ZoomControl`。
- 若原生自动分组无法保持中间值只读或目标排列，使用 `HStack` 排列原生按钮与只读 `Text`，以原生按钮样式承载，不手绘系统控件、不退回范围选择器。

30／60 秒继续是[既有参考比例](../09_activity_timeline/panel-ux-round2.md)的缩放档位，不是整轮长度、ETA 或进度。实际可见秒数依赖绘图区宽度；宽度改变时读取真实视口宽度并显示相应值，不能为凑“30s”改变来源时间。默认跟随、阅读暂停、锚点和同聊天缩放状态继续沿用原规则。

## 6. 紧凑主子智能体轨道

所有成员固定展示，移除主、子智能体的展开按钮及可展开命中区。不要以透明按钮保留“整行可展开”的旧行为。

- 每个成员都显示有来源的身份和状态，并在右侧固定排列模型、工具两轨。
- 模型在上、工具在下；主智能体、子智能体、无子智能体的聊天都遵循同一顺序。
- 所有成员使用同一时轴、比例和原点；父子缩进只改变名称区，不挪动条带的横坐标。
- 有子智能体时主成员与后代一起组织；子层级采用小幅缩进，不能把多层嵌套变成越来越窄的时间绘图区。
- 无子智能体时省去重复的主成员标题，直接呈现紧凑模型／工具轨道。
- 已结束的成员保留真实状态和已有轨迹，降低视觉重量，不因刷新把它移来移去。
- 每条仍是独立来源阶段。紧凑展示不能把模型／工具合并成失去身份的汇总块，也不能把不同时段拼成连续工作。
- 点击活动仍打开该活动或原规则规定的命中集合，不把智能体名称做成另一个展开入口。

目前 `TimelineAgent` 可提供选定父轮范围的组状态；细到“思考中 · 8s”的实时动作只在快照身份、轮次和活动证据都能可靠匹配时展示。否则使用“本轮活动中／本轮已结束／状态未知”等有来源状态，不从图形长度、沉默或最后一条阶段猜当前行为。

任务标题只有明确来源时才可优先展示，现阶段使用可靠 `display_name`／现有名称回退。不得为了复刻线框临时概括子任务职责或发明名字。无法归属的已知子任务，保留独立、明确标记的异常入口，不塞入任意父聊天或主聊天计数。

## 7. 图例与统计

图例位于整张时间轴下方左侧，只显示一份，并与统计区分隔。采用小色标与短标签；单聊和多智能体文案一致，不再在一处附加“上／下”。

正式图例继续表达现有活动种类：思考、正文、参数、编辑、整理，存在相应协作活动时显示协作标识。模型／工具是轨道归属，不是要替换掉活动颜色的两种新类型。既有失败、被阻止、部分观测和选区含义也继续保留。线框里的灰阶“模型／工具”只说明布局位置，不能作为改写正式颜色分类的依据。

统计以普通小字号并排显示输出、其中推理用量、推理均速，不再使用大号两列排版或“统计”展开按钮。信息入口说明：输出已含推理，推理均速是接收窗口估算，并非服务端纯计算速度。

沿用 `PanelStatistics` 的逐字段归属判定：输出与推理用量核对其 `turn_id`；推理均速独立核对样本 `turn_id`。根聊天用量不改成对全体智能体求和，正文实时速度也不改称推理均速。历史轮统计不可确认时显示 `—`，不借用当前轮或最近一轮的有效样本。

## 8. 用户输入浮层

用户输入按钮属于所选轮次。点击打开可交互的原生浮层，而非仅悬停提示：文本可选择、可复制，长内容限高滚动；浮层有关闭入口，外部点击或 Esc 可关闭。

初始输入取自所选轮次明确的初始用户输入记录，内容经既有详情接口读取，不从标题或聊天最后一条消息拼接。没有对应记录时禁用入口并说明不可用。加载、失败、重试、未保留或被截断的来源状态要可见，不显示其他轮的旧正文。

切换聊天、轮次或关闭主面板时关闭浮层并取消其请求；迟到响应不得覆盖新的身份。浮层内部点击和滚动不能误关主面板；Esc 优先关闭浮层，再次 Esc 才按面板规则关闭主面板。点击整个面板外部仍可退出。

用户后续输入／steering 在时间轴上的既有标记与独立详情入口继续保留；初始输入浮层不替代它们。浮层不新增输入、提交、审批或与 Codex 对话的能力。

## 9. 线框的适用边界

线框全部是合成示例。它确认区域位置、常驻信息、显隐规则和操作意图；不确认原生控件像素、动效、真实来源覆盖或活动点击可用性。

正式结果以本章决定、来源约束及目标 macOS 的原生验证为准。只做本轮相关回归；不能把此前原生检查、当前 HTML 预览或静态校验写成本轮原生实施已验收。
