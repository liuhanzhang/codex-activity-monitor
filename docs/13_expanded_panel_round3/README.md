## 目标与最终结构

打开面板时，先扫读所有活跃聊天；选择一个聊天后，在同一面板下方查看其轮次轨迹。主、子智能体统一采用紧凑双轨，减少重复标题、展开操作和大号统计。

结构顺序为：

1. 顶栏：工作概览、活跃主聊天数、连接／覆盖状态、设置。
2. 统一聊天列表：默认只列进行中；点击“显示最近完成”后，在同一列表追加最近记录。
3. 所选聊天的活动：左侧原生轮次入口与用户输入按钮，右侧加减缩放；其下为紧凑时间轴。
4. 时间轴下方的一份图例，以及一行输出／含推理用量／推理均速。

## 本轮确认的决定

| 编号 | 决定 |
| --- | --- |
| D01 | 使用“上方聊天列表＋下方单个查看区”，同一面板内完成选择与查看，不新增独占详情页。 |
| D02 | 列表默认只显示进行中的主聊天；最近完成通过明确文案入口加入同一列表，活跃聊天排在前面。 |
| D03 | 聊天列表最多显示 5 行；不足 5 行按内容缩小窗口，超过后列表滚动。屏幕可用高度仍是硬边界。 |
| D04 | 同时只选中一个聊天，不再以聊天展开／收起承载选择；后台刷新不改变选择或按速度重排。 |
| D05 | 主、子智能体固定紧凑模型／工具双轨，共用时间轴，全部移除展开／收起按钮。 |
| D06 | 没有子智能体时，模型／工具轨道也使用紧凑布局。父子缩进只作用于名称，不作用于时间坐标。 |
| D07 | “本轮活动”本身是轮次选择入口；正式 App 复用 SwiftUI 原生 `Picker` 菜单样式，显示可操作的系统控件外观。 |
| D08 | 用户输入按钮紧邻“本轮活动”；点击打开原生浮层，可选择复制，长文本在浮层内滚动，不增加主面板高度。 |
| D09 | 缩放位于活动区右上角，使用原生减号／加号按钮和只读范围值；不使用范围选择器或滑杆。沿用 30／60 秒参考档及缩放语义。 |
| D10 | 缩小对应更长可见时间，放大对应更细时间；边界按钮禁用。最终采用 `HStack` 组合原生 `Button` 和只读文字，原生标定差异见实施结果。 |
| D11 | 删除“轨迹选项”展开入口，轮次、输入和缩放直接可达。 |
| D12 | 图例放在整张时间轴下方左侧，只显示一份；单聊与多智能体不再分别添加“上／下”字样。 |
| D13 | 图例和轨迹保留正式 App 现有活动类别、颜色、协作及质量语义；线框中的两种灰阶仅示意布局。 |
| D14 | 输出、其中推理用量、推理均速放在一行，删除统计展开按钮；口径说明用小型信息入口按需查看。 |
| D15 | 统计只展示可确认属于所选轮次的数据，缺失显示 `—`，已知零值保留。实时聊天状态与历史轮次内容明确分开。 |
| D16 | 点击具体活动继续使用现有独立活动查看器，保留原始参数／结果、分页、复制和窗口复用。 |
| D17 | 子智能体名称、父子关系、状态、耗时必须有来源；线框中的名称、状态、数值和条带全部是示例。 |

## 实现边界的默认规则

这些是把已确认设计落到现有程序时采用的边界规则，详见设计说明：

- 首次打开选中稳定顺序中的第一个活跃主聊天；同一 GUI 会话重开时，优先恢复仍在活跃列表中的上次选择。没有活跃聊天时展示紧凑空态和最近完成入口。
- 正在查看的聊天结束后，保留本次查看及一条标明真实结束状态的选中行，直到主动切换或关闭；重开面板恢复默认活跃过滤。不要因完成事件突然切走用户的阅读位置。
- 过多智能体时约束轨迹区高度，保持窗口在屏幕内；仅缩进名称，轨道与标签共同垂直滚动，横向共用一次时间滚动。
- 归属待确认的已知子任务继续作为有明确标记的异常入口保留，不计入主聊天数，也不挂入猜测的父聊天。
- 模型／工具的来源阶段、时间比例、缩放锚点、选区和详情身份继续沿用既有契约。
