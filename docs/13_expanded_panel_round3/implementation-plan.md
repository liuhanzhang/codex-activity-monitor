# 第三轮展开面板实施计划

日期：2026-10-20。状态：2026-10-21 完成 P0–P5。以下保留分阶段要求；实际代码、检查证据、运行差异与验证边界见[实施结果](implementation-results.md)。

## 1. 阶段与退出条件

### P0：基线与小范围原生标定

1. 记录当前工作区、源码版本及运行 App 身份，保留其他任务的改动。
2. 复用现有只读 snapshot／timeline fixture 入口，补充本轮必要的合成场景：1／5／6／12 主聊天、有最近记录、多智能体、长输入及未知来源。
3. 在隔离原生预览中确认：420 pt 内的菜单标题、输入按钮、原生减号／范围／加号是否合适；固定双轨最小高度是否仍可读、可点；子浮层与外部点击能否共存。
4. 将最终行高、轨距、浮层尺寸与原生控件组合补入结果记录。原生标定差异回写文档，不改变已确认的信息结构。

退出条件：三个交互风险都有可运行的原生结论，合成数据与当前数据语义兼容。不要为这轮布局重新做完整采集、逆向或安装实验。

### P1：统一列表与唯一选择

主要修改 `DashboardStore`、`DashboardView`、`ChatRowView`。

- 替换聊天展开集合，使用完整聊天身份的唯一选择，保持稳定顺序。
- 将活跃与最近候选合成同一列表；默认仅活跃，最近通过明确文案入口追加，按身份去重。
- 列表按实测内容自适应至最多 5 行；数量增加后只滚动列表。
- 实现重开恢复、完成时保留、主动切换解除、收起最近和无活跃空态。
- 保留归属待确认子任务入口，数量与状态不混入活跃主聊天计数。
- 查看区只挂载选中聊天的时间线任务；切换取消旧任务，保留每聊天阅读状态。

退出条件：1／5／6／12 行与刷新、结束、重开状态正确；不会跳选或同时请求所有聊天历史。已保留的旧信息不能继续冒充实时状态。

### P2：固定紧凑主子双轨

主要修改 `TimelinePresentation`、轨道／布局生成、`TimelinePanelView`、`TimelineSurface`。

- 增加面板专用 `.panelCompact`，避免改变独立查看器默认表现。
- 成员固定两轨，移除面板标题折叠、汇总轨道与展开命中区；无子成员也紧凑。
- 名称／状态使用成员组元数据，父子缩进只在名称区，所有条带共享原点与比例。
- 名称与轨道共用纵向偏移，保持一次横向滚动；大量成员受窗口预算约束。
- 绘制、命中、选区及辅助功能统一几何，修正紧凑后子成员的所属名称查询。
- 一份图例置于图下左侧，保留活动颜色、协作／失败／阻止和部分覆盖；保留需要时的“回到最新”。

退出条件：单成员、多成员、嵌套成员横坐标一致，短条／重叠活动命中身份正确，子成员辅助功能名称正确，独立查看器原布局不受影响。

### P3：原生头部、输入浮层及一行统计

主要修改 `ChatDetailsView`、`TimelinePanelView`、详情加载状态、`PopoverController` 及相关文案。

- “本轮活动”复用原生菜单 `Picker`，用户输入按钮放在旁边，范围加减放右侧，删除轨迹选项入口。
- 继续现有缩放比例，显示真实视口范围、禁用边界，保留阅读锚点与最新跟随。
- 输入按所选初始输入的完整身份加载；支持原始文本选择、复制、限高滚动、必要分页和失败重试。
- 关闭／切换取消请求；延迟响应不能串聊天、串轮次或重新打开浮层。
- 处理子浮层窗口归属、菜单跟踪、Esc 顺序和外部点击；浮层不撑高主面板。
- 输出／含推理／推理均速并为普通字号的一行，说明按需查看，复用原有逐字段轮次判断。
- 统一屏幕高度预算，小屏、跨屏和多成员时仍可访问所有必要操作。

退出条件：轮次、输入、时间线与统计始终属于同一选择；原生浮层内操作不会误关主面板，真正外部点击仍可关闭。

### P4：定向回归与来源核对

按[验收计划](validation-plan.md)运行与改动相称的模型／状态测试、隔离预览和原生交互检查。新增测试覆盖选择状态、几何与身份竞态等行为契约，不为静态文案或每个视图实现细节重复造测试。

用有限的实际来源核对一个单成员轮和一个有明确子关系的轮；确认 UI 中活动及详情身份、时间和统计归属与来源相符。实际内容留在 `.local/`，文档只保存脱敏结论与可公开的合成截图。

退出条件：本轮必要矩阵通过，失败已修复或明确列为未完成；未执行的自然使用、发行或全新机器检查不能计为通过。已有有效验证只在本轮改动触及其契约时定向复查。

### P5：结果记录与日常版本衔接

1. 新增 `implementation-results.md`，记录实际差异、源码／构建身份、执行的检查、原生证据和未验证边界。
2. 更新本章入口和根目录 README，把已实施与仅设计条目区分清楚。
3. 后续实施若包含日常 App 更新，再按既有流程构建并核对已加载版本；本轮不因 UI 改动重启或重配采集器。
4. Git 提交与推送按用户后续指令处理，只纳入获准范围。

退出条件：文档描述与最终代码、实际加载版本及验证证据一致；未完成项清楚可见。

## 2. 依赖与范围控制

P0 → P1 → P2 → P3 → P4 → P5。每阶段确认退出条件后再扩大范围，避免同时改变状态、来源与布局而难以判断错误。

本轮不新增后端 schema、历史拉取模式、指标账本、推测的子任务名字／父关系、任务百分比或 ETA；不重做菜单栏动画和独立查看器。发现这些模块的独立问题时单独记录，不夹带修复。

现有章节保留为历史依据；发生冲突时以本章明确替代的 UI 决定为准，其来源与身份约束继续有效。可交付检查标准见[验收计划](validation-plan.md)，不以“HTML 看起来一致”代替原生结果。
