## P0：历史交接收敛与基线

已实现：

- JSONL 已接管的历史在确认替换／截短后失效，不再从一份嵌套的旧 `observation` 或独立 `observed_turn` 完成账本恢复旧完成结论。移除该影子状态及其持久化 allowlist；旧 sidecar 的影子字段也不参与恢复。
- 明确区分有效完整历史与部分末行：未完整读取时不按“未找到”撤销已有历史；补写完整后再校正。来源不可读仍标记 `history_unavailable`，不冒充确认删除。
- 尚未交接的当前实时完成仍即时结束指示；现有短期历史重试 1 s、30 s 后放缓到 10 s 和约 600 s 的当前 Engine 上下文保留继续沿用。没有把这些窗口扩展成完整正文的独立历史。

验证：修改后的四个反例在临时解出的 `c3996dc` 上全部失败，在新实现上通过；历史校正 41 项和 timeline/query/storage 43 项针对性检查通过；随后完整 Python discovery 336 项通过（40.076 s）。真实 Codex JSONL 没有被修改。

自然样本与性能基线见 [p0-baseline.json](evidence/p0-baseline.json)。已有探针捕获三个无中途 collector 重载的完整自然回合，最后 message 的可见文本 delta 持续约 8.794／0.548／3.247 s。turn 完成到 AppKit 空闲 draw 约 179／172／187 ms，最后 delta 到 draw 约 402／348／406 ms，本组未复现约 2 s 的结束滞留。样本中的不可用区间计数保留，未用最终空闲结果掩盖中途未知状态。

这是 3 个样本的入口证据，不是 10 个以上自然回合、长期运行或所有环境的保证。探针还运行了对照 Engine，统计包含仪器化开销；draw 不等同于物理屏幕呈现。GUI 驻留构建与基线 Swift 源码仅差 `ActivityContent.swift` 末尾一个空行，已按完整源码指纹重算核对。探针到期自动退出并恢复普通 collector，本轮没有因为观察窗口到期而自行重启一个仍活着的探针。

合成 Swift debug 投影基准：10／100／300 个聊天的一组 getter 访问中位数约 2.153／156.443／1336.178 ms。输入是每组一个 root 和两个显式 child，输出有 checksum；基准测试默认不执行，可用 `CPM_PROJECTION_BENCHMARK=1` 显式运行。它为 EH06 提供结构性成本证据，不代表普通 10 聊天场景已有可感知卡顿。

普通 collector 恢复后的一个资源点样本：Python RSS 55,344 KiB，GUI RSS 109,120 KiB；该时刻 GUI 有动画与诊断，属于点样本而非峰值或资源预算。真正工作集／峰值测量在 P5 继续。

## P1：统一子进程执行器

实现内容：

- 新增 `ProcessExecuting`、请求／结果／失败类型和 POSIX spawn 执行器。启动时建立本次拥有的进程组；两个非阻塞 pipe 在同一有界 poll 循环中排空，管理／查询共用该实现。
- stdout 硬上限、stderr 有限尾部、单调时钟 deadline、取消、SIGTERM 宽限、SIGKILL 和继承 pipe 的有限 drain；仅所属组收信号。终止前保留 child 的 waitable 身份，避免用已回收 PID 发送组信号。
- 移除 `QueryProcess` 和其旧 timer。查询保留 12 s 截止／8 MiB 输出，管理为 30 s／1 MiB、status 为 5 s；默认终止／drain 宽限各 500 ms。
- 有副作用的管理操作失败或取消后，在独立、有限时的 status 查询中读取真实状态，并让 store 应用该状态；不把取消当作回滚，也不误杀独立 collector。
- 新失败原因有中英文资源，查询选择代际和既有阅读状态防护保留。

验证：首批 7 项真实子进程场景通过；接入两个调用边界并补充 detached service／参数环境后，Swift AppTests 92 项及 ModelTests 50 项通过。随后增加取消／退出竞争、取消后的管理状态查询及 Swift→实际 Python 离线时间线查询，12 项针对性检查通过。测试发现的临时目录 `/var` 与 `/private/var` 表示差异已按 POSIX `realpath` 比较修正，命令的目录语义未被修改。

测试 fixture 仅使用临时文件和本次拥有的进程，未操作真实 Codex writer。Swift 默认测试中原生窗口场景仍按现有 opt-in 规则执行；最低系统／干净 checkout 和日常 GUI 切换不是这里的已通过项。

## P2：状态通道与后台恢复存档

实现内容：

- `DetachedSnapshot` 在领域拥有线程上深复制当前投影；live 编码隐藏 `usage_recovery`，恢复存档单独保留该字段。worker 不访问 Engine，也不持有 timeline 锁。恢复记录包含版本、collector 实例、状态序号和编码时钟；这些不是实时健康证据。
- 新增私有 `state.sock`，JSON Lines 协议版本 1；只读订阅、完整状态、实例／序号、带 nonce 的 hello／heartbeat 和 tick 年龄。服务端单独线程共享最新编码结果，每连接只保留发送中帧和可替换的最新状态；4 个客户端、8 MiB 帧、16 KiB 请求、3 s 单帧写入上限。
- 过大状态发送 `state_unavailable`，不持续展示旧状态为健康。慢读端或无效请求只关闭所属连接；新实例与连接重新取得完整状态。
- 恢复 writer 只有一个写入中和一个最新待写检查点，失败按 250 ms 至 4 s 退避，退出最多等 2 s。只在 collector 与 worker 实际结束后释放生命周期锁，避免延迟 writer 覆盖替换进程；未完成的 daemon 写入不阻止进程最终退出。
- Swift 增加 `StateSubscribing` 和 Unix socket 实现，以字节分帧后解码 UTF-8，拥有并关闭自己的 descriptor；取消不在另一线程直接关闭 descriptor。只接受本地 deadline 内匹配 nonce 的健康响应，按单调时钟计算 tick 年龄；合并的 UI 更新携带最新完整状态，避免心跳挤掉唯一状态。
- `DashboardStore` 可通过注入在隔离路径消费状态，任务独立于 management 查询。菜单展示接受连接健康，不用改写旧 `updated_at` 制造新鲜度；文件 fixture 的新鲜度语义保留。

验证：Python 34 项相关检查通过（60.825 s），其中实际 collector 的存档 worker 连续阻塞至少 30 s，期间新回合开始、心跳和完成状态仍可接收，完成状态接收小于测试上限 900 ms；这是受控场景上限，不是日常延迟分位数。SIGTERM 后阻塞 writer 的退出等待有限，进程存活期间锁未提前释放。另覆盖 ENOSPC 恢复／最新值合并、输入脱离、权限、请求边界、客户端上限、慢读端、实例更换和超大状态恢复。

Swift 首批 6 项跨语言／隔离接入检查通过，补充单调时钟边界及重排序后的后续心跳后，默认回归中 AppTests **102 项通过**（1.747 s），ModelTests 50 项也通过。合成契约保存在 `tests/fixtures/state-protocol-v1.jsonl`；测试实际连接 Python `StateServer`，并用独立 peer 注入分片、过期 nonce、版本／大小／实例错误，验证取消关闭连接、旧序号不回退。管理查询持续阻塞时，store 无需 `snapshot.json` 仍能应用状态。加入检查点身份字段后，9 项 Python 针对性检查再次通过。

当时边界：P2 先保留约 1 Hz 恢复文件和原生产读端，尚未完成租约／bridge 解耦；以下 P3 记录后续迁移。日常 GUI 和驻留 Codex Desktop 的统一切换仍需单独验收。

## P3：租约、bridge 与生产读端（代码已接入，日常切换待验收）

已实现：

- collector 启动读取一次配置／v2 session grant，已连接热循环只读内存期限。GUI 以 session id／secret 取得一个连接的续期权；reader、终端探测与状态文件不能续期。正常释放立即撤销，断线仅保留原有 5 s 期限，新连接取代旧连接后，旧 heartbeat／release／close 无权影响新拥有者。
- AppController 持久化启动凭据并在运行中的 collector 内安装 grant；管理重试使用相同凭据，不撤销仍有效的所属连接。确定的拒绝恢复先前记录；可能已生效但丢失确认时保留相同凭据供重试，不盲目回滚。确认旧 collector 协议不兼容时才走有限替换；新版 IPC 暂不可用或控制记录缺失时保留生命周期锁，不能据此重复启动。
- `Observer.offer()` 只查内存许可／期限和有界入队。worker 主动发起 nonce 握手，约 500 ms 请求续期，响应截止 750 ms、许可最多 1500 ms，实例改变／过期回复不能续期。被丢弃的原始 chunk 会改变分帧代次，防止过期前的半帧与恢复后的输入拼接。转发泵不等待许可；仅在启动原后端前给首次握手至多 150 ms，连接立即失败时提前继续。
- 生产 GUI 改用 `state.sock`，订阅、重连及 250 ms 健康时钟独立于管理查询；迟到 Task 受代际检查。管理状态使用 5 s 周期、5 s 截止的统一执行器查询，包含旧驻留 bridge 的版本诊断。生产路径不再监听／轮询 `snapshot.json`；显式只读 fixture 继续保留文件读取。
- 终端 `watch`／`--once`／`--json`／`status` 通过有截止时间的只读 IPC 探测，机器输出增加 `connection` 健康信息，不改写源 `updated_at`；没有恢复文件 fallback。普通启动使用锁证明所有权，IPC 用于启动就绪判断。恢复存档降至常规约 10 s，生命周期变化及最终保存优先。
- Swift 订阅返回独立控制句柄：正常退出在同一连接显式释放，最多等 600 ms；取消／重连保留已有宽限，重复释放不建立新期限。修复了释放后被误当成未握手连接、以及关闭时跳过待发确认的竞争；排队但尚无可写机会的连接也受写入期限约束。
- 旧 GUI 的 configure／resume 命令在修改前要求状态协议能力；新 GUI 识别旧 collector 并有限更新。旧 bridge 即使已停止发送，也能通过已登记且核实过进程身份的记录显示重开提示；新 bridge 登记协议能力。PID 只用于诊断和启动校验，不能独自取得租约。

受控验收摘要见 [p3-validation.json](evidence/p3-validation.json)。`tests/acceptance/verify_state_transport.py` 是显式 opt-in 的 macOS 工具，使用临时 profile、Preview 和合成 echo CLI，不创建 Codex writer，不修改日常 launch 环境。

- 原生压力验收：存档阻塞至少 30 s，collector 后续配置读取设置为阻塞，reader 暂停读取至少 60 s。119 个探测样本均健康，待写检查点最多 1 个；本例每连接应用待发字节峰值 6364 B。GUI 的真实拥有连接持续续期；源字节回显与退出码 17 保持；解除屏障后恢复写入。单次完成到 AppKit 空闲 draw 为 220.336 ms，低于受控 750 ms 目标。GUI 被 SIGTERM 后 collector 按期限停止。这是合成场景和应用层队列指标，不是自然延迟分位数、内核缓冲峰值或长期内存预算。
- 后续用当前构建与代码重做同一 30 s／60 s 屏障，并加入可见文本 delta 和速度绘制：确认出现 speed，完成到空闲 draw 为 **118.309 ms**，最后 delta 到 draw 为 **246.259 ms**，仍无配置热读取，原始字节和退出码保持。它补足了首例仅包含 reasoning 的场景，仍不是自然对话或跨环境延迟保证。
- 原生正常退出：在较新的 Preview 构建中，通过实际设置菜单点击“退出 Monitor”，GUI 退出码 0，所属 collector 停止，观察记录被释放，启用配置仍保留。两个验收各自的构建 ID 在 JSON 中记录；后一次另包含管理状态查询及升级提示接入。
- 原生测试最初一次把配置故障注入得早于运行保证范围，误拦了启动元数据读取，随后改为启动完成后启用屏障。受限进程的原生程序也曾在 macOS `_RegisterApplication` 处 SIGABRT，未进入业务代码；之后用桌面会话权限运行 Preview 完成上述验证，代码签名验证通过。失败不计为产品验收通过。
- Python 完整 discovery **369 项通过**（76.701 s），包含修改后的终端 PTY、原始字节／EOF／信号、历史恢复、管理失败和租约场景。Swift 完整检查为 **ModelTests 50 项与 AppTests 105 项通过**；先前单条旧能力 fixture 使用 `app_session` 标记，已改成新握手的 `observer_permit` 标记后通过。历史 P1／P2 的 Swift 计数现明确按 target 记载，避免漏记 ModelTests。之后补充“许可短暂丢失不能拼接旧半帧”和关闭连接拒绝新请求，相关分帧、原始传输及状态通道 36 项再次通过（25.730 s）；该新增反例尚未计入前述 369 项。

仍未完成：日常 GUI／collector／驻留 bridge 的统一切换和新版自然完整回合。仅重启 collector 不能更新旧驻留 Python 代码；需要任务边界的完整 Desktop 重开。没有把 Preview 合成通过写成日常现象已经全部解决，EH01 暂不标为完成。

## P4：详情分页内容快照

已实现：

- 详情协议 v2，独立于 Snapshot／timeline 的 v1。`SectionVersion` 把完整活动／section 身份、来源、完整性语义、格式、固定 code point 长度与原始 UTF-8 前缀绑定到 SHA-256；token 最多 16 KiB，身份及 offset 在历史 I/O 前校验。标题和界面语言不进入版本，源换行和 Unicode 不归一化。
- 第一页摘要与切页使用同一已渲染字符串；后续页重新验证固定旧长度的前缀。追加可读完旧快照；改写／截短／来源交接返回 `content_changed`。新 provider／CLI 不改变版本；相同内容的文件原子替换允许继续。
- `HistoryRead` 在一个句柄内验证 session header、所选记录及其 turn context、读取前后文件状态；输出按 `(turn_id, call_id)` 匹配，不能跨轮次借用同名 call。文件中途变化返回不可用，重新索引后重试，不能把不同读取得到的参数与结果混合。
- Swift 使用服务器给出的 `ActivityPageCursor`，不从 grapheme 数推算 offset。两个阅读入口共用身份、版本、范围、固定总长和拼页校验；变化／消失时保留已读内容、停止旧分页并提供重新读取。后台刷新不替换已冻结的阅读快照；仅正在跟随、同来源、未分页的实时完整缓冲可接受严格字节前缀增长。v1 可展示第一页，不能无版本继续加载。

验证：Python 内容分页 15 项通过，包含独立 provider／实际 CLI、Unicode／换行、来源交接、同 inode 中途改写、跨 turn 同 call ID、共享契约及热读字节计量。约 2 MiB 的合成 JSONL 热分页读取不足 4 KiB；冷索引仍需扫描源，所选大记录仍需读取／摘要，未声称任意大小都为常数成本。

Swift 全量为 ModelTests **55 项**、AppTests **108 项通过**。真实 `SystemTimelineClient` 经统一执行器调用 Python，读取超过 262,144 code point 的正文，在组合字符边界分页后按 UTF-8 完整还原。共享合成契约为 `tests/fixtures/detail-protocol-v2.json`。另在实际 macOS 窗口会话显式运行 1 项原生验收：v2 详情刷新及 en／zh-CN 切换保留同一文本视图、原文、选区、滚动位置与独立查看器。没有改写真实 Codex JSONL。

完整 Python discovery 首次运行 385 项，其中 1 项状态通道测试因关闭连接与诊断计数更新的竞争失败；该测试改为等待拒绝计数而非假设 close 的可见性顺序后，状态通道 8 项通过（34.060 s）。不将这次完整运行写为全通过；后续阶段集成再执行完整回归。`bin/export-localizations --check` 和 `git diff --check` 通过。

## P6：单快照 GUI 投影（代码和合成验证完成）
