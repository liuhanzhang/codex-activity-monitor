## 执行顺序与入口条件

```mermaid
flowchart LR
    P0["P0 基线、历史语义与菜单栏验收"] --> P1["P1 子进程 EH02"]
    P1 --> P2["P2 状态通道与存档 EH01"]
    P2 --> P3["P3 租约、桥接及读端迁移 EH01"]
    P3 --> P4["P4 安全分页 EH03"]
    P4 --> P5["P5 规模测量与预算 EH04"]
    P5 --> P6["P6 GUI 投影 EH06"]
    P6 --> P7["P7 类型与职责收尾 EH05"]
```

这是便于排错和回退的工程顺序；子进程执行器不是 IPC 的硬性技术依赖。EH05 的身份类型和协议类型随相应功能一起建立，P7 处理剩余边界。

P0 的三个完整自然回合未复现约 2 s 的结束滞留，具体延迟、不可用区间和仪器化边界见实施记录。这是入口样本；后续切换仍需新版本完整回合与长期样本，不能据此宣称所有环境的延迟已解决。

资源上限与测量边界见 [resource-budgets.md](resource-budgets.md)。

## 文档维护规则

- 设计与执行状态以本章为准；第 17 章的旧 `next-steps.md` 只保留迁移入口。
- “已确定约束”“工程默认方案”“待测参数”“已验证结果”分别记录。设计示例不是已经存在的产品 API。
- 实施时逐阶段更新本表、实施计划和 `implementation-results.md`，记录实际提交、验证范围与剩余问题，不预填完成结论。
- 修改协议或默认行为时同步更新技术设计与验证场景；不在 TODO、历史 CR 和本章维护三份独立方案。
- 第 17 章的回归调查可追加后续证据，原始测试计数和当时结论保留其时间边界。

当前首发基线沿用 macOS 26+、Python 3.11+。许可证、素材分发、独立安装包和发行兼容矩阵属于[并行发行准备](requirements-and-decisions.md#发行准备与维护者决策)，不计入上述六项的完成率。
