# 最近一秒的接收速度

速度显示**当前活跃生成流最近一秒内收到的本地 token 增量之和，单位 T/s**。固定一秒分母，启动不足一秒也不外推；25 token 的首包显示 25 T/s。一秒没有新增归零，完成事件立即结束测速。此口径于 2026-10-25 确定。

## 实现约束

- 窗口为 `(t-1s, t]`，使用 bridge 接收时钟。不能用分词完成时间给旧文本重新计时，也不能按 delta 个数假定 token 数。
- 每条流保留有界的接收时间／累计字符位置，精确确定窗口起点的文本前缀。计数 worker 分别计算当前前缀与起点前缀；差值就是该完整一秒的本地 token 增量。无需给每个 delta 单独分词，BPE 边界仍按累计前缀处理。
- 沿用异步、隔离分词和现有任务／字节预算；GUI 使用最新完成的窗口结果，短暂计数滞后不进入分母。窗口过期而新计数未完成时保留不可用，不能冒充零。
- 正常初次计数没有 `… T/s`；还没有数字时，菜单使用既有“生成”文案，聊天行保留动作说明，首次完成计数即显示数字。真实断连、缺口、超限和失败保持 `—`。
- 不跨 item／来源合并计数基线。单聊天与菜单继续对独立流去重汇总；已完成流立即退出当前速度，不因窗口尾部而拖延结束状态。

接收位置每流最多 4,096 点，全局每次调度将保留点控制到 65,536 点以内；同一接收时间合并，过期仅保留一个起点之前的位置。全局调度检查前，本批新进事件可以暂时增加点数，不将它宣称为硬 RSS 上限。达到预算标记不可用，不悄悄采样丢点。窗口只需一个完整前缀及一个整数切分位置，排队字节仍按完整前缀计；worker 内会临时切出起点前缀，两次分词分别沿用既有单次执行期限，单个窗口任务可能包含两次 IPC／分词，不能把既有单次 3 s 期限称为完整任务期限。

## 验证与上线

覆盖固定一秒边界、启动首包、接收批次／同时间 delta、旧数据过期、BPE 纠正、计数迟到、模型重计数、终止和异常；通过隔离 collector 与原生 Preview 验证实际计数及无省略号展示。

维护入口为[速率回归](../../tests/test_token_rate.py)、[源接收边界与预算](../../tests/test_receive_window.py)、[确定性窗口测量](../../tests/benchmarks/measure_one_second_rate.py)、[真实 collector 验收](../../tests/acceptance/verify_token_rate.py)和[双语原生验收](../../tests/acceptance/verify_speed_presentation.py)。它们直接验证当前实现，不依赖检出旧本地提交。

### 已验证结果

- [确定性接收窗口](evidence/one-second-rate-window.json)：真实本地 BPE、虚拟时钟，四种批次的每个读数都与源时钟定义的 `(t-1s,t]` 收到量一致。每 250 ms／25 token 的稳定值为 100；每 1.2 s／120 token 则按实际接收显示 0 或 120，不承诺平滑。
- [真实隔离 collector](evidence/one-second-rate-collector.json)：64 批、每批 25 token／250 ms，包含实际隔离分词与事件／状态 socket。12 个稳定读数全部为 100 T/s，全部有效读数与各自计数窗口的实际源接收量一致；首个发布正值为 50，完成后为空。前一轮脚本在首个状态尚无 stream 时抛出 StopIteration，已改为接受该有效初始状态后重跑通过，不将前次失败算作通过。
- [原生中英文展示及日常切换](evidence/one-second-rate-presentation.json)：Preview 两种语言各 7 种合成状态通过，初次计数和前缀纠正没有省略号，真实失败、超限、缺口与断连仍显示不可用。观察的是实际 AppKit 应用状态与 tooltip，不是物理像素或自然时延。
- Python 完整 discovery 首轮 471 项有 4 个旧断言仍要求单前缀未知／超过一秒不归零；修正这些旧口径 fixture 后，相关 125 项针对性回归通过（2.172 s）。没有为此重复全部 90 s 测试，也不将首轮记为全通过。Swift Model 报告 66 项，其中 64 项执行通过、2 项跳过；App 报告 115 项，其中 108 项执行通过、7 项跳过。默认跳过项不计为原生验收。
- 清理废弃实验与合并提交前，125 项相关回归再次通过（2.511 s），新验收入口可加载、本地化导出一致。产品源码字节保持不变，复用已有 Swift、隔离 collector 与原生验证，没有再次重载日常程序。

日常 GUI 与 collector 已更新：实际 GUI build 为 `7288de560f82ece6d1f68e2e59360d814830edf3f5ea31ef473c049732b43ff6`，collector 实际加载 metrics 指纹为 `37a576e8c61e8072a847b39b5d248bd91caeb246634589fc480a93556a00501b`，同实例拥有连接及新鲜递增状态序号已核对。三个原有驻留 bridge 的身份／指纹保持，Desktop 和原后端未重开。旧包与匹配旧加载版本的 metrics 保存在私有回退目录；所有重载产生的观察缺口保留，当前跨重载回合可能继续显示 `—`，不能据此伪造干净自然验收。

## 调查结论与剩余验收

- 旧算法把活动创建到首段文本之间的等待混入分母，也曾将已截取前缀的计数与较晚显示时刻配对；这是旧实现自身的偏差。当前按源接收位置截取完整一秒，分词等待不进入分母。
- 旧短区间外推对批次敏感；相同长期平均量也可能出现明显的瞬时变化。新口径直接报告一秒收到量，不承诺平滑，也不能据此认定模型服务变快。
- [同组接收与 token 统计](chunk-interval-distribution.md)保留关键测量：921 个 delta、两条工具参数流，正批次间隔 P90 约 15.93 ms、最大约 404.48 ms；离线本地重建中每个 delta 恰为 1 token。这是有限工具输入样本，不能把所有 delta 写死为 1 token。
- 该源样本跨过诊断重载，没有进入活动 TextStream，不能代替 GUI 数字或无缺口自然回合验收。之前自然跳动的完整因果链、结束延迟、bridge 超长诊断丢弃／内存峰值及长期门槛仍未闭合。

当前提交只维护一秒方案与必要的状态、异常和边界测试。旧两秒／占位实验、重复文档及依赖旧提交的对照脚本已清理；不以清理或版本合并宣称上述剩余问题解决。
