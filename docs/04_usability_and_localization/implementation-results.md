# 易用性与多语言准备：实施结果

日期：2026-10-13。状态：本轮实现与相关验收完成。精简证据见 [验证记录](implementation-validation.json)。

## 1. 实际实现

- 准备与运行统一为 `准备中 · 名称`、`运行中 · 名称`。参数完成但执行未确认时仍显示 `处理中`，不降低执行证据门槛。
- 命令使用完整可识别 token 的 basename。支持路径、引号、环境变量、已知 shell / env / sudo 包装、简单前置 `cd` 和分块输入；未知选项、动态表达式与截断保守回退。列表、普通详情与旧快照兼容展示均隐藏命令参数。
- MCP 消费已有 `appContext.appName/actionName`，名称与原始工具身份分开。直接调用和 Code Mode 名称遵循同一规则；缺少展示元数据时回退服务 / 工具短名，没有手工别名表。
- 已结束活动使用名称与真实状态，避免“刚完成 · 运行中”或详情同时显示运行与完成。短操作保留在详情，完成耗时冻结。
- 看板采用显式 Rich 刷新，定时 1Hz；选择、展开、退出及未来语言切换即时响应。连续 JSON / 非 TTY 输出也为 1Hz，采集与指标内部节奏继续约 250ms。
- 耗时不足一秒留空，整秒向下取整，达到一分钟 / 一小时分别显示 `1m02s` / `1h02m03s`；未知耗时为 `—`。速度精度与统计窗口沿用原实现。
- 中文文案集中于 `messages_zh_cn.py`；快照增加语言无关的 `display_message`。状态判断使用消息 key / 语义值，旧中文标签保留为兼容诊断字段。
- `i18n.py` 提供完整资源注册、模板参数检查、中文回退和单复数形式支持。`watch --lang`、语言优先级、独立 `ui-settings.json` 与切换保存机制已实现。

当前只发布完整的 `zh-CN` 资源。英文资源仍属后续工作，测试用第二语言不会作为产品语言发布；至少两种完整语言可用时才提供 `l` 切换入口。

## 4. 保留的边界

- 提供方展示名称是否存在取决于调用元数据；不能保证每个 MCP 都有产品标题。已检查的相关既有命令捕获未包含服务 / 工具目录返回，不声称目录 title 路径已经实测接入。
- 复杂 shell 表达式、间接调用、未知包装和不完整命令 token 仍可能只有通用名称；不执行代码来换取名称。
- 完整英文翻译尚未交付；资源、设置和切换机制的第二语言验证使用测试资源。
- 原生 Codex Desktop / 当前用户 Terminal 窗口没有做截图验收；本轮依据源码、过滤器 / 引擎、独立真实 PTY、运行快照和进程指纹。
