## 提交前修正

复现发现：侧存储初始化原先捕获所有 `sqlite3.DatabaseError` 并隔离重建，因此 `BEGIN EXCLUSIVE` 引起的锁定也会触发改名；打开失败或不兼容版本同样可能误入该路径。

现在只在 SQLite 明确返回 `SQLITE_CORRUPT` 或 `SQLITE_NOTADB` 时隔离并重建。忙／锁定及其他数据库操作错误保留原文件，通过现有 `OSError` 降级路径报告元数据不可用；不兼容 schema 原样保留，通过现有 `ValueError` 降级路径交给兼容版本处理。没有修改 Codex 自有历史，也不增加新观察会话。

新增三个回归：真实排他锁下保留文件 inode 与记录、数据库打开失败不隔离、不兼容 schema 保留内容。修正前这三个场景均失败；修正后通过，原有损坏隔离场景继续通过。
