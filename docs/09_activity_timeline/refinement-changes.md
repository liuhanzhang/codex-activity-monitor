# 活动时间线：后续改动点

日期：2026-10-17。状态：已按本文件完成实现、针对性检查、原生预览和本机 Monitor 更新。实施步骤见[后续改动计划](refinement-plan.md)，实际证据与限制见[本轮结果](refinement-results.md)。

本次调整解决三个已观察到的问题：大量状态菱形没有可读内容；很短的工具活动难以点击、经常弹出候选列表；工具详情按命令、文件修改等类型加工，难以直接核对来源记录。

## 1. 本轮采用的决定

| 项目 | 本轮目标 |
| --- | --- |
| 工具展示粒度 | 保留现有内部工具活动，复用命令、MCP、文件操作等投影与历史读取。暂不新增外层 Code Mode 执行轨迹或完整的外层到内层展开树。 |
| 工具布局 | 保留耗时比例作为基础，设置最小显示宽度；同轨重叠或过密时按稳定顺序向右顺延。工具轨只表达大概的耗时分布。 |
| 模型布局 | 思考、正文、参数生成继续使用来源时间位置；上下文整理作为有耗时的过程条放在模型轨。 |
| 输入标记 | 只显示已确认的用户消息；首条从轮次标题访问，同轮 steering 等后续消息画菱形。 |
| 其他状态 | hook、等待响应、重试、连接恢复、审批等待等不单独画点。错误仍由对应活动状态表达，观察缺口保留质量提示。 |
| 回答问题 | 暂不新增专门的问答响应标记。若来源本身产生用户消息，沿用输入规则；否则仅在实际保留的工具结果中查看，不承诺恢复未保存的答案。 |
| 工具详情 | 统一为“参数”“结果”，直接展示原始来源字段值；不再拼装命令摘要、解析代码生成参数或重建 diff。 |
| 内容完整性 | 展示来源保存的全部可用内容；明确区分来源截断、尚未落盘、读取失败和未保存。Monitor 分块加载不等于来源截断。 |

保留内部工具是复用成本与本轮范围的选择。当前已有内部活动投影、历史索引、查看器，以及部分基于明确 ID 的“查看执行”跳转；这不等于已有完整的 `exec → 全部内部调用` 树形下钻。外层 `exec` 参数生成活动的原始参数／结果读取继续复用，不为其新增或推算执行区间。

## 2. 标记与上下文整理

### 2.1 用户输入

- 仍以 canonical `userMessage` 为输入标记的权威来源，不把 `turn/steer` 请求另画成第二个点。
- 第一条用户消息通过轮次标题入口访问；同轮后续消息保留时间点及内容查看能力。
- 失败的 steering、被取消的提问、自动清理的请求不能被画成已提交用户输入。
- 本轮不扩展提问响应、MCP 表单等专用适配，不按内容相同或时间接近猜测去重。

### 2.2 隐藏非输入状态点

在时间线展示投影中统一过滤非输入 marker，包括已在元数据侧文件中保留的旧 hook 等记录。只停止展示，不删除 Codex 历史，也不移除 Engine 正确计算当前状态所需的事件。

“等待响应”当前来自 `model/safetyBuffering/updated` 的泛化文案，不能解释为通用网络等待或首字延迟；本轮移除其时间线状态点，不新增等待耗时推断。

隐藏项不再参与候选列表、键盘活动序列、可访问元素或同轮活动导航。观察中断仍通过已有质量信息说明；失败、中断等继续由实际活动本身表达。

### 2.3 上下文整理是过程条

- `contextCompaction` 的 `item/started → item/completed` 属于同一过程；历史存在有效 `started_at_ms / completed_at_ms` 时可恢复耗时。
- 将其投影到模型轨，标签为“整理上下文”；补充可辨认的样式及图例／可访问名称，不占新轨道。
- 复用现有稳定阶段 ID，实时记录、历史记录及旧侧文件中的同一过程不重复出现。
- 旧 `thread/compacted` 完成通知不再额外画菱形，也不能用它反推开始时间。缺少边界时明确耗时未知。
- 来源只有过程元数据而没有正文时，查看器展示状态和计时信息，并说明“来源未提供可查看内容”；不能报成“源历史已移除”。

协议与来源边界沿用[事件映射](event-mapping.md)和[来源证据](evidence.md)。本次只读抽查发现过有效 compaction 历史区间，不等于本轮已经重新触发并验收了实时 compaction。

## 3. 工具轨的近似布局

### 3.1 几何规则

按每条可视工具轨分别计算，稳定排序依据为来源时间锚及阶段 ID，不按 delta 到达、状态变化或调用名称重排。主智能体与各子智能体展开后的工具轨独立排布。

```text
显示宽度 = max(最小显示宽度, 可用耗时 × 当前时间比例)
显示起点 = max(来源时间对应位置, 前一工具的显示终点 + 间距)
```

最小宽度最终采用 12 pt、间距为 3 pt，已在原生预览中检查。没有可用耗时时只保留最小可选块及未知样式，不能因最小宽度反推出一个耗时。

工具轨一次性标注“近似布局”（可采用紧凑的 `工具 ≈` 及说明）。顺延后的位置和末端不代表真实开始／结束时刻，也不能据此认定工具串行或计算并行度。模型及上下文整理仍按来源时间位置绘制；秒刻度不作为工具顺延位置的精确读数。

### 3.2 数据与交互

- 扩宽、间距和顺延只存在于 GUI 几何中，不回写阶段时间、侧文件或指标。回合总耗时不累计视觉偏移，详情保留来源时间和质量。
- 不对长工具另设最大宽度，不把长过程强行压缩到面板。画布宽度覆盖真实时间范围及顺延后的最右端，横向滚动可以到达最后一个活动。
- 绘制、鼠标命中、悬停、选中边框、键盘定位、可访问 frame 和滚动到选中项，共用同一组阶段矩形。
- 普通工具块点击直接打开自己的详情，不再因最小点击区相互覆盖弹出列表。模型轨的真实重叠、多个输入点或子智能体汇总中的真实多候选仍可保留消歧列表。
- 子智能体汇总轨仍保持现有入口与选择能力；只对其中工具活动采用近似排布，不承诺消除混合模型／工具的全部重叠，不临时增加永久轨道。
- 相同数据得到相同排布。活跃条增长或来源补全可以推动后续条，但保持活动身份、相对顺序、当前选择和阅读锚；用户阅读旧位置时不抢回最新。
- 缩放时重新计算几何，优先保持选中活动的视口位置；无选中项时沿用既有阅读锚。不能用顺延后的 x 坐标反推出来源时间。

这改变了首轮“所有活动严格共用线性位置”的工具轨约束，不改变时间记录本身，也不改成仅表示顺序的轴。

## 4. 原始“参数／结果”详情

### 4.1 原始字段映射

下表是读取规则，不是新增一套合成工具调用。字段存在时取原值；来源字段命名按实际 JSONL 保留。

| 来源类型 | 参数区 | 结果区 |
| --- | --- | --- |
| raw `function_call` | `arguments`，通常是包含 JSON 的字符串 | 相同 `call_id` 的 `function_call_output.output` |
| raw `custom_tool_call`，包括 Code Mode `exec` | `input` 原始代码字符串 | 相同 `call_id` 的 `custom_tool_call_output.output` |
| canonical `CommandExecution` | 来源实际提供的 `command`、`cwd` 等参数字段 | 原始聚合输出及实际提供的退出码、耗时字段；字段名不改写为伪造的 `output` |
| canonical `McpToolCall` | `arguments` | `result`／`error`，保留来源对象结构 |
| canonical `DynamicToolCall` | `arguments` | 来源的内容项、成功标志等结果字段，保留原字段名 |
| canonical `FileChange` | 若没有独立参数字段，说明“源记录未提供独立参数” | 来源 `changes`、`status` 及实际存在的输出字段，不重新拼 diff，也不把失败时的拟议修改宣称为已应用 |
| 其他仍可见的工具类型 | 仅采用可明确识别的原始参数字段 | 无法可靠拆分时展示该工具的原始 item JSON，注明来源；不按相邻活动猜配参数 |

“原始”指字段值和结构来自来源；对象／数组可以仅做 JSON 缩进与显示转义，不要求复现原文件的空格和字节排版。字符串不额外 `json.loads` 后重排；不把结构化结果数组展平为拼接文本；不补造来源中不存在的字段。字段筛选只为分成两个区域，不生成命令、代码或差异正文。

空字符串、`null`、`false`、`0`、空数组／对象与字段缺失要区分。仅参数字段缺失不应让整个活动返回 `missing`。没有明确 `call_id`／来源引用时，不把外层 `exec` 参数当作某个内部命令的参数。

### 4.2 内容状态与截断

- 已取得的原始内容按现有游标分块读取；继续加载只读取源中已有的后续内容。
- `source_truncated` 只基于已确认的来源截断信号／约定标记；不因达到某个长度、代码中出现“truncated”字符串或 Monitor 分页而声称来源截断。
- 区分来源暂未落盘、未保存、读取失败、文件已移除，以及此类型本来就没有正文。来源文件存在但缺少某个活动内容时，不笼统断言历史文件已被删除。
- 所有可用结果照实展示，保留来源已有的截断说明，不补造缺失内容。提问答案也不因工具名而假定一定被保存。
- 复用目前的查看器、选择、复制、分块与内容保留能力。工具不再使用专用 diff 加工；模型正文、可见摘要和用户消息继续按其自身内容类型查看。

本机固定版本源码对部分 canonical 命令输出／MCP 结果有约 64 KiB 的持久化预算，raw 工具返回还可能在此前受工具输出预算影响；不能把所有参数和结果概括成同一种上限。首轮已记录的[来源与限制](implementation-results.md#需要保留的限制)继续适用。

## 5. 本轮边界与对原需求的修订

| 首轮要求 | 本次修订 |
| --- | --- |
| R04、R14：输入与多类状态标记 | 保留用户消息入口／标记，隐藏其他状态点；compaction 改为过程条；专门问答响应标记暂缓。 |
| R08、R09：模型阶段 | 补充模型轨上的上下文整理；参数生成与实际执行仍分开。 |
| R11、R15、R17：严格位置及重叠命中 | 工具轨允许最小显示宽度与水平顺延；模型轨仍保留时间位置，普通工具点击不依赖重叠菜单。 |
| R24、R25、R27：活动内容与来源状态 | 工具采用原始参数／结果，不再重构 diff；更准确地区分没有正文、来源缺失及截断。 |
| R18–R20、R29–R38 | 继续遵守稳定身份、阅读状态、质量降级、只读历史、元数据存储及既有指标边界。 |

本轮不新增外层执行投影、完整调用树、专门问答恢复、全量轨迹录制或新发行方案。现有速度、官方用量、菜单栏动画、管理与观察生命周期不在本次改动范围。来源时间即使有效，也只表达该来源记录的生命周期／接收窗口，不额外承诺服务端纯执行时间。

本文件定义本轮差异；首轮已交付行为、截图和旧验收结果保留其原有含义，本轮检查单独记录于[实施与验收结果](refinement-results.md)。
