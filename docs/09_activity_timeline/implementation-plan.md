# 活动时间线：实现计划

日期：2026-10-17。状态：P0–P6 已实施并形成针对性验证；完成范围与限制见[实施结果](implementation-results.md)。下文保留阶段任务和退出条件。依赖顺序为 P0 → P1 → P2 → P3 → P4 → P5 → P6；可独立的阅读和准备工作不必阻塞，但未通过数据验证前不能按假设完成 UI 接线。

## 1. 实施约束

P0–P6 是首轮交付基线。后续调整复用内部工具与现有历史路径，按[Q0–Q4 改动计划](refinement-plan.md)执行；不按本文件旧“共同线性轴／多类状态点／专用 diff”任务重新实现已被修订的行为。

- 保留 Python 核心和 SwiftUI／AppKit，不重写指标、配置恢复或菜单栏动画。
- 先用隔离数据根、合成事件及只读原生预览形成可检查结果，再处理日常运行环境更新。
- 阶段完成应有对应源码／夹具／验证记录，不能以“代码可编译”替代数据语义或原生交互验收。
- 阶段结果见[验收记录](validation-results.json)；已执行内容与未执行环境分别记录，不将计划文字当作验证证据。

## 2. P0：验证数据来源与关联契约

**目标**：确定最小可行历史路径与事件字段，不把样本推论当成通用协议。

工作：

1. 读取当前版本实际 app-server 通知，核对开始／完成时间字段、source／call ID、raw item 和 canonical item 关系；只输出脱敏结构和统计。
2. 对真实本机 paginated 历史建立只读解析样例；补充可获得的 legacy、缺少时间、空／半行、截断及文件替换合成样本。
3. 对照参数生成、Code Mode、直接 patch、动态脚本、并行调用和持久进程交互，列出哪些阶段有独立开始／完成证据。
4. 验证 steering 的成功、拒绝、无活动轮、排队输入等实际事件；固定输入标记的权威来源及去重方式。
5. 验证父子 thread、child 自有 turn、多次派发／复用与跨轮活动的可确认关联范围。关系不够时明确降级，不能按时间邻近补配。
6. 评估历史 API 的只读访问是否适合当前 writer 拓扑；没有安全可达路径就使用 JSONL，不改 Desktop 接入和 Remote 路由。
7. 验证选中活动的实时内容来源／缓冲能否复用；明确尚未落盘和中途订阅的呈现边界。

建议交付：本章下 `source-validation.md` 与脱敏统计，测试目录中的小型合成夹具；最终字段与兼容性变化回写事件映射和技术方案。

**退出条件**：E01–E07 有结论和证据；至少通过隔离探针／夹具证明“实时参数生成区间 → 补充元数据 → 完成后从 Codex 读取参数内容”这一条最小链路，无须在此阶段完成产品模块。不能关联的类型可保守降级，但必须写明，不能隐藏成“全部支持”。

## 3. P1：阶段投影与补充元数据

**目标**：保留真实阶段和时间，摆脱旧 Activity 的状态覆盖及最近 20 条裁剪。

涉及现有 `events.py / engine.py / collector.py / tool_labels.py`，建议新增 `timeline.py`、`timeline_storage.py` 等独立模块；命名可在实现时调整。

工作：

1. 从过滤后的事件与已接受身份事实建立 `TimelineBook`。复用现有身份与去重判断，避免新增一套按文本猜测的解析器。
2. 补齐 steering 的必要请求／结果元数据。核对 producer 时间字段，保持新旧字段兼容，不改变旧 Engine 的速度计算时间。
3. 为生成和执行保存独立 phase；在 `tool_input → tool_ready` 前关闭生成阶段，保留原开始时间，不复用被重置的 Activity 时钟。
4. 明确 patch／静态 Code Mode 分类、alias、镜像、重复、乱序、缺开始及晚到完成的处理。
5. 建立 SQLite 元数据侧文件、schema、幂等 upsert 与观察实例信息；不落盘正文、参数、补丁或工具结果。
6. 实现轮次窗口、跨轮活跃引用和查看器 pin 的保留与清理；长轮次不能只剩最近 20 项。
7. bridge gap、collector 重启、写失败与版本不兼容按质量降级，不影响已有采集转发和指标。

**验证**：阶段顺序、重复幂等、乱序补全、跨轮继续、同名文件不建立关联、侧文件无正文、重启停止可信 live 状态、保留超过 20 项。

**退出条件**：同一输入序列稳定得到相同阶段身份；现有总速、官方用量、主聊天计数和菜单栏投影在相关回归中保持原语义。

## 4. P2：只读历史与详情提供器

**目标**：通过 Codex 自有历史补全内容和可用时间，不复制完整聊天库。

建议新增 `history.py`／相应适配器与 `timeline_query.py`，并对 `cli.py`、运行根隔离及必要本地只读通道做最小接入。

工作：

1. 按明确 home＋thread 定位并核验历史；流式解析目标轮次，建立可失效的来源索引。
2. 实现 paginated canonical 与 raw 内容的分别读取、别名关联；legacy／缺少字段返回内容与未知时间。
3. 实现追加、半行、截短、替换和回滚下的缓存失效；每次引用重新核验来源身份。
4. 合流 sidecar 的生成时间与历史的 canonical item 时间，保留各边界 provenance，不跨语义阶段覆盖。
5. 通过 `ContentRef` 懒读正文、可见摘要、代码／参数、diff、工具输入输出与可用附件引用。长结果分块，不默默截断。
6. 报告 pending、missing、unsupported、partial 和 source-truncated；选中活动需要实时内容时走 P0 已验证的有界临时路径。
7. 只读查询不能触发 `resume / configure / turn/start` 或其他管理／写聊天副作用；不阻塞 collector 事件循环。

**验证**：同一记录实时／历史只出现一次，raw ID 不等于 canonical ID 时不误合并；参数正文可读取而生成时间保持未知；文件被删除和输出被来源截断时反馈正确。

**退出条件**：一轮活动可以无损返回可用元数据和内容引用；删除 Monitor 临时索引后仍可从源历史恢复基础结果，补充元数据缺失只降低相应阶段时间质量。

## 5. P3：GUI 契约、布局模型与最终视觉状态

**目标**：在不接入真实管理操作的环境中，把显示规则变为可验证的布局与选择契约。

涉及 `MonitorModel`、`DashboardStore` 及独立只读预览，建议新增时间线 DTO、查询 client、纯 `TimelineLayout` 与 `TimelineStore`。

工作：

1. 固定版本化 summary／查询契约，支持旧快照与未知类型降级。全文不进 snapshot。
2. 实现共同线性轴、视口裁剪、缩放、固定轨道、重叠／密集区域投影及 hit test。
3. 实现稳定选择、轮次／智能体展开、阅读锚、自动跟随暂停和请求取消；晚到旧响应不覆盖当前选择。
4. 用同一套合成数据补齐最终视觉状态：默认聊天收起、当前轮双轨与 child 汇总、child 展开、重叠消歧、独立查看器、部分观测和长轮次。
5. 确定浅／深色四种模型色阶、工具色、尺寸、可访问命名和键盘导航。参数变化回写 `design-spec.md`。

**验证**：缩放不改变时间顺序／归属，命中目标正确，轨道数量不随重叠变化；视觉状态清楚展示同一数据模型，不再比较互相冲突的时间线模型。

**退出条件**：最终设计状态与纯布局契约一致，可供原生实现直接使用。图像只能证明视觉意图，不能替代 P4／P5 的真实操作验证。

## 6. P4：展开面板时间线

**目标**：替换纯文本活动列表，维持已验证的紧凑面板行为。

涉及 `ChatRowView / DashboardView / DashboardStore`，建议新增 `TimelineView / TimelineHeader / OverlapPicker` 等组件。

工作：

1. 保留两行聊天、当前动作和指标；所有新聊天默认收起，历史聊天继续由历史分组控制。
2. 轮次选择、初始输入入口、模型／工具双轨、图例、横向滚动、缩放和“回到最新”。
3. child 默认汇总与展开双轨，明确的跨轮活动入口；不再重复铺开旧 child 文本活动列表。
4. 输入与状态点、未知时间、观察缺口、失败、读取中和空态。
5. 不改变 popover 顶部锚点、外部点击、`Esc`、菜单与管理确认行为；横向手势不能破坏聊天纵向滚动。

**退出条件**：R01–R20 在合成原生预览中可操作，且日常菜单栏样式与已有指标语义未变。原生证据分开记录点击、滚动和截图，不以截图推断交互通过。

## 7. P5：独立活动查看器

**目标**：一次点击到达可持续阅读的完整可用内容，并与菜单面板有正确的焦点及生命周期关系。

建议新增 `ActivityViewerWindowController / ActivityViewerStore / ActivityDetailView`，由 AppDelegate 协调单窗口生命周期。

工作：

1. 普通窗口创建／复用、收起 popover 后前置、尺寸位置记忆、显示器变化校正。
2. 上下文、同轮时间线、活动切换、按类型呈现的正文／代码／JSON／diff 与复制。
3. 内容分块、异步读取、错误重试、源截断说明；选中项实时更新和阅读位置保持。
4. 重叠候选列表、键盘操作、可访问元素、浅／深色和减少动态效果。
5. `Cmd+W`、最小化、应用切换、重开和 App 退出；关闭查看器释放加载与 pin，不停止观察，不重新配置接入。

**退出条件**：R21–R28 原生验证通过；复用单窗口、焦点、外部点击、关闭后继续采集都有实际操作证据。

## 8. P6：针对性验收与交付记录

按[验证计划](validation-plan.md)完成新增语义及相关回归，记录当前版本、构建来源、数据覆盖和未验证环境。先独立只读 Preview，再按实际授权和运行边界更新日常 App；不因写了新 UI 自动重做安装、恢复配置或 Remote 全链路实验。

建议交付：

- `implementation-results.md`：完成阶段、最终参数、兼容范围、本机更新／重载边界、残余限制。
- `validation-results.json`：需求编号、验证层次、结果和证据路径；未执行项保持未验证。
- `assets/`：合成数据的最终设计／原生截图；不提交真实消息、命令、补丁与输出。
- 可复用预览、夹具与必要测试；README 状态从“设计基线”更新为实际交付状态。

**完成条件**：验收矩阵没有未解释的关键缺口；不把已知历史缺失或输出截断包装成完整支持；相关旧功能回归通过。提交、推送和发行状态分别记录，不能默认为已完成。

## 9. 工程决策的回写规则

P0 遇到字段缺失、ID 不可关联或历史格式差异时，优先使用已定降级，不重新发明用户工作模型。只有发现必须改变用户可见范围或核心交互，才提出具体差异；普通模块拆分、DTO 字段与渲染参数由实现者决定并回写文档。
