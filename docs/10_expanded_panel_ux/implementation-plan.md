## 2. 实施前必须核实的数据边界

1. **统计与轮次**：检查当前快照生产端如何关联 `Chat.turn_id` 与 `Usage`，以及新轮切换和迟到用量更新。仅靠同次快照、接近的时间或相同标题不能建立归属；`latest_reasoning.turn_id` 需要单独核对。
2. **历史统计**：现有时间线 bundle 没有本轮统计 DTO，不默认承诺所有历史轮都有用量。先复用有明确归属的数据；缺失时显示未知。若需要只读透传已有轮次元数据，另记最小向后兼容字段与验证依据，不重建账本。
3. **完成时间**：当前 `Chat` 没有独立完成时间字段，`last_progress_seconds` 不能直接变成“几分钟前完成”。可使用已加载且身份匹配的结束记录；无记录就用状态，不能为每行时间文案主动加载所有历史正文。
4. **当前状态与所选历史**：聊天展开区中的实时状态、轮次状态和统计归属分别建模。禁止用本地化动作文本猜状态。

这些核实可以得到“数据不可用”的有效结论，不要求先扩充历史采集才能完成界面。

## 3. 分步修改

### P1：默认展开与阅读状态

- 按 `Chat.id` 所含作用域和稳定 thread 身份维护展开；默认值由现有明确工作状态决定，不按中文标题判断。
- 建议将“默认状态”和“用户手动覆盖”分开保存，避免每次刷新对 `expanded` 全量赋值。
- 同一次展示保留手动展开、最近完成分组、列表位置和选择；关闭后重开应用本章默认规则。无关刷新不重排。
- 聊天完成时按既有规则分组，不清空无关聊天的状态；已打开的活动窗口继续沿用原有生命周期。
- 不增加单聊详情路由、“查看详情”按钮或返回入口。

完成条件：有限合成状态测试覆盖 V01–V05、V13 的状态部分。

### P2：聊天内轮次分组与统计投影

- 运行与最近完成聊天复用相同的轮次内容组件，每个聊天继续使用同一个 `TimelineStore`。
- 分组和统计重排放在面板专用承载层。独立窗口目前使用 `TimelinePanelView(compact: false)`，不能通过全局样式或共享布局修改让该窗口一起改版；不修改 `ActivityViewer` 的布局和控件。
- `prepareForPresentation()` 保留面板新开、运行聊天主动重新展开时的最新定位；普通刷新或布局重建不能误重置正在阅读的历史轮次与位置。
- 顺序固定为轮次入口、时间线、归属明确的统计、补充说明。保留轮次切换、输入入口、子智能体和旧轮仍运行提示。
- 统计区按 [chat-detail-concept.png](assets/chat-detail-concept.png) 的局部布局做成两列：左侧“输出”标签、突出数值及次级“含推理”，右侧“推理均速”标签与突出数值；标签与主数值分别对齐，不使用概览修订图中的纵向堆叠。
- 为统计增加纯展示投影：所选轮次、可靠归属、可用数值、未知原因和说明，避免视图自行拼接错误范围。
- 模型信息及最近推理均速的归属独立核对；跨轮不改写来源，也不把最后有效值包装成本轮值。

完成条件：V06–V09 通过；现有时间线比例、命中和覆盖语义保持。

### P3：中性面板分组与原生展开

- 更新工作分组、聊天摘要及可用状态层级，运行聊天默认内联展开，最近完成默认收起。
- 首选 `DisclosureGroup` 自动样式；在实际 macOS 上验证小型控件外观和标题点击范围，再决定是否需要局部 `DisclosureGroupStyle`。
- 标题只负责原地展开／收起，轮次和缩放等内部控件独立响应；核对点按、悬停、键盘焦点、辅助功能状态和减少动态效果。
- 去掉聊天与轮次的大面积蓝／紫底，使用原生中性表面、标题、间距和必要的细分隔线。时间线内既有选区不改。
- 沿用 420 pt 起点与基于屏幕的最大高度，不因加入分组缩进让时间线绘图区失去必要宽度。保留原生细滚动条。

完成条件：浅／深色原生只读预览覆盖 V01–V05、V10–V14。展开／收起后的阅读锚点需实际检查，不能只凭状态变量宣称通过。

### P4：既有窗口入口回归与交付

- 不改独立活动窗口的布局、控件和行为，不重新组织其时间线、参数／结果或上下文。
- 只核对面板点单项活动或重叠工具时，仍把正确记录和固定命中集合传给现有窗口。
- 运行受影响的 Swift 检查与构建；用手写合成记录做有限原生验收。新增默认展开后，核对多个活跃聊天的并发查询与取消，避免重复轮询同一 `TimelineStore`。
- 用户随后授权按本文档实施；P1–P4 的实现、原生检查和本机加载已完成，结果另记，不把本页的计划描述当成验收证据。

完成条件：V08、V12、V15 通过，新增实施结果记录实际参数、证据、未覆盖项和是否更新本机。既有独立窗口保持原有外观和交互；采集、Remote、恢复和发行矩阵不因布局调整重复执行。
