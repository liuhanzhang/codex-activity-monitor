# 本机 GUI 使用

本地开发版本，目标 macOS 26+。需要已有 `.local/venv` 与可构建 macOS 26 API 的 Xcode / Swift 工具链；当前尚未把 Python 和依赖封装进发行包。

```sh
bin/build-gui
bin/run-gui
```

构建产物为 `.local/gui/Codex Monitor.app`，也可以直接打开。构建只生成 App；首次打开时自动接入 Codex，默认开启登录启动。若 Codex 早已启动但没有继承接入配置，任务结束后正常退出并重开 Codex。

菜单栏显示已接入独立生成流的总速度；点击打开聊天与活动面板。聊天行可展开工具活动和子代理。`≈` 表示分词或接收窗口估算；`—` 表示未知、部分观测或数据已过期。Output 包含 Reasoning，两个计数不能相加。推理速度保留最近有效估算，并非服务端纯推理速度。

- **配置**：启用或修复接入。重复配置、移动 App、重装会沿用尚未恢复的原备份。
- **设置 → 登录时启动**：开关 GUI 登录项。采用 `SMAppService.mainApp`，系统要求批准时可打开系统设置。
- **退出 Monitor**：停止采集，保留配置；已有 Codex 通信继续。重新打开恢复观察，中间区间标为缺口。旧包装进程尚未升级时界面会提示，任务结束后重开 Codex 即可加载新能力。
- **恢复配置…**：恢复接入前的变量或未设置状态，保留用户后来修改的值。Codex 仍在运行时先恢复配置，再等待退出后清理；提前退出 Monitor，下次继续。正常恢复后重开保持未接入，主动点击“配置”才重新启用。
- **清理本机数据并退出，用于卸载**：在恢复面板勾选。依赖安全退出、登录项注销与清理全部完成后 App 退出，随后手动删除 `.app`。再次打开按首次启动处理。

直接删除 App 时没有常驻卸载 Helper。App 外的 shell 入口在下次启动时回退原版 CLI；它不能自动清除所有残留，也不能修改已运行进程继承的环境。重新打开重新下载的 App，可以继续恢复。

## 路径与现有终端看板

管理记录、准确原值备份、启用标记和启动入口位于 `~/Library/Application Support/CodexProgressMonitor/`，不随 App 包删除。新安装运行目录为该目录下 `run/`；本机从 TUI 迁移时沿用 `.local/runtime/`，不移动活跃包装进程依赖的路径。源代码和开发 venv 不属于 App 卸载清理范围。

原有 `bin/codex-progress watch` / `status` 可以继续读取同一运行目录。GUI 管理接入后，配置与卸载请使用 App；旧 `setup` / `uninstall` 会拒绝覆盖 GUI 管理状态。退出 GUI 后看板仍可开着，但不会继续采集。

只读预览不修改接入：

```sh
bin/run-gui --read-only --window
```

只读预览可加 `--preview-dark` 检查 App 自身深色外观，不改系统外观；该参数仅在只读或隔离验证模式生效。

如果已有 GUI 实例，先正常退出再选择不同启动参数。`--window` 是开发检查入口，正常使用点击菜单栏即可。

当前验证范围与未完成项见 [实施结果](implementation-results.md)。当前开发版本依赖本机源码、venv 和原 CLI 路径；GitHub Release、自包含 Python、正式签名与公证另行交付。
