# 实时模型补充的退出规则

日期：2026-10-22。状态：已实现、通过定向回归并载入日常后端及 GUI。首轮修复后的补充，基线 `99b3b81`。本次补齐 R13；不调查 Codex 为何没有将某次实时开始形成持久化消息项。本文记录提交前的验证结果，提交信息以 Git 历史为准。

## 已确认的问题

原始截图中的浅紫色活动来自一次实时思考开始观测。该回合的 JSONL 没有这个 ID 对应的思考完成事件或内容记录；文件中后来出现的 ID 只是诊断文本引用。

首轮代码将保留的实时条目与 JSONL 合并，同 ID 时优先采用历史事实。没有历史对应项的旧实时模型活动在回合结束后仍保留为 `unknown`，绘图又以 `observed_until_ms` 作为右端，把不确定窗口表现为持续生成。

“已保存的历史优先”还需要规定实时补充何时退出普通展示，不能仅靠同 ID 覆盖。

## 实现规则

1. 在身份核验成功、读到完整末行并到达当前 EOF、没有解析质量异常的历史视图中，只有存在明确终止状态及结束时间的回合才能决定模型条目集合。
2. 对上述回合，JSONL 中没有匹配 `(scope, thread, turn, item type, item ID)` 的实时模型生成条目退出普通快照和时间线。覆盖思考、正文、计划及原始工具参数生成；工具执行和跨回合后台进程继续按自身生命周期处理。
3. 对应历史项存在时继续保留可用的实时字段补充。实时已完成但历史回合尚未结束时，完成状态立即可见，无需等待落盘。
4. 原有观测记录保存在有界的观测缓存及元数据 sidecar，增加 `history_retired` 标记，不伪造 item 完成或结束时间；普通查询不显示该条目，按已知 ID 读取诊断仍可返回观测元数据及 `not_retained` 状态。
5. 不完整、不可读或异常来源不能产生新的退出决定。先前可靠确认的退出决定在短暂读取失败时保留；有效替换或截断后的来源重新计算资格。迟到历史项追加后按正常身份合并恢复。
6. `Engine`、时间线后台合并和按需查询共用成员资格规则。collector 停止或重载后，元数据中的退出标记仍阻止旧条目重新进入普通时间线。

`HistoryProvider` 明确返回 `read_complete`。这只是当前一次读取已抵达完整行边界的 EOF，不表示文件以后不会追加，也不以静默时长推断落盘完成。

## 时间线几何

截图中的实时孤立思考在确认历史回合结束后完全退出普通时间线，不画短标记。

对仍有资格显示的条目，宽度只采用可用的活动起止时间；可靠活跃条目可以延伸至当前时刻。非活跃条目缺少时间边界时保持耗时未知及最小选择宽度，不使用观测截止时间补造持续区间。例如原始工具参数内容可能只有外层记录时间，没有参数生成阶段的起止字段。完整思考完成事件及同 ID 内容记录应先关联，不能仅凭内容行没有时间字段就判定整个活动没有时间。
