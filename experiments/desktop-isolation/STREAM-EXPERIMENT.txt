Use the existing signed app, a distinct Electron profile, a distinct Codex home,
and a localhost WebSocket app-server. No repackaging or Computer Use is involved.

stream_probe.py connects to the latest isolated backend and runs one dedicated
persisted test chat with a second client subscribing through thread/resume.
The text mode records exact received text increments and JSON payload bytes.
The command mode runs a three-second, stdout-only Python command, observing its
start, output increments, and completion. Test prompts are sent over RPC;
Desktop UI-initiated tasks have not yet been checked.

The prototype prints one-second status samples and saves raw event evidence,
text, samples and a summary under the corresponding run directory. It is an
experiment driver, not yet a passive monitor or graphical progress display.

Boundaries:
- Counts measure observer receipt, not model-side generation speed.
- JSON payload bytes include event metadata and are not upstream reasoning bytes.
- No verified tokenizer is present, so live token/second is not reported.
- Hidden reasoning progress is unverified. A quiet interval must be displayed
  as time since the last event, rather than interpreted as a hang or reasoning.
- Usage also includes tool-call output; it is not always visible body text only.
- Multiple clients cannot resume the tested ephemeral chat; persisted test chats
  were used to validate subscriptions.
- Desktop connection environment variables are undocumented and may change.

Source distinction:
Local public Codex source at 325cf16194 (2026-07-14, older than installed CLI)
parses response.custom_tool_call_input.delta and passes it only to a registered
tool argument diff consumer. Its test explicitly skips function arguments delta.
Direct apply_patch has a consumer gated by apply_patch_streaming_events, default
false and under development; the installed backend lists the same flag as false.
Tool execution is scheduled after OutputItemDone. The official Responses API
itself supports argument deltas, so execution waiting for complete arguments
must not be confused with inability to stream argument generation upstream.
We did not capture this backend's raw upstream model transport.
