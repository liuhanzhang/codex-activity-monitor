# 技术方案

日期：2026-10-29。下文保留本轮技术方案；实现与验证的实际状态见[实施结果](implementation-results.md)，范围和源码基线见[本章入口](README.md)。

## 1. 沿用现有读取与校正链路

继续由 `HistoryProvider` 拥有历史缓存和读取锁，后台 `HistoryRefresh` 交接明确选择范围内的事实，`TimelineQuery` 提供只读时间线与详情。原始 stdio 转发、实时分词和一秒速度计量不增加同步历史 I/O。

在现有模块之间补齐两个职责：当前 rollout 的解析，以及有范围的历史来源集合。可以新增小型来源解析模块，避免把 SQLite、文件发现和引用链逻辑散落在 GUI、Engine 和各类索引中；不另建一套常驻正文存储。

| 现有位置 | 预计改动 |
| --- | --- |
| `events.py`、`bridge.py`、`engine.py` | 有界保留并传递必要的路径／历史模式提示；处理回退等来源失效信号 |
| `history_contract.py`、`history.py` | 为选择增加可选来源提示；集中解析当前来源与继承范围；统一缓存来源代次 |
| `history_index.py`、`history_read.py` | 索引和正文引用绑定实际文件及有效区间；支持对多个合法区间的窄读取 |
| `history_refresh.py`、`reconciliation.py`、`timeline.py` | 交接来源代次和覆盖范围；拒绝旧来源结果，撤销已失效的历史权威结论 |
| `timeline_query.py`、`request_rate.py` | 时间线、详情及所选轮均速使用同一有效历史视图 |
| `agent_identity.py` | 复用来源解析，避免另一套文件名查找继续选中旧头部 |

具体文件拆分以实现时的最小职责边界为准。新增桥接字段需兼容旧 bridge 缺字段的情况，并纳入桥接实现身份和重启提示的核对。

## 2. 分离聊天身份和来源身份

对外的聊天、轮次、活动身份继续使用现有 scope/thread/turn/item 规则，不用新 `rollout_id` 创建一段新聊天。内部来源描述至少包含：

- Codex scope、请求聊天 `thread_id`、选中的 `rollout_id` 与规范路径。
- 实际来源头部的聊天身份、文件身份及头部摘要。
- 每段允许读取的 ordinal 范围和字节截止位置，以及引用它的上一级边界。
- 组合来源代次；供所有历史缓存、异步结果和校正事实比较。

来源代次与普通追加修订分开：当前路径、文件替换、继承链或截止边界改变时换代；当前活动文件正常追加只推进原增量读取修订，不因此重扫全部祖先。

## 3. 当前 rollout 的解析

优先利用已观察到的 Codex 元数据和只读状态索引，不能继续依赖“文件名最后一个 UUID 就是聊天 ID”。

1. 从 `Thread.path`、历史模式等现有回复／通知中提取有界元数据提示；字段可选，不转发整个 Thread 或任意正文。不新增主动 Codex 请求。
2. 在配置可确认时，只读查询对应状态数据库的 `threads.rollout_path`、`history_mode`。本次基线使用版本化的 `state_5.sqlite`，文件名与 schema 适配集中维护。考虑明确的 `CODEX_SQLITE_HOME`／`sqlite_home` 配置，不能假设数据库永远在默认 Codex home，也不按 mtime 或最大的版本号猜数据库。
3. 对 paginated 聊天，已确认的当前数据库记录优先于旧协议提示和目录候选。观察到 `thread/reverted`、重连或提示与数据库冲突时，失效提示并重新解析。协议路径是带新鲜度的提示，不等同于直接访问 Codex 内部 live writer。
4. 没有可靠状态记录时，可使用新鲜且通过身份校验的协议路径。再无可靠提示时，才用兼容旧布局的文件系统回退：解析两种文件名，核对头部；有多个可能的当前来源则返回未知，不按最新修改时间挑选。
5. 已知 paginated 当前路径不可读、缺失或不匹配时，不退回旧分支伪装为成功。短暂发布／移动竞态可有限重试，超出期限明确降级。

所有候选必须在当前 scope 的受管 `sessions/` 或 `archived_sessions/` 根内，规范化路径后校验文件类型和头部，不能通过嵌套符号链接读到其他 scope。按 thread 精确查询，只读连接设短超时，不创建或迁移数据库，不修改 journal 设置；无法确认数据库配置时保留未知状态。

路径检查与发现放在历史读取 worker 中。热查询使用有界的短期解析缓存，目标是切换在下一次常规刷新附近被发现；即使旧文件仍存在，也必须周期核对当前指针。明确失效事件不等待缓存到期。具体 TTL、重试次数和扫描预算在实现时用定向测试固定，不能形成每次查询递归扫描全部历史的路径。

## 4. 有边界的继承读取

从选中的当前 rollout 出发解析 `SessionMeta.history_base`，按引用的 rollout 身份寻找祖先，而不是把所有同名聊天文件拼起来。

- `history_base.thread_id` 是历史遗留字段名，实际表示引用文件的 **rollout ID**，不保证等于当前聊天 ID。
- `end_ordinal_exclusive` 是不包含该 ordinal 的截止位置；`end_byte_offset` 是最后一条包含记录之后的 JSONL 字节位置。两者均需校验，字节边界必须落在完整记录末尾。
- 新文件头部自身也有 ordinal。按上游规则理解祖先范围、当前文件头部和自身记录的起始位置，不把头部重复投影成活动，不用“少一行／多一行”的猜测处理边界。
- 支持多次回退和普通用户聊天分叉形成的多段引用；记录已访问 rollout ID，拒绝循环、越界、冲突身份和非法顺序，并限制链长度、扫描时间及缓存占用。达到预算时返回部分／不可用，不能默默截断后声称完整。
- 每个祖先保留自身的头部和来源身份验证。分叉时祖先可能属于不同聊天：校验“声明的引用 → 实际来源”，不能机械要求每个源头部都等于请求聊天，也不能直接取消身份检查。展示视图中的归属必须与上游普通 fork 的语义用例对齐，保留原始 turn/item 身份和内部来源引用，不把继承记录注入实时事件入口。
- 先形成有效来源区间目录，再按所选 turn、item 和明确 call 依赖读取，复用现有窄索引。正文引用包含具体来源文件及区间，不能跨文件共用裸 offset。

时间线、活动详情、后台事实校正及所选轮均速必须消费同一来源集合。请求计时按有效记录顺序推进，不重复计算共享前缀，也不纳入截止位置后的 usage。若某个选中轮次所需的边界无法证明，就沿用未知／部分覆盖语义，不拼凑一个完整平均值。

RH03、RH04 的完整支持仍暂缓。压缩祖先暂不可读时，保留可证明的当前后缀，标记覆盖不足；子智能体／attached thread 带专门继承边界时，不借本次普通 fork 支持把未解释的父前缀新增为子智能体活动。专门边界不具备证明时保守限制投影，完整语义后续单独验收。

## 5. 缓存、异步交接与旧结果

当前目录、完整索引、turn/facts/timeline/detail 窄索引、来源路径提示及平均速度账本，都必须在复用前核对组合来源代次。缓存淘汰后重新构建，也不能仅因为旧文件未改动而复用旧来源结论。

来源切换时：

1. 失效该 scope/thread 的派生索引和过时路径提示；未变化的不可变祖先可在校验区间后复用。
2. 给正在执行的历史读取绑定请求来源代次；新代次生效后，旧结果不得覆盖新结果。校正不能仅按异步到达顺序或各文件自己的 revision 大小排序。
3. 撤销被证明失效的历史完成依据和所选轮均速。删除／撤销只能作用于明确覆盖范围；部分链读取失败不能用来证明其他活动不存在。
4. 保留“实际观察到的活动”和“当前有效源历史”之间的区别。已丢弃分支的内容不得作为当前历史返回，已有工具执行事实也不能仅因不再属于模型历史而被改写成未发生。
5. 翻页或刷新期间重新验证当前来源和所选内容的有效成员关系。保留已有内容摘要及分页校验；即使旧文件字节未变，也不能继续从已丢弃分支加载下一页。界面可按现有机制保留已加载内容并提示重读。

来源代次优先内部传递；如需增加可选查询字段，应保持旧端可解码，不为本次修复重做整个 GUI 协议。新增用户可见原因时补齐中英文文案。

## 6. 失败处理与资源约束

区分当前指针未知、已选路径暂不可读、继承链不完整与目标活动确实无可查看内容。复用现有质量和不可用状态表达；无法准确表达时才增加最小的原因字段，不能把所有失败都写成“源历史尚未写入”。

保持现有历史缓存与选择索引预算、后台工作限额和查询回复大小限制。稳定文件上不为每秒查询重扫完整链；多文件打开、验证、摘要与正文读取仍在历史 worker 中完成，不能持有 Engine 事件锁。来源在读取期间变化时有限重试或失败，不返回混合代次正文。

压缩支持暂缓不代表可以将 `.jsonl.zst` 判为用户删除历史；记录暂不支持／覆盖不足即可。实现不得为读取而在 Codex 目录生成解压副本、修复索引或更新数据库。

实现完成后的已支持形态、保守降级形态与实际性能记录另记结果；本方案不等于已经具备上述能力。
