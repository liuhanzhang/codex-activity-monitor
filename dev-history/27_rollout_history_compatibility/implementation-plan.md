# 实施与验收计划

日期：2026-10-29；交付状态更新于 2026-10-30。RH01、RH02 及本轮隔离验收已完成，日常 Monitor 已按用户要求更新并重启；Codex 的旧 bridge 尚未重启。下文保留原实施顺序和验收门槛。实际结果见[实施结果](implementation-results.md)，问题与优先级见[本章入口](README.md)，读取语义见[技术方案](technical-design.md)。

## 实施顺序

| 阶段 | 工作内容 | 阶段完成条件 |
| --- | --- | --- |
| S1：固定复现与兼容边界 | 将 RH01、RH02 的临时合成复现转为正式回归；制作普通、回退、连续回退和用户 fork 的有效历史期望；固定上游字段及截止规则 | 用例能准确触发现有缺口，期望依据上游语义；包括旧分支不得读取的反例，不使用真实会话数据 |
| S2：当前来源解析 | 实现集中解析器、只读数据库适配、可选协议提示及旧布局回退；接入 provider 和头部身份查询；建立来源代次和失效入口 | 数据库指向新文件、旧文件仍存在或缓存已预热时，均能切换；字段缺失、身份冲突和配置未知时不猜错分支 |
| S3：有效继承区间 | 解析 `history_base` 链及双重截止边界；接入窄目录、选中 turn/item 正文引用；先覆盖本轮约定的未压缩普通聊天形态 | 本轮与保留的前几轮可读，多次回退／fork 不遗漏有效前缀、不带入被排除后缀；预算和损坏链有明确降级 |
| S4：统一查询与校正 | 时间线、详情、facts、均速共用有效来源；修复异步晚到、缓存重建、分页及派生元数据失效 | 旧结果不能覆盖新来源；已丢弃分支不再提供当前详情或均速；实际已发生的工具事实与历史成员关系分开处理 |
| S5：集成与交付记录 | 跑相关回归及完整 Python 套件，按变更决定 Swift 检查；构建独立 App／DMG，做隔离链路验收；更新产品兼容边界与本章实际结果 | 下列本轮门槛均有证据；本地通过、日常替换、Codex bridge 重启和自然使用验收分别记录状态 |

以上按依赖串行推进。中间提交可分为“来源定位与切换”和“继承读取与一致性”；只有两部分一起通过，才算本轮核心问题完成。临时放宽 glob 不单独作为最终修复交付。

## 本轮必过回归

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | 传统单文件、无数据库／无新增协议字段 | 保持已有读取能力，未引入必须重启旧 bridge 才能查询的依赖 |
| A02 | 旧文件保留，当前指针切到 `{thread_id}_{rollout_id}.jsonl` | 当前活动从选中的新文件读取，不能按 mtime 或唯一旧文件误选 |
| A03 | 目录、详情、窄选择和均速均已预热，随后切换当前来源 | 下一次有效解析后统一换代，旧缓存路径存在也不继续充当当前来源 |
| A04 | 当前 paginated 记录存在，但目标暂时缺失／身份不符；同时有合法旧文件 | 有限重试或明确不可用，不回退旧分支并声称成功 |
| A05 | 数据库配置在其他明确目录、只读／繁忙／schema 不支持，协议提示缺失或冲突 | 不写入数据库；按证据和兼容边界降级，不扫描猜测“最新数据库” |
| A06 | 一次回退，旧文件包含保留前缀和被丢弃后缀 | 保留的前几轮可查看；被丢弃部分不能作为当前源历史读取 |
| A07 | 连续回退、回退到更早祖先、普通用户聊天 fork | 按各段截止位置读取，turn/item 归属及内容匹配；共享前缀不重复 |
| A08 | 截止处的完整行、前后一条记录、不同源头部与 ordinal | ordinal／byte 边界一致；头部不重复投影，不越界读取，合法跨聊天引用不误拒绝 |
| A09 | 循环、缺祖先、非法／越界截止、跨 scope 路径、超长链 | 不读入错误来源；明确部分／不可用；不把无法读取等同于活动不存在 |
| A10 | 旧读取任务晚于切换后的新任务完成；读取中发生文件替换或指针变化 | 丢弃或重新验证旧代次结果，不混合两套正文／完成事实 |
| A11 | 打开旧详情并翻页时发生回退；旧源字节完全没变 | 不能从已失效分支继续翻页；按现有内容变化／不可用机制保留阅读状态并引导重读 |
| A12 | 所选轮次横跨合法继承区间；截止之后仍有 usage；切换历史轮次 | 均速只用该轮有效区间的样本，不带入丢弃分支；无法证明的计时显示未知或部分覆盖 |
| A13 | 实时 delta 持续到达，同时读取／切换历史；无关聊天仍在活动 | 原始转发不等待历史；实时身份、计数窗口和其他聊天不被旧历史结果污染 |
| A14 | 命中暂缓的压缩祖先、子智能体或 attached 特殊边界 | 不宣称完整兼容，不扩大父前缀的活动归属；可证明的后缀保持可读，覆盖不足可诊断 |
| A15 | 源稳定时重复查询、长链、缓存淘汰与重建、超预算 | 沿用有界缓存与窄读取；热路径不反复扫描全部历史，不阻塞 Engine；不足时明确降级 |

S1 应先补关键失败用例；其余随对应阶段增加有意义的反例，不为每个内部 helper 编写与实现同构的测试。

优先扩展 `test_history*.py`、`test_timeline_query.py`、`test_reconciliation.py`、`test_request_rate.py`、`test_content_paging.py`、事件过滤及资源预算相关用例；必要时增加独立来源解析测试文件。所有期望值来自合成的有效历史序列，不从被测解析器反向生成。

## 集成检查与完成标准

1. **行为回归**：受影响的历史、查询、校正、均速、分页、事件与资源预算用例通过，再运行完整 Python 回归。新增文案时检查本地化导出；涉及 Swift 解码或展示时运行相关 Swift 测试。
2. **隔离联调**：在 disposable Codex home、状态数据库与 Monitor profile 中，模拟 bridge／collector／GUI 查询期间切换当前路径并追加新轮次。界面能从新来源打开本轮详情，切回保留的前几轮有正确内容，已丢弃部分不再冒充当前内容。使用真实的回退文件布局与引用字段，不能只在同一路径覆盖 fixture。
3. **速度保护**：用可核对的实时 delta 序列比较修复前后的计数和一秒窗口结果；另用独立期望核对继承区间内所选轮均速。两项分别验收，不以历史可读推断实时测速已验证。
4. **资源与只读边界**：针对新增来源切换／继承场景复用现有预算检查，确认热查询复用、失败有界、没有锁住事件处理，测试前后 Codex 源文件与状态表没有被 Monitor 修改。
5. **独立包验收**：构建 App／DMG，确认新增来源模块和只读 SQLite 依赖被打入包中；从 DMG 复制后在隔离环境复核查询链路。必要的 Swift SDK 设置按现有构建环境处理，不改变部署目标来绕过构建问题。
6. **交付记录**：写明实际提交、支持的上游基线、通过的场景和剩余边界。更新日常 App 是独立步骤；若桥接代码改变，分别核对 GUI、collector 和现有 bridge 的构建身份，并记录旧 bridge 兼容读取与重启后的新字段验证。不得为验收中断用户正在进行的 Codex 任务。

本轮完成要求 RH01、RH02 的本轮支持形态及降级门槛通过。RH03–RH06 不作为完整修复的发布门槛，也不因为触及同一模块就顺手扩大范围；但不能借本轮变更引入新的错误来源读取或活动归属。

| 问题 | 后续工作方向 | 提升优先级的条件 |
