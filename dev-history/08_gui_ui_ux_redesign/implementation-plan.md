# GUI 重设计：实施计划

日期：2026-10-16。状态：S1–S5 已实施并更新本机 App。本文保留实施前基线和步骤；最终参数、证据及未覆盖环境见[实施结果](implementation-results.md)。需求与 U1–U10 见[产品需求](requirements.md)。

## 1. 实施边界与当前基础

沿用 Python 核心和 SwiftUI / AppKit，不重写计量、用量账本或配置恢复事务。本轮集中修改展示投影、菜单栏承载、面板布局和交互。先用合成快照和只读原生预览验证，再替换本机 GUI；不为调整 UI 重跑已有采集和安装验收。

## 2. 最小状态契约

由核心在现有快照上增加可选、版本化的 `menu_presentation`，不改变全局 `schema_version` 或原有字段语义。以下契约已实现：

```json
{
  "menu_presentation": {
    "version": 1,
    "mode": "thinking",
    "active_conversation_count": 1,
    "reason": "reasoning"
  }
}
```

- `mode`：`speed / thinking / executing / unavailable`。空闲、等待和多会话均可使用 `speed`，具体原因由 `reason` 区分；无可靠数值时使用 `unavailable`。
- `reason` 为稳定语义标识，例如 `generating / reasoning / executing / multi_conversation / idle / waiting / paused / coverage_incomplete`，不传本地化后的动作标签作为状态码。
- 数值继续读取 `overview.generation_rate`，不在新投影中增加一套速度；部分小计仍单独读取 `overview.observed_subtotal`。
- 主会话计数基于全部逻辑 Thread 的明确父子树；不复用 `displayedChats` 或直接把 `active_thread_count` 当作主会话数。丢失父项、冲突和循环按需求保守处理。
- 核心复用活动 / 流生命周期与质量判断：活动生成优先，其次确认执行，再其次确认 reasoning；准备、等待、审批或泛化的“处理中”不能冒充二者。
- Swift 在每次读取后独立检查新鲜度、连接和契约版本；过期立即降为 `—` 并停动画。旧快照缺投影时仅显示可靠总速或 `—`，不推断动画。

实施时可根据最小改动调整新字段的组织，但必须用契约用例固定上述语义。数字格式属于 GUI；局部四舍五入不回写原始快照，不更改 TUI 和计量测试。

## 3. 分步实施

### S1：固定状态规则与小范围回归

1. 提取菜单栏语义投影，复用既有明确活动、逻辑身份和父子关系，不增加主动查询或正文落盘。
2. 覆盖单主会话、多个主会话、父已结束但子仍活跃、多个子代理、缺失 / 冲突父关系、镜像流、部分覆盖、暂停与过期。
3. 单独覆盖活动生成短暂停顿、可见摘要、工具参数生成、明确流结束后的残余速率，以及准备与实际执行的边界。
4. Swift 增加最小 DTO 和纯展示决策，统一有限非负数值格式；旧快照和未知枚举保守降级。

完成条件：状态表可由无正文的合成样本验证；既有总速与用量口径不变。对涉及的 overview / 活动语义 / Swift 模型运行针对性测试，不重复全套历史实验。

### S2：原生菜单栏固定区域与动画

1. 以固定 `NSStatusItem` 长度或等效自定义内容承载统一区域；生成态移除常驻波形，只显示整数 `T/s`。
2. 用真实字体测量常见和超长数值，固定宽度、对齐和溢出策略；按当前显示器坐标验证相邻图标位置。
3. 实现三点轻跳与小锤子敲击；动画时钟与快照读取分开，避免为动画重复启动 Python、读取快照或分词。
4. 明确状态更替、暂停、过期、减少动态效果及 App 退出的开始 / 停止逻辑；可访问名称和悬停说明随语义更新。

完成条件：用固定样本覆盖 U1–U4、U10 的菜单栏部分；实际录制短片检查节奏与状态停止。网页动效预览只作为视觉参考。

### S3：紧凑面板与稳定列表

1. 把固定窗口改为约 420 pt 宽的内容尺寸布局，顶部一行、两行聊天、按需详情、最近完成折叠和简短底部。
2. 高度依据内容计算，上限结合按钮所在屏幕与可用空间；列表超限才滚动。展开时保持顶部锚点不变。
3. 使用稳定 ID 和会话内固定排名；速度和进度刷新不改变同组顺序。新增 / 完成仅调整对应组，不重置展开状态或无关滚动位置。
4. 仅把终态活动放入最近完成，沿用保留时间和数量边界。缺失标题、长项目、长动作、未知指标及多层子代理都有可读布局。
5. 配置、恢复、登录启动和退出移到顶部设置；继续调用原管理方法并保留所有禁用条件、错误反馈及恢复确认。

完成条件：空状态、两个聊天、多项聊天、展开详情、父子树、异常提示、浅 / 深色的原生固定快照可读；U5、U6 及 U9 的入口行为通过。

### S4：定位与关闭行为

1. 先记录状态按钮、popover 实际窗口、当前屏幕与可用区域的 frame，以及打开时的 key / 焦点变化，定位问题。
2. 优先修正现有 `NSPopover` 的内容尺寸、锚定与焦点；证明原承载无法满足后才局部替换，不能仅凭问题描述直接重写成自定义面板。
3. 统一点击入口、`Esc`、外部点击与应用切换的关闭方法。必要的事件监听仅在面板显示时注册，关闭后释放，避免重复注册或泄漏。
4. 外部点击监听不吞事件；区分本面板、状态按钮和自身关联菜单 / 确认界面，避免内部操作被误关闭。不增加捕获输入内容的权限。
5. 检查展开向下增长、屏幕边缘、菜单栏自动隐藏与可用的多显示器 / 缩放场景，逐项记录实际验证范围。

完成条件：U7、U8 用原生实际操作证明；收起后读取当前快照 / GUI 会话，证明采集继续。仅 `.transient` 或单张截图不算完成。

### S5：有限本机验收与交付记录

1. 汇总 U1–U10：分别标注模型测试、固定快照原生检查和真实使用，不混写为全部通过。
2. 在日常安装迁移前，先在只读 / 隔离模式检查界面与管理入口；不为设计验收执行正式恢复、清理或重启 Codex。
3. 只读及隔离检查通过后，正常退出旧 GUI、构建并打开新 App；核对备份不变、采集恢复及运行源码指纹。不重启 Codex 或桥接，不为显示连续数据清除观测缺口。
4. 新建实施结果记录最终尺寸、语义字段、动效参数、验证环境、已通过项与仍未覆盖项，并更新本章状态。是否提交、推送按用户后续指令处理。

## 4. 验证与范围控制

不为像素间距或低影响样式编写镜像式测试。自动测试集中在主会话计数、状态优先级、覆盖 / 过期降级、格式和生命周期边界。布局、动画、菜单与外部点击通过原生交互检查。

复用[第 06 章已有结果](../06_gui_app_options_and_decisions/implementation-results.md)，只对移位的管理入口、关闭面板、退出和被修改的状态路径回归；没有新失败或接口变化时，不重新跑接入迁移、卸载、Remote 等完整实验。发现真实兼容问题时再扩大范围。

设计材料均为合成内容；不向 Git 添加日常聊天正文、真实快照、浏览器存储或运行日志。运行证据按既有约定保存在忽略目录，提交文档仅保留必要的检查结论与边界。
