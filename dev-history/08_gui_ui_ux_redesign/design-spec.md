# GUI 重设计：布局与动效

日期：2026-10-16。本文保留设计起点；原生实现已完成，实测尺寸和截图见[实施结果](implementation-results.md)，产品规则以[需求](requirements.md)为准。

## 1. 视觉方向

采用轻量原生菜单栏面板：系统材质、单层列表、细分隔线、深浅文字层级。去掉大面积装饰、重复说明和低频管理按钮。使用系统字体及适合菜单栏的小尺寸单色图标，浅 / 深色随系统变化。

面板不采用卡片套卡片，不为填满固定区域拉大间距。详情通过缩进和浅色层级区分；普通状态下，速度与当前动作优先于指标说明。

## 2. 面板布局

| 部位 | 布局与内容 |
| --- | --- |
| 顶部 | 一行：连接状态；右侧总生成速度和齿轮设置。无大图标或标题区。 |
| 异常提示 | 仅需要用户理解当前状态时出现；短文案位于顶部下方，完整原因可以展开查看。不可仅依赖悬停才知道断连。 |
| 聊天第一行 | 展开箭头、聊天标题；右侧当前聊天生成速度。标题单行省略，保留完整名称的可访问 / 悬停说明。 |
| 聊天第二行 | 项目名与当前动作；右侧当前动作耗时。项目等次要文字弱化，但保持可读对比度。 |
| 展开详情 | 本回合 Output / Reasoning、最近推理均速，再列工具和子代理；指标说明通过悬停提供。 |
| 最近完成 | 默认折叠的分组标题及数量；展开后沿用紧凑聊天行。 |
| 底部 | 简短的活动主会话数量；不重复设置、配置、恢复或退出按钮。 |

面板顶部总速与聊天行速度使用相同数值格式，但统计范围不同；总速来自核心独立流汇总，不相加当前可见行。菜单栏显示三点或锤子时，面板仍保留数值总速和具体动作，方便检查。

聊天详情是对列表的局部扩展，不替换整个面板页面。子代理归父级，折叠不影响计数和总速；多层级缩进设上限，不能把标题和指标挤出面板。未观测到的指标保持 `—`，不用空值填零。

### 尺寸起点

| 项目 | 起点 |
| --- | --- |
| 面板宽度 | 约 420 pt |
| 左右内边距 | 约 12–14 pt |
| 默认聊天行高度 | 约 58–64 pt，保证两行可读 |
| 字体 | 主要内容约 13 pt，次要内容约 11–12 pt；使用系统缩放和可访问字号能力 |
| 顶部 / 底部 | 约 36–40 pt / 28–32 pt，不为对齐旧窗口填充空白 |
| 高度 | 按实际内容计算；两条默认聊天约 240–300 pt，非固定高度 |
| 滚动上限 | 以 `min(约 520 pt, 当前可用高度的约 60%)` 为初始策略，再根据实际菜单栏 / 屏幕边界收紧 |
| 圆角 / 材质 | 优先系统 popover 外观；避免重复加一层大阴影或重度模糊 |

以上都是设计参数，不是已测得的原生窗口尺寸。空状态、异常提示、设置和恢复确认也必须受当前可用空间约束，不能强行沿用 720×520。

## 3. 菜单栏与动效

### 3.1 基准宽度与按需扩宽

基准宽度按 `999 T/s` 计算：当前 12 pt 等宽数字系统字体下，文本宽约 42.66 pt，向上取整并加左右各 2 pt 留白，得到 47 pt。此留白是本项目的布局选择，不是系统规定值。三位数以内、三点、锤子和 `—` 保持此宽度；四位数按需扩到 55 pt，五位数为 62 pt，六位数为 70 pt，回落后收窄。超过 70 pt 容量的异常值使用完整可容纳的上限提示，避免占满菜单栏。字体测量与正式绘制复用同一个字体；原生预览使用同一宽度函数。状态项变宽时刷新已打开面板的锚定区域。

常见速度保留完整整数。若异常大数超出容量，使用可在该宽度内完整显示的有界表示，例如 `>上限 T/s`，悬停显示完整整数；上限由实际字体测量确定，不能截出看似完整但数值错误的内容。小于 0.5 的有效速度可能舍入为 `0 T/s`，不能据这个显示结果改变真实生成状态。

### 3.2 空闲：沙滩待机

2026-10-17 用户选择参考 macOS 沙滩 emoji 的[单色概念稿](assets/idle-beach-concept-v1.png)试用。原生矢量绘制保留分区伞面、灰色沙洲和环绕水线，高 18 pt，居中于原有 47 pt 区域。伞面留白透明，墨色与沙洲灰度随深浅外观变化；先用静态版，空闲不启动动画时钟。仅在快照新鲜、总速完整、明确 `reason=idle`、主聊天数为 0 且存在已连接后端时显示。悬停和可访问名称为“空闲 · 暂无活动聊天”，面板仍显示数值总速。实际共用绘制器导出见[浅色](assets/idle-beach-native-light.png) / [深色](assets/idle-beach-native-dark.png)。普通界面不提供宠物切换选项。

比格小狗仅作为实验素材及开发预览保留：按用户提供的多栋 GIF 确认眯眼笑、胸前小爪、短身体和大垂耳；棕色毛发映射为灰色，白色口鼻及身体保留白色。透明 PNG 帧在 47 pt 区域内居中绘制，高 18 pt，8 帧、每帧 0.2 秒循环，减少动态效果时固定首帧。开发离屏导出继续共用此绘制器，日常快照不进入宠物模式。

### 3.3 思考：依次明暗的三点

- 三个约 4 pt 的圆点，点间距约 3 pt；固定在同一条水平线上，不位移、不缩放。
- 每轮约 1.35 秒，点之间错开约 0.18 秒，从左到右依次平滑变亮再变暗，之后短暂停留。
- 透明度在 0.65–1 之间平滑变化，避免突变闪烁；不添加 IM 聊天气泡，不播放声音。减少动态效果时三个点统一静止在 0.65 透明度。
- 保持圆点数量、总体边界与菜单栏宽度恒定。

这是借鉴 IM“正在输入”语言的自有节奏。Apple 的[官方说明](https://support.apple.com/en-us/104972)确认 iMessage 支持输入指示，但未据此核实原版逐帧运动或时序；本设计不把预览参数称为 iMessage 原始参数。

### 3.4 执行：敲击小锤子

- 使用单色、约 18 pt 的 `hammer.fill` 轮廓，水平镜像为接近 macOS 🔨 emoji 的锤头朝左上、握柄朝右下姿态。静止及减少动态效果时不额外旋转，取消早期静止位额外抬高的 25°。借用 [Xcode 的锤子意象](https://developer.apple.com/hello/january26/)，保留“正在建设”的联想。
- 以靠近握柄的位置为支点，缓慢抬起、短暂蓄力、加速敲下、小幅快速回弹，再缓慢收稳。抬起采用缓入缓出，落下采用二次加速曲线，回弹采用三次减速曲线，避免每段都套同一缓入缓出。相对静止位抬起 18°，敲下至另一侧 16°。连续两下后停顿，一轮仍为 3.3 秒，两组之间静止约 1.4 秒。
- 不采用匀速旋转；不加入彩色 App 方底、复杂蓝图、火花、音效或大幅整体摇晃。
- 不能把“等待执行 / 准备调用”当作实际敲击的依据。

HTML 预览使用 Lucide 的 `hammer` 表达动作；原生实现需选择可读的系统锤子符号或等效资源，不能把网页图标文件名当作已确认的 SF Symbol 名称。

### 3.4 动效生命周期

动画由独立的展示时钟驱动，GUI 数据继续沿用现有读取节奏。只有可靠的对应状态持续时才循环；阶段结束、暂停、断连和过期立即停止。减少动态效果时显示对应静态图形，保留“思考中 / 执行中”的可访问名称和悬停说明。

思考和执行使用 `NSView.displayLink(target:selector:)` 跟随所在屏幕同步刷新，允许 60–120 fps、优先 120 fps；系统可按显示器能力和运行策略调整实际频率。动画使用单调时间及下一帧显示时间计算姿态，不按帧数推进，因此三点 1.35 秒、锤子 3.3 秒的节奏保持不变。数字、沙滩、未知状态和减少动态效果会释放显示同步时钟；视图移出窗口或停止时同样清理。归档的小狗开发预览继续使用 5 Hz 定时器。开发诊断可记录实际同步回调和已绘制姿态数量，不把目标帧率当作实测帧率。

菜单栏常驻期间可见动画应保持轻量；面板收起不能停止当前状态展示，也不能触发后台采集重启。暂态防抖与动作动画分开处理，不强迫动画播完才更新真实状态。

## 4. 定位与关闭

以菜单栏按钮为锚点，面板内容完整位于菜单栏下方，顶部位置固定，扩展向下增长。优先由系统 popover 提供锚定、边缘避让和视觉材质；仅当本机验证证明原承载无法满足要求时，再局部调整承载方式。

外部点击、其他应用激活、重复点击入口和 `Esc` 的关闭路径统一。设置菜单与恢复确认属于关联界面，其打开与获得焦点不能触发错误关闭。确认框的内容和安全操作说明保持完整，不通过缩小字号挤进列表。

定位和收起必须使用原生窗口实际行为验证；不能依据设计图的箭头位置，或代码中已设置 `.minY` / `.transient`，声称问题已经解决。
