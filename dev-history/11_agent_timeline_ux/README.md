## 已查明的原因

本次依据用户提供的 2026-10-19 22:13:10 截图、当前源码，以及截图对应的历史轮次进行分析。

| 事实 | 结论 |
| --- | --- |
| 第 09 章 R12 明确规定子智能体汇总与展开双轨；R13 区分父级协作调用和子智能体工作 | 原先已经考虑子智能体 |
| `TimelineLane.lanes()` 为每个 child 建立 summary／header 及自己的 model／tool 行；历史查询返回各自 thread／turn 所有权 | 子智能体实际活动没有全部并入主智能体的工具轨 |
| 主智能体直接显示模型／工具行，子智能体行紧随其后；`TimelinePanelView.labels()` 删除“子智能体 · ”前缀 | 主从身份与分类轨道混在同一视觉层级 |
| 两个不同完整 ID 的前八位同为 `01a15451` | 固定前八位回退名称发生碰撞，并非同一子智能体被画了两遍 |
| 已验证的子会话 `session_meta` 含 Lorentz、Parfit、Sagan 昵称，以及结构化 agent path；索引未提取，查询回退到短 ID | 存在可用身份信息未进入 UI 的实现缺漏 |
| `collabAgentToolCall` 归入工具执行类别 | 父级协作调用目前沿用普通工具语义，需要在展示上明确区分 |

最后一项是通用分类现状，不能据此认定截图中主智能体工具轨上的每个块都是协作调用；截图对应轮次的历史查询并未返回该类型的父级阶段。

## 本轮范围

- 以“智能体组 → 模型／工具活动”组织展开面板，保留共同时间轴。
- 使用已验证的真实名称与可区分回退名，显示属于所选轮次的状态。
- 保持子智能体折叠汇总与展开双轨，并明确父级协作动作和作用对象。
- 为旧历史、旧 DTO、缺失身份、刷新、跨轮和子智能体复用建立兼容规则。
- 复用现有索引与请求内缓存，维持 `d2b0986` 消除重复历史加载的约束。

本轮不重做采集传输、SQLite schema、速度与 token 计算、菜单栏动效、配置及观察租约。独立活动窗口继续使用现有布局、原始参数／结果、分页、复制和窗口复用；允许其现有标题与辅助描述复用更准确的名称／协作语义。

## 实施状态

已完成身份读取与消歧、轮次状态、显式分组模式、全宽组标题和协作语义。实际生产改动涉及 11 个文件；相比初估增加了 collector 新 helper 的源码指纹登记。原生测得面板内容宽 420 pt，采用 22／24 pt 标题、16 pt 汇总和 20–21 pt 分类行，保留既有横向比例。

本轮通过 60 项 Python 测试、73 项 Swift 测试（包含单独启用的原生窗口用例），并完成真实历史元数据的原生只读重放。日常 App 与 collector 已载入本轮代码，工作尚未提交。此前加载故障的修复见[第 09 章记录](../09_activity_timeline/loading-fix.md)，本轮独立记录新增验证，不复用其结果冒充新 UI 验收。
