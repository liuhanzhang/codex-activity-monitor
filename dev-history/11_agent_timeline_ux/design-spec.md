# 设计说明

日期：2026-10-20。状态：已实现；实际截图与验收见[实施结果](implementation-results.md)。依据用户确认的“智能体分组、真实名称、协作语义”方向。

## 1. 用户要看懂的顺序

先认出谁在工作，再看该智能体正在生成还是执行，最后按需读取活动内容。“主智能体／子智能体”表达工作主体，“模型／工具”表达活动分类，两者必须有不同层级。

## 2. 行为规则

| 编号 | 规则 |
| --- | --- |
| A01 | 存在子智能体时，主智能体显示明确的组标题，模型／工具行属于其组内；没有子智能体时沿用紧凑双轨，避免额外空标题。 |
| A02 | 每个子智能体显示独立组标题，包含子智能体标识、可理解名称、展开状态及可确认的轮次状态。与前一个工具行之间存在清楚的分组边界。 |
| A03 | 子智能体默认折叠。折叠时显示组标题和一条紧凑活动汇总；展开后以该智能体自己的模型／工具两轨替代汇总。 |
| A04 | 同次呈现中，刷新或名称补全保持完整身份对应的展开、选中和阅读状态。换轮不因昵称相同而合并智能体。 |
| A05 | 名称只使用结构化、身份验证通过的来源；缺失时显示可区分的短 ID，不从任务正文生成角色或名称。 |
| A06 | 状态只描述所选父轮引用的子智能体活动；“本轮已结束”不等于该智能体已关闭或以后不能复用。证据不足显示“状态未知／部分观测”。 |
| A07 | 汇总仅画可确认活动片段并保留空档；颜色保留类别含义，不用首次出现至最后出现的一条满块表示持续工作。 |
| A08 | 派发、发送消息、等待、关闭等父级调用显示协作语义和可确认作用对象；调用结束不结束子智能体组。 |
| A09 | 协作调用保留父级原始所有权与来源区间，子智能体活动保留自己的所有权与来源区间，不复制为两份活动。 |
| A10 | 命名、分组和新增标题不改变时间比例、活动水平坐标、短线宽度或普通工具的命中规则。 |
| A11 | 多层关系使用已有明确 parent 身份组织；最多两级视觉缩进，更深层通过辅助描述说明。缺失或冲突关系显示关联不完整，不靠名称或位置强行挂靠。 |
| A12 | 独立活动窗口的轨道排布沿用现状，现有文字可使用相同名称与协作语义；不新增单聊页面或智能体控制入口。 |

## 3. 命名与状态

名称优先级：有明确来源、且不是当前短 ID 回退值的线程／任务名称 → 已验证昵称 → 结构化 agent path 的末段 → 可区分短 ID。agent path 末段只是来源提供的标识，不自动翻译为臆测的中文职责。

同名智能体在标题中补充短 ID 区分。短 ID 建议从末六位起，在该 bundle 内存在冲突时扩展；昵称或短 ID 从不成为数据关联键。完整 ID、完整名称和来源通过悬停／现有详情辅助描述访问。

截图中的三个对象至少应能显示 Lorentz、Parfit、Sagan。已有结构化名称若更合适，可优先显示；任务路径放在辅助描述，避免一行塞入名称、路径、角色和完整 ID。

| 状态文字 | 证据要求 |
| --- | --- |
| 本轮活动中 | 所选父轮明确引用的 child 活动仍活跃，且没有断连／过期等证据使该结论失效 |
| 本轮等待中 | 同一引用范围内有明确等待状态；不能由“暂时没有 delta”推断 |
| 本轮已结束 | 所引用轮次有明确终止记录，且不存在仍活跃／等待或未解决的生命周期记录；失败／中止按来源补充说明 |
| 状态未知／部分观测 | 缺少关联范围、结束依据，或观察覆盖不足 |

原始生命周期与活动质量信息继续保留。多轮复用时，不用该 child 在别的父轮中的当前状态替代本轮状态。

## 4. 紧凑面板排布

面板继续约 420 pt。采用全宽智能体标题行，使“子智能体 · 名称”和状态不挤在原有 78 pt 左侧标签列。

| 行 | 内容 | 建议高度 |
| --- | --- | --- |
| 共用时间轴 | 所选轮次的同一时间刻度 | 沿用现状 |
| 智能体标题 | 主／子身份、名称、子智能体展开箭头、右侧状态 | 约 20–22 pt |
| 折叠子智能体汇总 | 固定左侧简短“活动”标签，右侧真实活动片段 | 约 14–16 pt |
| 展开后的模型／工具 | 固定类别标签、右侧来源时间块 | 约 20–21 pt／行 |

标题行占自己的垂直空间，时间线绘图区在该行留空；名称不会覆盖活动条，也不随横向滚动移走。所有组共享一个水平滚动位置，维持原有 291 pt 左右绘图宽度与 30／60 秒比例。组间用轻分隔或小间距区分，不增加重色卡片。

相比当前单行 summary，折叠子智能体预计增加约 10–15 pt；有子智能体时再增加一个主组标题。通过列表原有纵向滚动承载，原生检查确认三子智能体场景不会出现大面积留白或逐组独立横向滚动。

长名称截断，状态保持可读；完整名称通过 help 和辅助功能名称提供。展开按钮的可点击范围覆盖组标题，可聚焦、可用键盘操作，辅助功能同时读出身份、名称、状态和展开状态。不能仅靠颜色区分主／子或运行／未知。

## 5. 协作调用

父级工具轨可以继续承载协作调用，使用系统协作符号和明确文案，例如“派发 · Lorentz”“等待 · 3 个子智能体”。多对象名称在辅助描述列出，不把所有名称挤进时间块。

现有活动时间块仍优先表达时间；短块不强塞文字。悬停、键盘选择、可访问名称和已有详情标题提供动作与对象。点击继续打开已有原始参数／结果详情，完整目标 ID 保留。识别不了具体动作时显示“协作调用”；只有明确协议身份的调用才使用这一展示。

不新增永久第三条协作轨，不把父级等待区间复制为每个子智能体的工作区间，不为识别协作而解析任意代码字符串。

## 6. 与前章的关系

本章细化第 09 章 R12／R13 的身份表达和分组方式，折叠汇总从“同一行中塞入名字与所有内容”调整为紧凑标题加汇总。第 10 章的聊天默认展开、统计归属、模型说明和原生面板管理继续沿用。
