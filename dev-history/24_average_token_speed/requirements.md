# 平均速度需求与决策

日期：2026-10-28。状态：产品口径已确认并实施，验证与剩余边界见[实施结果](implementation.md)。实验依据见[算法对比](experiments.md)，技术细化见[技术方案](technical-design.md)。

## 已确认的统计范围

平均速度按所选轮次独立计算。一轮指一次用户输入开始到该轮结束，其间可以有多次模型请求、工具调用和多条 usage。新轮次重新累计；切换历史轮次时展示那一轮自己的平均值。

各聊天、各轮次保持独立。选中父聊天时，平均速度的统计对象是该聊天的所选轮次，不因为时间线同时展示子智能体而自动合并子智能体用量。

## 已确认的计算口径

1. token 数来自 Codex JSONL 的官方 usage，输出包含推理用量，不将 reasoning tokens 再加一次。
2. 使用请求时间窗方法，不再将 Reasoning、AgentMessage 等 item 的持续时间之和作为分母。
3. 平均值为有有效计时的输出 tokens 总和除以同一批请求的耗时总和，不直接平均各次请求的速度。
4. 每收到一条新的、可归属且有有效计时的 usage 就更新，不等待整轮结束。
5. 相邻 usage 之间保留上次结果，不把仍在流逝的时间单独加入分母。
6. 轮次结束后保留该轮最终结果，并可从仍可读取的 JSONL 重算。

这是请求级速度估算。推导出的时间窗可能包含首 token 等待、网络、排队或其他无法拆分的时间。稳定性实验不把它变成服务端纯生成速度；平均值也不承诺从第一条 usage 起就恒定。

## 已确认的界面位置

位置是聊天展开详情最底部现有统计行：

```text
左侧：输出 Token 数、含推理用量          右侧：平均速度    统计说明
```

右侧可采用 `平均速度 39.4 token/s` 的形式，具体数字格式与现有速度格式保持一致。首次没有有效样本时显示 `平均速度 —`。已知零和未知值必须区分。

现有统计说明按钮继续承载口径说明。平均速度的说明应包括：所选轮次、官方输出包含推理、请求级时间估算，以及必要时的部分覆盖提示。常态统计行保持紧凑，不放实现字段、调试状态或长解释。

平均速度跟随轮次选择，不借用当前轮数据填充历史轮次。在轮次切换期间也不短暂显示另一轮的值。

现有菜单栏和聊天列表的实时速度继续承担一秒接收窗口指标；本需求只在详情统计区增加平均速度。

## 数据不完整时的预期

没有有效请求计时时显示 `—`。部分请求计时不可用时，仅有匹配 token 和耗时的样本可以参与速度计算，并在统计说明中体现部分覆盖；左侧总输出用量仍遵循现有官方用量口径。

重复 usage 不重复计数，无法确认的归属不靠时间相近或聊天名称猜测。数据不足时不将耗时按零补齐，也不靠隐藏高低速样本制造稳定曲线。

## 本阶段的工程默认

以下是技术方案的默认处理，不是新增的用户产品决策：

- 请求级长窗口按合法边界保留；没有证据时不按固定秒数自动截断。长窗口的诊断和反例保留在实验记录中。
- 优先覆盖本次已验证的 `token_usage_record` 记录路径；旧格式不足以配对时显示未知。Token Monitor 的旧格式回退算法单独记录，是否扩大支持范围以兼容验证为依据。
- 新功能通过现有 JSONL 读取和详情查询链路接入，不向 Codex 发起额外模型请求。
- 产品实现前先完成本章文档。后续产品集成、运行验收和提交分别记录，不将本章实验写成产品完成状态。

## 完成标准

用户能在进行中的轮次看到随 usage 更新的累计平均速度，在两条 usage 之间看到保留值，在轮次结束后查看最终值；切换轮次后数值有明确归属。详情底部左右布局、中英文和无障碍信息正确，实时速度的含义保持独立。
