# 平均速度实现计划

日期：2026-10-28。状态：产品实施、定向验证、隔离原生预览及真实 JSONL 增量接入核对完成，实际结果见[实施结果](implementation.md)。日常实例已按后续指令更新，见[部署记录](deployment.md)。下文保留原实施顺序和完成条件。

## 实施顺序

### 1 固定计量规则和接口

- 按[需求](requirements.md)固定每轮独立、usage 驱动、详情底部左右布局。
- 以[技术方案](technical-design.md)为依据确定账本对象、接口字段和缓存上限。
- 将正常 usage/count 配对、重复 count、异步工具结果、跨轮边界和预览冲突整理为小型合成记录；不把真实聊天当作公共 fixture。

完成条件：公式、数据归属、状态转换及未知值行为能对应到明确的记录和期望结果。接口细节属于实施细化，不重开已经确认的产品范围。

### 2 实现 Python 请求账本

- 新增独立计时模块，存储数值、生成身份和必要诊断，不保留正文。
- 实现每条 usage 的窗口预览、响应去重、token 与时长同步累计。
- 实现后续 token_count 确认与冲突撤销，保留合法长窗口。
- 处理缺字段、错误时钟、缺失确认和不同轮次的隔离，避免跨请求借用旧起点。

完成条件：第一条有效 usage 就能计算；没有新 usage 时值不变；重复记录幂等；无法配对的 token 与时长均不进入速度集合。已知零、未知和部分覆盖可区分。

### 3 接入历史目录和查询

- 在 HistoryDirectory 原增量扫描中维护账本，不增加第二个全量日志扫描器。
- 将账本纳入源文件 reset、缓存版本和 retained_bytes 权重。
- 在 TimelineQuery.bundle 中提供所选根线程、所选轮次的可选平均速度投影。
- 校验分段追加、未完成末行、文件替换、截断、同大小改写、缓存淘汰后的重算。

完成条件：一遍读取和分段读取得到相同的有效样本；查询历史轮次不混入当前轮次或子智能体；重启从 JSONL 重建后结果一致。

### 4 接入 Swift 详情统计

- 扩充 TimelineBundle 的可选 DTO 和 PanelStatistics 的轮次匹配。
- 在 ChatDetailsView 底部统计行右侧加入平均速度，保留左侧输出、推理用量和说明按钮。
- 补齐中英文、未知值、部分覆盖说明与无障碍标识。
- 沿用现有详情轮询；数值刷新不推动实时速度，不额外维护 Swift 计量账本。

完成条件：新字段缺失时能兼容旧响应；切轮期间不闪现其他轮均值；轮次结束后保留结果；中英文和窄窗口布局可读。

### 5 定向验证和原生验收

先运行新增逻辑及其相邻边界的测试，必要时复用现有全量测试证据，不为文档或低风险布局变化重复运行无关实验。

| 验证层 | 关键场景 | 证据边界 |
| --- | --- | --- |
| 请求账本 | 首条 usage、零输出、重复响应、冲突、错误起止、缺失确认 | 证明受测记录下的计算与降级 |
| 并发和边界 | 模型输出后到达工具结果、重复 count、旧轮晚到记录、父子线程 | 证明归属和起点不会被不相关事件移动 |
| 历史读取 | 分块追加、半行、替换、截断、缓存淘汰和重建 | 证明源版本与平均值一致 |
| 查询与解码 | selected turn、缺字段、旧响应、部分覆盖、离线历史 | 证明只展示同一轮的合法数据 |
| 真实数值回放 | 与本章 285 个样本点逐点对照 | 证明已验证格式的兼容，不证明纯解码速度 |
| 原生预览 | 首条前 `—`、进行中更新、完成后保留、轮次切换、中英文和窄布局 | 证明预览中的可读性和交互 |
| 自然使用 | 开始一轮并多次调用工具，核对 JSONL 新 usage 与 GUI 更新 | 证明真实接入和实际刷新，不等于长期可靠性或发行验收 |

原生验证使用隔离 Preview App、合成场景或用户明确授权的自然回合。日常 collector 和 Desktop 切换、重启与新模型用量不作为普通单元测试的隐含步骤。
