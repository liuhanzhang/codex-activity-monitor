# 需求与验收标准

日期：2026-10-28。基线：`6c39325`。状态：已实现；验收证据与未验证范围见[实现结果](implementation-results.md)。技术细节见[技术方案](technical-design.md)，执行顺序见[实现计划](implementation-plan.md)。

## 1. 目标与范围

用户能在一个常规 macOS 设置窗口中管理 Monitor 和 Agent 接入，并回答三个问题：配置是否已经写入、当前进程是否已经使用配置、出现问题时哪里受影响以及如何处理。

| 编号 | 需求 |
| --- | --- |
| R01 | 主面板齿轮直接打开独立设置窗口，重复打开聚焦同一窗口。 |
| R02 | 采用原生侧边栏和内容页，提供通用、运行状态、日志三个页面；移除顶栏折叠按钮，保留原生拖动隐藏行为。 |
| R03 | 通用按模块展示应用设置、Agent 接入，并保留独立的清理与卸载入口。 |
| R04 | Codex 接入使用开关；配置状态、运行状态、操作失败和重启要求分别呈现。 |
| R05 | 首次启动继续自动配置接入；已有状态及用户主动关闭的选择跨启动保留。 |
| R06 | 运行状态集中展示已检测项目的健康、降级、异常、未启用或无法确认状态。 |
| R07 | 日志记录发生、重试和恢复过程，支持筛选、搜索、复制及打开目录。 |
| R08 | 诊断和日志有资源上限，不阻塞 Codex 字节转发、采集主循环或 GUI 主线程。 |
| R09 | 主面板背景交由原生容器管理，保持现有会话列表、时间线和测量语义。 |
| R10 | 新增界面及结构化提示完整支持简体中文、英文和键盘操作。 |

本轮不实现其他 Agent 的接入、不重做主面板列表控件、不扩大监控到普通终端 CLI，不把所有业务失败归为 Monitor 故障。

## 2. 设置窗口

| 页面 | 内容与操作 |
| --- | --- |
| 通用 | 应用设置：语言、登录时启动；Agent 接入：Codex 开关与状态；维护：清理本机数据并退出，用于卸载。 |
| 运行状态 | Monitor 与已接入 Agent 的组件状态、影响说明、检查新鲜度、当前问题及对应处理入口。 |
| 日志 | 时间、级别、来源、摘要；来源和级别筛选、搜索、详情、复制、打开日志目录。 |

窗口是现有菜单栏应用的一部分。关闭窗口不退出 Monitor、不恢复配置、不释放正在使用的观察租约；再次打开不创建第二个采集器。应用保持现有菜单栏运行形态。

工程默认：首次打开设置显示通用页，当前进程中记住上次页面；窗口位置和大小可恢复，允许调整大小。普通设置保持紧凑，日志页利用可用空间。退出 Monitor 的入口和 Command-Q 保留，并经过现有退出流程；Command-W 关闭设置窗口。

状态不能只靠颜色表达。开关、错误说明和跳转日志的操作具备可读名称与键盘焦点。切换语言即时作用于已打开窗口，日志中的原始系统错误详情不强行翻译。

## 3. Codex 接入

### 3.1 开关语义

- 开启：调用现有配置流程，保存原配置备份、写入接入配置并启动或恢复观察；分别报告各步骤结果。
- 关闭：调用不清理数据的恢复流程，停止观察并恢复仍由 Monitor 管理的配置值；保留后续用户修改。
- 开关表示接入配置是否启用，不等同于采集器存活、Codex 已连接或全部会话已经覆盖。
- 操作期间显示进度并禁止重复切换。失败或超时后重新查询实际状态，不能直接反转开关，也不能凭命令返回前的画面认定操作成功。
- 状态无法核实时明确显示未知及上次确认结果；只提供与已知状态相符的重试或继续恢复操作。
- 关闭开关不触发卸载确认或数据删除。清理与卸载为独立操作，保留确认和等待依赖退出的流程。

### 3.2 对用户显示的结果

| 情况 | 反馈要求 |
| --- | --- |
| 配置进行中 | 正在开启接入，展示操作进度。 |
| 配置完成，Codex 未运行 | 已配置；下次打开 Codex 后接入。不要求重启未运行的应用。 |
| 有证据表明当前进程仍持有旧配置或旧 bridge | 已配置，需完全退出并重新打开 Codex；仍正常工作的已接入连接另行说明。 |
| 当前 bridge 的配置、能力和实时连接已经确认 | 已生效，范围限定为已确认的本机接入。 |
| 配置完成，但采集器启动或通信失败 | 保留已配置事实，另报运行失败、影响和重试入口。 |
| 配置失败且确认回滚完成 | 开启失败，保持未启用；显示原因。 |
| 配置或回滚只完成一部分 | 操作未完成／状态待确认；显示已知结果及恢复操作，不伪装成完全开启或关闭。 |
| 恢复配置完成，旧进程仍存在 | 接入已关闭、配置已恢复；提示重开 Codex 后使用恢复后的配置，必要时等待退出完成清理。 |
| 配置恢复且相关依赖退出已经确认 | 已关闭、恢复完成。 |
| 无法检查进程或配置 | 暂时无法确认，并说明检查失败；不能据此断言必须重启或已经恢复完成。 |

没有聊天、没有 token 或短时间没有源事件，均不能单独证明接入失败或必须重启。仅有配置记录也不能证明运行中已经生效。

### 3.3 跨启动与配置归属

首次启动的自动配置与手动开启走相同状态及日志流程。原有已配置安装允许重新应用登录会话环境，但不能因此重建原备份、虚构新的配置代次或要求每次重启 Codex。

主动关闭后，再次打开 Monitor 保持关闭；待恢复、待清理或失败状态继续原有恢复工作，不能自动重新开启。登录时启动设置与 Agent 接入开关独立，沿用现有偏好和系统审批提示。

本轮不强制退出 Codex、不自动重启 Codex、不删除 Codex 对话。重启提示明确指向 Codex，提醒用户在任务结束后操作。

## 4. 运行诊断

运行状态描述有证据的故障与能力范围。页面显示的是“已检测项目的状态”，不能宣称已发现或排除了所有程序错误。

| 检查项目 | 首版覆盖 |
| --- | --- |
| 接入管理 | 配置读写、回读验证、恢复／回滚结果、外部配置变化、检查失败及重启证据。 |
| GUI 与采集器 | 连接失败、心跳超时、采集主循环停滞、实例更换、重连与恢复。 |
| bridge 与采集 | 断连、已检测到的丢包、解析错误、协议能力不匹配、观测缺口。 |
| Token 计数 | 已有计数失败、超时与预算信号，说明影响的是速度／计数能力。 |
| 历史与时间线 | 已有读取失败、查询不可用、元数据写入失败及队列丢弃信号。 |
| 日志自身 | 写入或轮转失败、队列丢弃、日志可用范围；提供不依赖成功写日志的界面提示。 |
| 上次结束情况 | 下次启动发现未正常结束时给出谨慎提示；不能仅凭标记断言崩溃原因。 |

规则要求：

1. 未启用、等待 Codex 启动、正常空闲、主动退出及正常取消不报故障。等待重启属于待处理状态。
2. 操作进行中、重连退避期和系统睡眠后的恢复期应有对应状态，不立即渲染为持续严重故障；已有实时数据失效规则仍即时生效。
3. 区分全部不可用和局部降级。例如时间线存储失败时，不能把仍有新鲜证据的实时监测一并判为失效。
4. 观测缺口表示捕获连续性不足，不证明 Codex 任务失败；工具执行失败也不自动构成 Monitor 异常。
5. 当前告警由当前失败及恢复证据决定；累计计数、历史日志、旧实例状态不能永久维持红色告警。
6. 实例、来源、影响范围和最近检查结果可追溯；陈旧数据应标注为上次状态或未知。

## 5. 日志

默认记录运行诊断，包括启动／停止、配置／恢复、失败／重试／恢复、显著的丢弃或预算变化。正常心跳和每个 token 不逐条写入日志；同类重复错误合并并保留首次时间、最近时间和发生次数。

日志默认在本地保存。普通关闭接入保留诊断记录；完整卸载才按归属规则清理。日志不默认保存对话正文、工具参数／结果、环境原值、配置备份、认证信息和租约 secret。系统错误上下文仅保留允许的字段，日志仍应视作用户本地数据。

界面按需读取有界的日志窗口；明确表示仅加载了部分记录、保留期已淘汰、记录被截断或丢弃。复制只针对用户选中的记录；打开目录不自动分享文件。

日志不可写时，实时监测与原始 Codex 转发应继续；界面保留内存中的日志故障提示。记录能力受限时不能递归打印同一个日志错误。

## 6. 原生外观与兼容性

设置窗口使用原生导航、表单和控件，交由运行系统提供对应外观。当前最低部署目标保持 macOS 14，使用新版 SDK 构建；macOS 26+ 的系统效果和 macOS 14／15 的原生外观分别验证，不为材质新增版本分支。

主面板先仅移除 `DashboardView` 的 `.background(.regularMaterial)`，由现有 `NSPopover` 提供背景。会话选择态、时间线绘制及布局不在本轮重做。删除一行是最小实现步骤，不能代替运行验证；若 hosting 层仍覆盖系统背景，应定位该覆盖并做最小修正。

验证浅色、深色、减少透明度及必要的键盘交互。系统效果受 SDK、运行版本和用户设置影响，不能保证每种环境都呈现同样强度的透明效果。

## 7. 验收场景

| 编号 | 场景与通过条件 |
| --- | --- |
| A01 | 齿轮打开同一设置窗口；关窗不停止观察，重复打开不重复启动后台。 |
| A02 | 通用页分组、语言即时切换、登录审批、退出与卸载入口均可用。 |
| A03 | 隔离的新安装自动接入，处理结果在窗口可见；已有关闭安装重开保持关闭。 |
| A04 | 开启、关闭、再次开启保留正确原备份及用户后改配置，未改值／空值／未设置可正确恢复。 |
| A05 | 配置成功但采集器失败、命令超时但配置已落地、部分恢复失败，均显示准确组合状态。 |
| A06 | Codex 未运行、旧进程仍在、新 bridge 已接入、进程不可见、部分连接已接入时，提示与证据一致。 |
| A07 | 心跳丢失或主循环停滞影响实时健康；旧数据和历史日志不被当成新健康证明。 |
| A08 | 注入丢包、解析错误、计数失败、历史读取失败、元数据写入失败，告警范围准确；恢复后有对应状态和日志。 |
| A09 | 正常空闲、主动停止、取消、等待重启和启动宽限不产生误报；累计错误不会永久维持告警。 |
| A10 | 日志筛选、搜索、详情和复制正确；队列／文件预算、并发轮转、不可写及异常中断不阻塞主路径。 |
| A11 | 完整卸载清理新增的归属明确的诊断文件；普通关闭保留日志，未知文件不被扩大删除。 |
| A12 | 原生设置与弹出面板在可取得的目标系统验证；未取得的版本明确记录未验证，不以编译替代。 |

故障注入和原生预览优先使用合成数据、临时目录、注入管理服务及一次性 profile。日常安装切换和真实 Codex 完整回合的结果独立记录，不从本轮文档或单元测试推断通过。
