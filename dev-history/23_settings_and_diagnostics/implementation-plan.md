## P1：实现独立日志基础

1. 增加结构化事件、允许字段、中英文消息和有界 writer；GUI、管理命令、collector、bridge 使用同一事件语义。
2. 实现按固定组件分类的 JSONL 追加、跨进程锁、轮转、保留期、容量维护和丢弃统计，磁盘操作全部离开主路径。
3. 处理 `collector.log` 的存量兼容与运行期间容量上限，避免保留一个可无限增长的旁路。选择的输出捕获方案须验证退出、慢盘及子进程输出背压。
4. 增加独立 Swift 日志 reader／client，支持完整行分帧、偏移、轮转、损坏行、可取消搜索和有界结果。
5. 接入普通恢复保留、完整卸载清理的归属规则，测试临时 profile 的目录隔离。

定向验证：多进程并发追加和轮转无交错／重复读取；最后半行、超长行和坏 UTF-8 可降级；锁竞争、队列满、磁盘不可写和 writer 阻塞不使主路径等待；secret／环境原值／正文不进入日志。用独立故障进程模拟阻塞，测试自身也有截止时间。

通过条件：collector 不存在时仍可记录 GUI／管理失败并读取日志；日志成本和最坏资源占用有边界，记录丢失可见，关键流程不依赖落盘成功。

## P2：补齐接入状态与生效检查

1. 新增有界的只读配置／进程检查，保留现有 receipt、备份、事务锁和回读机制；输出分开的配置、操作、运行和重启状态。
2. 配置代次仅在规范化配置变化时更新。launcher、bridge 注册和生命周期事件带固定启动证据，核对实际有效配置；旧 bridge 缺字段按兼容未知处理。
3. 组合配置、进程身份和新鲜握手，处理新旧 bridge 并存、未运行、等待连接和检查不可用；不能以无聊天推断失败。
4. 统一手动与首次自动开启流程；保留恢复后关闭状态，避免每次 bootstrap 改代次或再次开启。
5. 管理超时、取消、回滚或部分恢复后查询实际状态，控制操作代次，避免旧结果覆盖新状态；登录注册错误独立呈现。
6. 正常恢复与卸载分开：关闭开关使用 `purge=false`，独立维护入口使用确认后的 `purge=true`。

定向验证：首次自动接入；重开关闭安装；重复 configure 不产生假重启；原值／空值／未设置和用户后改值；配置已写入但启动失败；超时后真实配置已改变；部分恢复及重试；旧代次、未知进程、已接入与旧连接混合。全部采用注入环境和 disposable profile。

通过条件：需求 A03–A06 对应状态可由事实解释；配置代次证明的是运行上下文而不是最新文件内容，原有可恢复性未退化。

## P3：实现健康投影与故障留痕

1. 从已有心跳、IPC、tokenizer、历史、存储和资源统计取得事实，补缺少的当前错误及最后成功信息；按范围构建有界摘要。
2. 为现有吞掉原因的管理刷新、连接重试和查询路径保留结构化原因，继续现有重试策略；补 Python 顶层／线程意外异常的尽力记录，验证其失败也不会递归处理或无限等待。
3. 实现问题首次发生、重复合并、恢复、实例更换和陈旧结果规则。累计计数不得直接等同于当前告警。
4. GUI 合并后台摘要和自身连接／管理错误；collector 失联时显示未知或不可用，不使用旧文件补成健康。
5. 加入预期状态：接入关闭、Codex 未运行、启动／恢复中、主动停止、取消、重连及睡眠恢复。可操作告警宽限不延长实时指标新鲜度。
6. 实现 GUI 未正常结束标记和下次提示，措辞保留原因不明；日志自身失败通过内存信号呈现，避免递归。

定向验证：心跳 worker 活着但 collector 主循环停滞；单项存储失败而实时链正常；恢复后累计数非零；没有新写入时尚未验证恢复；正常空闲；故障实例替换；只有历史 gap 的聊天不被解释为 Codex 失败。记录状态转换而非仅检查字典字段。

通过条件：A07–A09 有行为证据；异常范围、持续原因、恢复依据和历史日志对应一致。

## P4：接入独立设置窗口

1. 在 `AppDelegate` 增加单实例窗口 controller，将齿轮菜单替换为打开窗口的按钮，复用现有 `DashboardStore`。
2. 实现侧边栏和三个页面；通用包含应用、Agent 接入、维护模块。Codex 行包含开关、状态、重启／失败说明和重试。
3. 将语言、登录启动和系统审批入口接入共享状态；保留退出、Command-Q／Command-W 和卸载确认；恢复等待过程在窗口可见。
4. 运行状态按组件显示结果、影响和最近检查，支持跳转相关日志；日志页接入分页／增量读取、搜索、筛选、详情和复制。
5. 管理操作期间禁用冲突动作；关闭窗口取消页面读取，应用级任务继续；再次打开不取得新租约或重新配置。
6. 增加稳定的无障碍标识和中文／英文资源，复用已有词库导出方式。

定向验证：重复打开同一窗口、主面板关闭不关设置、设置关窗不停止观察；未启用时也可开诊断；中英文长文案、键盘焦点、开关读屏和登录审批；日志筛选不因状态刷新重置。

通过条件：A01–A02 和窗口部分 A10 满足，UI 没有复制管理或健康判定逻辑，未来 Agent 只需增加接入区域与来源。

## 3. 失败与回退

- UI 出错时保留接入记录及后端管理入口，不删除原备份。新健康投影不得写回活动状态来掩盖错误。
- 配置检查失败转为未知并保留上次确认结果，不能自动重新配置或恢复用户环境；配置事务继续由原管理流程控制。
- 日志不可写、压力超限或格式损坏时降级并报告可用范围，实时监测和 Codex 转发继续遵守原有边界。
- 新旧组件混用时缺失字段降级，不为刷新界面强制结束驻留 Codex。需要新版 bridge 才能完成的验收明确标为待重启。
- 回退代码与恢复系统配置是两件事；按已确认的实际安装状态处理，不通过覆盖 receipt、删除日志或清除错误计数制造成功状态。
