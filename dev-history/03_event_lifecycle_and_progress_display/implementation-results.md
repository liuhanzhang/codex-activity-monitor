## 3. 生命周期与查证结论

请求按 backend + requestId 单独记录；自动审核按 reviewId 单独记录，并用 startedAtMs 去重 strict review 占位。它们不会覆盖原工具。带 threadId 的 resolved、客户端回复、重复或乱序结束会清理对应请求；审核通过不会变成进程启动证明。

命令启动采用 `source=unifiedExecStartup/unifiedExecInteraction` 与 processId，或明确的命令输出 / 终端交互。当前源码中 unified exec 的 Begin 在进程创建后发出；app-server 可能在审批前已登记同一 item，抑制后续 canonical started。因此缺少实际启动证据的静默命令仍只能显示“处理中”。依据见 [进程管理器](/Users/bytedance/playground/codex/codex-rs/core/src/unified_exec/process_manager.rs:548) 和 [app-server 转换](/Users/bytedance/playground/codex/codex-rs/app-server/src/bespoke_event_handling.rs:1074)。

Code Mode 外层 cell 与嵌套工具的精确生命周期关联仍未取得。新模型输出只能关闭旧“准备上下文”为未知，不能把外层 cell 或后台工具标记为完成。functionCallOutput 的实际来源不是所有工具的通用返回通知，也不能批量关闭 exec。完成 trace 的 execution_started 属于完成后事实；本轮没有扩大 trace 订阅。

流的 completed / failed / incomplete 只清理明确关联的流，不按后端最近活跃聊天猜归属。错误结束失效生成，按 willRetry 区分重试与失败。idle 停止旧前台状态但不推断成功；后台命令等待自身结束。迟到的 turn started 不能重新打开已结束回合。

重连缓存保留必要终态，并清理旧请求、审核及前台活动。观测缺口使旧主状态暂不可用；新进度可恢复动作，但旧的不完整流不恢复测速。缺口后明确从头观察到的新流可独立计速。模型编码变化重算旧文本时重建速度基线，避免把历史文本计成新生成。

条件事件只影响明确关联的工作：同步 turn hook、已知工具服务器依赖、当前聊天环境、showBufferingUi 和目标状态。异步 hook、全局登录完成或无关联警告不暂停 / 恢复任意聊天。长期目标 active 不反造正在执行；目标仍有效时使用“本轮完成”。

## 4. 验证结果

### 离线与回放

**81 项回归测试通过**。覆盖 87 个消费边界、19 类 item 生命周期、11 类请求取舍，以及实际过滤—引擎—渲染路径。语义检查包括并行阻塞、多审核、strict 去重、仅完成通知、计划最终文本变化、摘要速度、父子镜像、重试、模型切换、idle、迟到事件、观测缺口及桥接正常转发。

回放 4 份既有捕获和本次 2 份隔离实测协议。既有完整模型流捕获的 12 条结束流，字符 / token 计数与最终文本匹配，缓冲释放；所有回放的未关联积压为 0。快照及渲染没有暴露测试中的私有参数、审核理由、stdout 或结果正文。入口为 [语义回归](../../tests/test_progress_semantics.py)、[捕获回放](../../tests/verify_captures.py)；日志和捕获哈希见验证 JSON。

### 当前安装版隔离实测

使用 CLI `0.162.0-alpha.17.2`，从已有隔离 CODEX_HOME 启动测试自己拥有的后端，模型为 `gpt-6-luna`。没有向日常聊天提交测试请求；隔离 config.toml 哈希保持不变。

| 场景 | 结果 |
| --- | --- |
| 回答与参数速度 | 实际有非零单列速度与参数速度，结束后清空 |
| 命令 / 静默命令 | 实际 process 身份及 started / completed，无输出期间仍显示运行 |
| 结构化计划 | 观察到 2 次 turn/plan/updated，快照带步骤状态 |
| 审批结束 | 明确拒绝一条无副作用命令；观察到请求、resolved、declined 和回合结束 |
| 消费者重连 | 命令运行期间停止 / 启动隔离采集器，重新接入并标记缺口 |
| 同聊天两条命令重叠 | 最终后台 probe 的 47 个采样点包含至少两项实际活动 |
| 回合结束后后台继续 | 46 个采样点仍有后台活动；两条命令随后均完成，exitCode=0，最终活动数为 0 |

证据在 `.local/improve/live-1012b/` 和 `.local/improve/bg-1012b/`。product_smoke 原始结果仍是 `passed=false`：模型把 A 中要求并行的命令顺序执行，未满足该脚本的同聊天并行断言。其他核心断言通过；并行与跨回合结束由独立后台 probe 补齐，后者 `passed=true`。没有重标第一份结果。

第一轮 `.local/improve/live-1012a/` 的命令被测试执行环境拦截，计划工具也未启用，不能作为执行验收。第二轮仅以进程级参数启用计划工具，在允许实际子进程启动的执行环境完成验证，没有改写隔离配置。

隔离验证阶段未逐项触发自动审核、压缩、父子镜像和条件长尾。本轮日常运行补充观察到自动审核开始并结束为 approved，以及同步内部处理的快照事实；压缩、父子镜像与其余长尾仍只有源码 / 离线依据，不标为逐项真实运行验收。
