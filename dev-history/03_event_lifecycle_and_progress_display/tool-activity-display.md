# 工具活动名称与命令显示

本文记录已完成的工具名 / 命令预览改动及其验证。默认界面的进一步简化方案见 [事件消费与展示决策](event-display-decisions.md)，目前待 review，尚未实现；本文中的现有文案与指标不代表新的最终产品取舍。

## 需求

- `exec` 是 Code Mode 的外层调用；看板应解释这个名称，并尽早显示生成代码中可见的具体工具名称。
- 参数生成阶段显示已收到的工具名。只有收到 `tools.<名称>(` 的直接调用语法后，才显示该内部名称；未出现名称、动态调用或无法识别时保留外层名称。
- 命令执行活动显示实际命令首行摘要，去掉可识别的 `bash/zsh/sh -c` 包装，列表不能固定在 40 字处截断。
- 名称展示不改变执行证据门槛。参数生成完成仍可处于“工具准备 / 执行未确认”；执行状态继续依据真实工具生命周期、进程与输出事件。
- 默认快照继续不保存正文、完整参数或 JavaScript；仅保存工具名称与现有边界内的命令摘要（最多 160 字）。
- 参数生成阶段也显示命令摘要：识别直接 `exec_command` 调用的 `cmd` 字符串，以及直接函数调用的 JSON 参数。已收到的前缀以“拟执行”标注，不完整时加 `…`；命令通过变量或动态表达式构造时，不求值。

## 实现计划

1. 保留上游工具 namespace，并在状态引擎中独立保存外层工具身份，避免展示名称变化影响生命周期判断。
2. 对已有参数内存缓冲做有界、保守的线性扫描，跳过字符串、注释和正则字面量。只识别前 64K 字符内的直接调用，不执行代码；每次指标刷新最多解析一次。
3. 统一命令摘要与工具标签，在参数完成项中补齐名称，在真实命令事件中更新命令摘要。
4. 调整终端列表和活动详情；验证分块参数、并行工具、工具完成后关闭、命令包装、名称缺失与敏感正文不落盘，并回放既有实测捕获。
5. 在线性扫描中定位命令工具首个对象参数的命令字段，解码字符串前缀（包含跨 delta 的转义），将最多六条、每条 160 字的预览与真实执行事件中的命令分开保存和展示；增加增量、多个命令、动态字段及非命令参数不泄漏的验证。

## 显示示例与边界

| 阶段 | 示例 |
| --- | --- |
| 外层名称已收到 | `生成工具参数 · exec（Code Mode）` |
| 内部调用名已收到 | `生成工具参数 · exec → exec_command, mcp__web__run` |
| 命令字符串正在生成 | `生成工具参数 · exec → exec_command · 拟执行: rg --fi…` |
| 命令摘要已生成 | `生成工具参数 · exec → exec_command · 拟执行: rg --files src` |
| 参数生成完但执行证据不足 | `工具准备 / 执行未确认 · exec → exec_command` |
| 已收到命令执行证据 | `执行工具 · exec_command · rg --files src` |

生成代码中的名称表示计划调用的工具，不证明代码分支已执行。字符串、注释与模板字符串内的名称不会用于显示；复杂模板插值之后的调用可能无法识别，动态属性、变量间接调用不解析。多于六个不同内部名称时，展示已识别的前六个。命令变量不会求值，命令摘要不是输出结果；超长命令无法安全去壳时保留原首行摘要。旧包装器无需重启也能在新版采集器中识别内部名称及已有命令的截断前缀；不完整命令摘要以 `…` 结尾。新增 namespace 字段由下一次包装器启动加载。

“工具准备 / 执行未确认”表示 monitor 尚未确认执行状态：工具可能还没开始，也可能已经执行但未观察到启动或输出证据。它不能证明工具正在等待，也不能证明工具已经运行；参数生成完本身只证明模型已经输出调用内容。

## 使用说明

`exec` 是 Code Mode 的外层工具，并不是 Bash 命令。参数刚开始生成时显示 `exec（Code Mode）`；收到 `tools.exec_command(` 等直接调用语法后，显示 `exec → exec_command`，一段代码调用多个工具时列出已识别的名称。这些名称表示生成代码中的计划调用，执行状态仍以真实工具事件为准。普通工具在名称元数据到达后即可显示名称，缺失时显示“工具名未知”。

命令活动显示具体工具与命令首行摘要，例如 `exec_command · rg --files src`，去掉可识别的 shell 包装，最多 160 字；展开活动可以查看命令摘要和生成的内部调用名称。当前运行的旧包装器可能已截断命令，不完整摘要以 `…` 结尾。

生成参数时，一旦收到可识别的 `cmd` 字符串内容，就显示 `拟执行: <已收到的命令摘要>`，后续增量继续补齐；该摘要可以早于完整字符串或整段调用参数生成完。直接 `exec_command` 的 JSON 参数也支持，`shell_command` 的 `command` 字符串同样支持。一段代码中的多条命令分别保留，详情最多显示六条。命令是纯变量时等待实际执行事件；字符串拼接或模板插值只显示已有的字符串前缀并加 `…`，不求变量值。默认快照保存这些有界预览，但不保存其他参数或完整代码。
