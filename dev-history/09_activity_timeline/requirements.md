此前调整按[改动点](refinement-changes.md)实现内部工具复用、最小显示宽度、仅用户消息标记、compaction 模型过程和原始参数／结果，并使用 F01–F10 验收。首轮验收保留原有含义。

最新工具规则以[来源时间方案](true-time-tools.md)为准。最新比例以[固定时间比例](fixed-scale.md)为准，重叠规则见[前次布局](overlap-layout.md)；下列相关目标已同步。

## 1. 目标与范围

普通用户打开 Monitor 时，首先需要知道“现在在做什么、之前的工作怎样推进、是否有并行工作”。默认展示轻量轨迹，具体消息、代码、参数、补丁和结果只在主动查看后出现。

本轮范围为 macOS 原生展开面板及其活动查看器，以及支撑它们的事件投影和只读历史读取。保留 Python 核心、SwiftUI／AppKit、现有采集链路和管理能力。

本轮不新增任务百分比、ETA、聊天控制、审批或用户输入操作，不把轨迹变成开发者调试控制台，不建立独立的完整聊天内容数据库，不修改 token 计算和菜单栏状态规则。长期搜索全部 Codex 聊天、远程主机历史接入及发行包验证不属于本轮交付。

## 2. 聊天与轮次

| 编号 | 要求 |
| --- | --- |
| R01 | 所有活跃主聊天首次出现时默认收起，保留标题、项目、当前动作、耗时和实时速度。用户展开后保持其选择，不因每秒刷新自动收起。 |
| R02 | 非活跃聊天通过默认收起的历史／最近完成分组访问；延续最近约 10 分钟、最多 10 个主聊天的入口边界。非活跃或空闲不能被一律标成“完成”。 |
| R03 | 展开聊天后，按真实 turn 分别展示，默认当前轮；没有进行中 turn 时默认最近一轮。可切换当前轮与最近 5 个历史轮次。 |
| R04 | 首次用户输入通过轮次标题区访问，不占独立轨道。确认属于活动 turn 的 steering 在该轮添加输入时间点，不创建合成 turn。请求失败不能显示为已接收输入。 |
| R05 | 工具或子智能体跨越父轮结束仍运行时，保留原始 turn／thread 归属。旧轮轨迹继续表达该活动；当前轮提供“前轮仍有活动”的查看入口，不复制成新轮活动。 |
| R06 | 聊天和子智能体排序稳定，不按速度或最近 delta 重排。历史轮次切换、展开、滚动和选择均以稳定身份保存，不因数据刷新跳动。 |

“子任务”是一般产品用语，不能自动等同子智能体。只有明确独立 thread／agent 身份和关联证据的对象才展示为“子智能体”；工具内部步骤仍属于其工具活动。

## 3. 轨道与事件语义

| 编号 | 要求 |
| --- | --- |
| R07 | 主智能体固定两条分类轨道：模型、工具。它们共享时间轴，空轨保留位置；不根据是否重叠增加或移除行。 |
| R08 | 模型轨包含思考、正文／计划输出、工具参数／代码生成，以及可明确识别的文件编辑内容生成。各阶段保持独立，不因最小像素宽或来源时钟边界交叠而收成层叠组。四者使用同一色系，另以独立样式显示“整理上下文”过程；提供图例、悬停及可访问名称。 |
| R09 | 生成 programmatic tool call、inline Python、命令参数、patch 等内容时仍属于模型轨；脚本运行、工具调用、实际应用补丁属于工具轨。不以参数生成完成推断已经执行。 |
| R10 | 文件编辑生成仅依据明确工具身份或已验证的有界静态识别。动态代码、混合脚本或无法识别的写文件意图归普通工具参数生成；不凭文件名、路径或自然语言猜测。 |
| R11 | 固定轨道高度不因重叠增加。工具按来源时间定位，不水平顺延；极短工具使用粗竖线符号。重叠处仅增强颜色，不形成间接重叠大组，不画数量徽标或在时间线内展开。 |
| R12 | 子智能体默认一条汇总轨，展开后显示该智能体的模型／工具两条轨。父子共享时间轴；子智能体保持自己的 thread、turn 和活动身份。 |
| R13 | 派发／等待／关闭子智能体等调用可以在父级工具轨出现，但派发调用结束不代表子智能体结束。子智能体实际工作由其自己的事件表达。 |
| R14 | 时间点只表达用户消息，首条通过轮次入口访问；不画 hook、重试、暂停、审批或 buffering 点，不新增专门问答响应标记。上下文整理放在模型轨表达过程与可用耗时；观察缺口由质量提示表达。 |

轨道表示分类，不承诺单个智能体的所有操作严格串行，也不要求时间块首尾相接。真正的空闲、等待和并行应保留；不存在通用的“大模型指定前台／后台工具”分类依据。

同一原始 item 可以具有“模型生成输入”和“工具执行”等不同阶段，允许各有一个时间块。阶段共享明确关联，但不能为了凑一对而猜测关系。

## 4. 时间、导航和实时行为

| 编号 | 要求 |
| --- | --- |
| R15 | 所有活动保留来源时间位置；工具仅允许最小宽度造成视觉近似，展开层的位置只用于选择。来源／接收窗口不等同服务端纯计算耗时。 |
| R16 | 菜单一屏最多 60 秒，详情沿用同一固定宽度／时间比例；窗口大小只改变可见时间，不改变活动宽度。短轮次不拉伸，长轮次横向滚动，不按时长裁剪，不自动切换比例或提供手动缩放。 |
| R17 | 模型短活动保留原有视觉和命中规则。极短工具画成 3 pt 宽竖线，工具点击区等于可见矩形，不增加透明范围；符号宽度不折算成耗时。 |
| R18 | 初次打开当前轮可定位最新活动；用户向前浏览后停止自动跟随，提供“回到最新”。新事件不抢回滚动位置、不切换已选轮次或已选活动。 |
| R19 | 起点、终点、关联或观测不完整时明确显示未知／部分观测。不能以零补空，不能把观察断开、参数结束、父轮结束或超时当作实际执行完成。 |
| R20 | 历史恢复可以补全记录，但保持事件稳定身份。时间边界更正、早到数据补入和子智能体关系补全不得让用户的当前阅读位置无故跳转。 |

最小工具显示宽度为 12 pt，展开成员间距为 3 pt；统一比例为 `(291−8)/60 pt/s`。实际视口只决定能看见多少秒，详情和回合总耗时继续读取来源时间。

## 5. 活动查看器

| 编号 | 要求 |
| --- | --- |
| R21 | 点击时间线直接打开独立活动查看器。工具重叠时仅传递点击位置命中的工具，按开始时间逐项显示名称、状态、耗时及原始参数／结果；刷新不改变成员，迟到响应不覆盖新选择。 |
| R22 | 复用一个查看器窗口；支持拖动、调整大小、标准关闭和最小化，记住用户调整后的大小与位置。不采用失焦即消失的浮卡，也不常驻置顶。 |
| R23 | 查看器明确显示聊天、轮次、所属智能体、活动类型、状态和时间；提供同轮时间线以切换活动，无需反复打开菜单面板。 |
| R24 | 用户主动查看后，展示来源保留的全部可用内容。工具统一“参数／结果”，字符串原样、结构值按 JSON 展示，不再二次解析参数、展平结果数组或拼装 diff；支持选择、复制和分块续读。 |
| R25 | 只提供与活动相关的内容区域。可见思考摘要按来源展示，不声称获取未公开的隐藏思维链。图片等非文本结果显示可用预览／来源状态，不把不存在的文本补出来。 |
| R26 | 新活动不抢占查看器选择；被选活动仍进行中时，仅更新它自己的可用内容。用户正在阅读较早内容时不自动滚动到底部。 |
| R27 | 分别说明尚未落盘、字段／活动内容缺失、来源找不到、已知文件移除、读失败、无正文、来源截断及部分观测。合法空值与字段缺失分开；无正文过程显示状态和时间，不能报历史被删除。Codex 已丢弃内容不补造。 |
| R28 | 关闭查看器继续保持菜单栏与采集。退出 App、停止观察、配置恢复与清理继续遵循既有生命周期；查看器不成为隐式的额外采集所有者。 |

“完整”指当前来源可提供的完整可用内容。对于尚未完成、未保留全文或未从头订阅的实时活动，先展示已取得部分并标注覆盖，完成后再从 Codex 历史补齐，不伪造历史前缀。

## 6. 数据与架构边界

| 编号 | 要求 |
| --- | --- |
| R29 | 原始事件身份、类型、生命周期和明确父子关系是展示依据。一个 delta 更新已有阶段，不生成一个新块；镜像和重复投递不重复画图。 |
| R30 | 保留 app-server 事件与实时日志观察链路，用于当前活动、参数生成时间及实时 token 速度。历史读取不能替代实时速度计算。 |
| R31 | 已完成活动和具体内容尽量读取 Codex 自己的持久化历史。Monitor 仅补存历史缺少的阶段时间、稳定身份、关联、来源引用和质量元数据，不持久化另一份正文／代码／参数／工具结果。 |
| R32 | 对不同 Codex 版本、legacy／paginated 历史及缺少字段做能力判断和保守降级，区分“没有活动”和“这部分记录不可恢复”。不对当前样本之外的版本作完整兼容承诺。 |
| R33 | 历史读取只读，不 resume／fork／steer 聊天，不注入工具调用，不影响 Desktop 的活动 writer 或 Remote 路由。读历史不必重新启用原本暂停的实时观察。 |
| R34 | 模型与工具时间线不重新定义现有当前动作、总生成速度、官方 Output／Reasoning、推理均速或父子镜像去重。新数据契约独立版本化并支持旧快照降级。 |

## 7. 性能与可访问性

| 编号 | 要求 |
| --- | --- |
| R35 | 收起的聊天不加载全文，不常驻解析全部历史；展开后按所选轮次／活动懒加载。长轮次按视口绘制，历史解析与内容格式化不阻塞 GUI 主线程或桥接转发。 |
| R36 | 时间线支持键盘定位、选择和打开活动；可访问名称包括类型、状态、时间及所属智能体。颜色和重叠深浅不能成为唯一的信息渠道。 |
| R37 | 浅／深色、减少动态效果、窄面板、长标题和大量短活动仍可操作。轨迹更新不增加菜单栏动效的时钟或采集频率。 |
| R38 | 不把真实聊天正文、命令、补丁和结果写入 Git 中的截图、夹具或验证报告；产品本地数据沿用私有目录与现有清理边界。 |

各条需求的验证方式见[验收矩阵](validation-plan.md#2-验收矩阵)。本章定义目标行为；实际交付范围和验证层次以[验收结果](validation-results.json)为准。
