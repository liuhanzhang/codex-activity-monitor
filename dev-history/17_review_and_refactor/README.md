# 系统 CR 与基线修复（归档）

审查起点：`6314547`，2026-10-22；完成于 2026-10-23；起始工作区干净。

含后续局部修正的代码基线：`c3996dc`。本章保存已发生的审查、修正和验证；**后续六项工作的设计、执行状态和验收统一在 [第 18 章](../18_engineering_hardening/README.md)**。归档不表示已满足发行条件；回归调查可继续追加新证据。

目标是让新贡献者能够理解启动链、数据所有权和展示语义，修复可复现的问题，减少需求演进形成的重复状态与隐含约定。审查涵盖全部产品 Python、Swift、入口脚本、资源、测试组织和公开仓库入口；历史实验作为背景资料，不把一次静态审查等同于发行验收。

## 工作方式

1. 建立模块图和语义约束，执行现有 Python / Swift 测试作为基线。
2. 逐层审查：桥接与进程生命周期；事件解析及身份；聚合、速度及用量；历史读取、合并及存储；查询协议；Swift 模型、异步状态及界面；配置、构建与开源入口。
3. 记录问题的触发条件、证据、影响、优先级和处理结果。区分已确认缺陷、设计债务和未验证风险。
4. 对已确认问题添加能表达行为的回归场景，分批修改，运行相关验证；最后执行完整回归和构建。
5. 汇总改动、保留的设计选择、发行前剩余事项与验证边界。

## 约束

- 保持实时观察只读，不启动第二个 Codex writer。
- 身份和父子归属仅采用显式作用域与协议 ID；未知状态不能被名称、时间邻近或静默补造。
- 接收速度、官方用量、源时间、视觉最小宽度分别处理。
- 历史原始详情与截断 / 不可用状态保留；不提交本机会话数据。
- 本轮不改变产品交互方向，不用大规模改名或机械拆文件代替设计改进。
- 审查实施阶段不提交或推送；后续经维护者要求，将当前改动固化为本地提交，未推送。实际日常运行链路的变更另行记录。
