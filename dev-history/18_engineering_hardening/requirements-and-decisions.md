## 已确定的产品约束

这些来自现有需求，不再作为等待维护者选择的技术问题。

1. **Codex session JSONL 是权威历史。** 实时观察补充当前、尚未落盘的活动和实时速度；不建立并列的第二套历史。
2. 观察通道只读，保留原版后端和原始 stdio。观察失败不改变 Codex 的输入输出、退出码或会话所有权。
3. 身份使用明确的 scope/thread/turn/item/call ID。父子关系依赖显式来源；名称、时间邻近、交流行为不能证明层级。
4. 未知或观测不完整保留 `—` 和原因；已经知道的零正常显示。重连不补造未观测期间的速度。
5. 官方 usage 与接收速度分别计量，Output 包含 Reasoning。结构调整保持现有口径。
6. 明确 `ephemeral=true` 的后台临时会话不进入聊天聚合和菜单模式；标记未知不按用途猜测。普通隐藏聊天及真实子智能体保持现有规则。
7. 原始详情保留源换行、参数、结果和 `source_truncated` / `not_retained` 等语义。Python 页偏移以 Unicode code point 计。
8. 保留紧凑面板、独立查看器、选择和阅读位置，以及中英文切换。源文本和身份不随界面语言翻译。

## P0 历史与实时的交接规则

`c3996dc` 中的 `observation` basis、`observed_turn` 和 `history_turn` 描述了 CR05 时的实现。P0 已按下表收敛并删除不必要的影子完成状态，实际结果见实施记录；本节维护语义规则，不因基线字段曾经存在就反推产品需要两套历史。

| 场景 | 目标行为 |
| --- | --- |
| 正在运行、JSONL 尚未提供对应项 | 当前回合允许有界的实时补充；实时终止事件可结束当前工作指示，不等待磁盘落盘 |
| 回合刚结束，历史尚未追上 | 已观测终止仍用于该当前回合的即时反馈，标明等待历史交接；临时保留不是永久历史事实 |
| 有效 JSONL 已包含对应活动／结束轮次 | 采用当前 JSONL 的内容和历史状态，按稳定身份退役相应实时补充；历史不恢复接收速度 |
| JSONL 暂时不可读或末行未完整写入 | 保留已加载内容和阅读位置并标记来源状态；不把读取失败等同于确认删除，也不退役仍需保留的补充 |
| 已验证同一源被替换／截短，旧事实已不存在 | 撤销依赖旧历史的结论并重新读取当前源；较早的实时缓存不能补回一段被当前历史移除的“权威历史” |
| collector 重启或 source bridge 确认断流 | 恢复身份与显示上下文，连续性与实时速度未知；不能仅凭恢复文件标成持续观测 |
| 仅 GUI 断开，collector 持续正常观察 | 界面标记断开／陈旧；重连取完整状态。collector 没有源观测缺口时不新增一个虚假的缺口 |

“等待历史交接”的容量／重试窗口在 P0 明确为工程参数。到期或超预算时标记不可验证并停止把缓存当作历史；不以超时伪造完成或持续生成。现有 history 请求保留短期快速重试、之后降低频率的方向，实际数值由场景验证确定。

当前轮次如果历史在运行中发生异常变化，未落盘的当前工作可继续按实时证据显示，并附来源变化原因；归档历史仍由当前 JSONL 决定。后台工具只能按其显式生命周期结束，模型 turn 结束不代表已确认后台进程结束。

## 工程默认方案

下表保留阶段开始时的默认选择和决策理由；协议及实际参数以技术设计、资源预算和实施记录为准。可在保留产品语义的前提下依据实验调整并记录原因，无需维护者逐一决定底层参数。

| 决策 | 默认方案 | 原因与调整条件 |
| --- | --- | --- |
| 本地实时传输 | Unix domain stream socket，使用独立 `state.sock`；保留现有 `events.sock` 和 `tl.sock` 职责 | Python／Swift 可共享小协议；原型验证字节分帧、取消和目标系统可用性后定稿 |
| 状态更新 | 每条都是完整状态；合并待发送的中间状态，不引入增量补丁协议 | 重连与丢弃中间刷新简单；真实生命周期事实已在 Engine 中处理 |
| 存活判断 | 生命周期锁、IPC 连通性、事件循环进展、存档结果分别表示 | 文件新鲜度不再混充进程所有权 |
| 恢复文件 | 暂保留 `snapshot.json` 路径，改作低频恢复存档；实时读端全部迁移 | 保留恢复及 fixture 兼容，避免仅 GUI 迁移后让终端看旧速率 |
| 分页 | 无服务器会话依赖、按 section 验证的阅读快照 token | 能跨 CLI/provider 实例比较；追加内容不会迫使已读页全部作废 |
| 来源变化的界面行为 | 保留已读内容，停止旧页拼接，提示重新加载 | 保留阅读位置，明确内容状态 |
| 资源控制 | 先测量；优先按需读取、索引分段、缓存淘汰与任务准入 | 参数须同时考虑复制峰值、队列文本及迟到身份，不能只看对象个数 |
| 类型 | 使用现有语言原生类型和小的协议适配层 | 避免为了类型引入第二套状态或通用框架 |

## 发行准备与维护者决策

六项工程工作的设计没有被以下选择阻塞；发行前需单独确定并验收。

- **许可证与素材范围**：2026-10-26 维护者已选择标准 [MIT 许可证](../../LICENSE)，版权署名为 Hanzhang Liu。第三方依赖与外部素材保留各自许可；图像、参考素材和开发预览资产的公开分发范围仍需复核。
- **兼容承诺**：工程阶段沿用 macOS 26+、Python 3.11+；首发正式支持的系统、架构和 Codex 版本矩阵由维护者确认。扩展范围会产生额外适配和测试工作。
- **发行交付**：独立依赖布置、稳定安装路径、签名／公证、安装更新、卸载恢复、旧版本迁移和干净 checkout／远端 CI 验证。
- **发行验收**：自然长期使用、Codex 升级／崩溃恢复、Remote、VoiceOver、多显示器，以及拟公开文档与 Git 历史的隐私／来源材料复核。

如果测量后发现达成资源预算需要改变历史可读范围或明显改变产品交互，应先给出测量、具体选项与取舍，再交维护者决定。现阶段不预设缩短可查看历史来满足一个未经测量的数字。
