# 分阶段实施计划

状态：**实现已落盘，自然验收待完成**。起始代码基线 `c3996dc`。P0–P7 的代码、预算与受控验收已有记录；日常统一版本切换已核对，新版自然／长期样本尚未验收。实际证据和边界见[实施记录](implementation-results.md)。问题编号和技术契约见 [README](README.md) 与[技术设计](technical-design.md)。

## 交付和提交方式

- 每个阶段先固定输入／输出契约和可复现失败场景，再完成实现与针对性回归；阶段验收后再推进日常切换。
- 提交围绕可单独理解和回退的行为组织。协议、实现和必要客户端适配形成一致提交；纯搬移／命名整理与行为变化分开。
- 复用仍有效的已有验证。仅当接口、兼容边界或失败场景变化时补对应测试；阶段性集成／最终切换再跑完整回归。
- 实验使用合成数据、临时 runtime 和可注入服务。原始本机诊断、私密会话、路径和截图保留在忽略目录；公开结果使用脱敏配置与统计。
- 文档计划本身不触发产品改动、日常重载、提交或推送。后续实施按维护者的开始指令进行；提交只覆盖当次已授权范围。

日常统一切换前，独立阶段可在隔离环境继续实施；这不替代 P3 的版本一致性和自然回合验收。

切换步骤：先在临时 runtime 通过故障矩阵，再安排完整回合间的日常切换；保存旧构建、源码提交和私有恢复副本，核对两端实际版本后观察新回合。数据 schema 兼容测试通过后才清理旧读路径。

当前材料与操作顺序见[日常切换清单](rollout-checklist.md)；[切换前范围核对](evidence/pre-cutover-audit.md)逐项保留最初 41 个实施项及其证据范围。准备包／备份／签名检查不当作实际切换或回退已经通过。
