## 每个 delta／批次的 token 数

同一组 921 个源 delta 没有直接保存逐段 token 数，也没有保存 delta 正文。后续利用明确相同的 JSONL `response_item.payload.id` 找到两条完整工具输入，分别为 3,599／102 个字符，UTF-8 字节数也分别为 3,599／102，与各流已采分段的字符／字节总长完全一致。两条流均只有一个观察代次，按逐段字符长度切分时，每段的 UTF-8 字节数也全部匹配。

按追加型 delta 协议，用最终原文还原累计前缀，并依照 Monitor 当前模型编码选择规则使用 `o200k_base` 做分词；每段 token 增量是相邻累计前缀计数之差，同一读取时刻的增量再合并为批次数。**这是离线重建的本地 token 估算，不是当时直接记录的逐 delta 分词结果，也不是服务端 token ID。** 每条原始 delta 的文本／内容摘要没有保留，无法逐段独立比对原文；重建依据与限制一并列出，不把长度匹配写成内容哈希匹配。

两条完整输入分别计为 892／29 个 token，总计 921；与各自所有累计前缀增量、批次增量求和一致。本次没有 0 或负增量；重建工具保留带符号差值，没有为得到这一结果做归零或限幅。单段直接分词的计数不能一般化地用于求和。

本组的 **每个 delta 恰好 1 个本地 token** 是观测结果，不能推广为所有正文、代码、中文或模型流都必然如此。流内接收时间戳不同的批次，通常只有 1–2 个 token，也会集中收到 19 个；它进一步说明逐批速度会对非常短的接收间隔敏感，但不替代 GUI 回归定位。

统计见[token 数量附件](evidence/chunk-token-distribution.json)。此次只读 JSONL、在内存中分词并保存脱敏汇总，没有重启 collector、修改 JSONL 或新增自然采样。

## 有效性与异常线索

首轮按“Engine 接纳并建立 TextStream”筛选，运行约 120.226 s，保留样本为 0，因而没有生成任何分位数。第二轮改为直接保留进入 collector 的上游接收元数据，按明确的序号去重；这不是把未知速度补成数值。

第二轮的 921 个 delta 都已有聊天归属，但没有活动 TextStream，Engine 将它们计入 `late_terminal_deltas`。该分支也包含线程状态为 unknown 的情况，因此**这个计数器名称不证明源流实际上已经结束**。本次诊断切换跨过了正在进行的回合；它对活动恢复的影响尚未定位，不能把这组记录当作无缺口自然回合验收，也不能用它确认之前 GUI 数字正确。完整流子集样本为 0，附件明确保留该边界。

本组数据能回答源接收间隔的分布。关于重构前后 GUI 波动的具体原因，仍需在未跨重载的新自然回合中同时核对状态与接收时序；没有为了补样额外发起模型请求。

## 统计口径

先前的约 7.7 ms 来自两个流的三个快照区间：约 3.226 s 新增 420 个 delta。它是粗略事件密度，不是逐次读取间隔的实测分布，无法推出中位数或 P90。

本次改用 bridge 在传输读取后记录、随事件传到 collector 的单调时钟。计数排队和 collector 调度时刻不充当接收时刻。第二轮保留源上游非空 delta，并按明确的序号去重；回放、采样边界前的旧事件及显式临时会话排除。无法建立活动流的源记录仍用于接收统计，另列完整流子集；两者不混称为 GUI 测速样本。原始文本、工具参数、结果和 token 内容均不保存。

同一次 bridge 读取中的多个 delta 共享接收时间。分别报告：

- **delta 事件间隔**：同一流相邻 delta 的时间差，保留共享时间戳产生的 0。
- **不同接收批次间隔**：同一流相邻不同读取时间戳的时间差，仅包含正间隔。
- **每个流内接收批次的 delta 数**：说明一批通常携带多少事件。

这里的“接收批次”是 bridge 读取到、包含该流 delta 的数据批次，不等于服务端 flush、SSE chunk 或 TCP 包。既不能给同批事件编造独立接收时刻，也不能把 collector 连续处理它们的 CPU 时间当作网络间隔。

分流使用明确的 backend／item／内容分片／来源／缺口代次，不跨工具或 item 计算间隔；已知缺口切断区间。流内长停顿保留，不因大于 1 s 就删除或推断其原因为思考、模型或网络。窗口边界及每条流首尾的等待无法形成完整相邻对，属于截尾部分。

分位数采用 nearest rank：将 n 个值升序排列，Pp 取第 `ceil(p*n)` 个值。均值按所有有效相邻间隔计算，每个间隔权重相同；不是先算每条流均值再平均。

## 采样与恢复

为取得逐 delta 源时间，当前 collector 临时由私有诊断启动器接管，已有 GUI 凭据保持一致；诊断记录先在内存中有界积累，结束后才写私有文件。Desktop、原后端和驻留 bridge 均保持运行，没有为补样额外发起模型请求。

临时切换会产生真实观察缺口，Monitor 保留这些缺口。限时到期后恢复普通 CLI collector，并核对实际 GUI 拥有连接、实例新鲜度及普通启动命令。诊断文件位于忽略的 `.local/diagnostics/chunk-intervals-20261025/`；公开附件只保留无身份、无正文的汇总数据。

两轮均已结束，普通 CLI collector、原 GUI 拥有连接和状态新鲜度已恢复并验证；恢复后 collector 实际加载的源码指纹与采样前一致。没有重启 Desktop、修改原始 JSONL 或部署新的测速策略。诊断开销没有端到端量化，不将探针内部分支计时当作全部额外开销。

统计实现用小样本验证了 nearest-rank、同批零间隔、空集合、跨流／跨缺口隔离及倒序时间处理。未修改产品源码，沿用已有产品回归证据，不重复完整 Python／Swift 测试。这不是全日或所有模型的稳定性结论。
