日期：2026-10-22。状态：英语支持已实现，资源、定向检查及隔离原生预览已通过；随后按用户要求构建并重载了日常 App。详见[实施结果](implementation-results.md)。用户已确认完整支持 macOS GUI、终端看板及相关用户提示的方向；本章细化语言选择、资源组织和兼容规则。

编写时源码基线：`5b3c0d3`，工作区干净。实施前重新核对 Git 状态及当前源码，保留其他工作。

## 目标

在现有中文界面基础上增加完整英语支持。用户可以在 GUI 设置中选择「简体中文 / English」，即时切换并保存；终端支持 `--lang en` 和 `l` 切换。默认继续中文。

支持范围包括当前活动、主子智能体时间线、独立 Activity Viewer、输入和活动详情、设置与恢复流程、用户可见错误及终端提示。语言只改变展示，采集、活动身份、历史来源和指标语义继续沿用现有规则。

## 当前事实与需要补齐的部分

| 已核对的现状 | 本轮工作 |
| --- | --- |
| Python 的 `i18n.py` 已提供消息 key、完整资源注册、模板参数检查、嵌套消息及单复数选择；目前只注册 `zh-CN`。 | 补齐并注册正式 `en` 资源，更新仅支持中文时的相关检查。 |
| 终端已有显式参数、运行目录内 `ui-settings.json` 和 `l` 切换机制。 | 发布完整英语后启用现有入口，补充真实英文资源验证。 |
| GUI 已有 `zh-Hans.lproj` 与 `L()`，部分位置仍直接调用系统本地化 API。 | 统一为可显式选择语言、可即时刷新的资源入口，补齐英文资源。 |
| Swift 快照模型仍读取 `display_label`；模型、时间线和管理状态存在中文硬编码。 | 解码语言无关的消息，分离状态与文案，补齐模型侧和动态内容的本地化。 |
| 管理接口已有稳定错误 `code`，但错误正文多为中文；历史详情也可能含 Monitor 生成的中文标题。 | 为可控的用户提示提供结构化消息和参数，保留原始来源内容与诊断。 |
| GUI 数据目录偏好与终端运行目录偏好相互独立。 | 沿用各自存储位置，共用语言代码和文案语义，不增加跨进程同步。 |
