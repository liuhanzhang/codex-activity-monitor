# 英语支持：实现计划

日期：2026-10-22。状态：P0–P4 已完成；实现和验证边界见[实施结果](implementation-results.md)。产品行为以[需求与决策](requirements.md)为准；下文保留实施路径与退出条件，实际通过范围以结果记录为准。

## P0：确认基线与文案清单

- 重新检查源码、Git 状态、现有资源和运行构建身份，保存其他改动的边界。
- 盘点 Python 资源及 CLI／管理／历史详情中的自有文案；盘点 Swift `L()`、直接系统本地化调用、模型属性、AppKit、Help 和辅助功能字符串。
- 将文案分为 Monitor 自有展示与原始来源内容，列出当前界面入口及每个动态标题的来源；搜索中文只是辅助，不能把用户数据当翻译目标。
- 复用现有合成 fixture 和只读预览，为中文、英语、旧数据缺消息、错误和长文本准备可控输入，不收集或提交真实聊天正文。

退出条件：明确资源、动态消息和兼容字段清单；确认验证使用的隔离 runtime、data-root 与偏好，不触及日常配置。

## P1：Python 英文资源与结构化消息

主要落点：`messages_zh_cn.py`、新增 `messages_en.py`、`i18n.py`、`display.py`、`cli.py`，以及实际产生用户提示的 `app_control.py`、历史／时间线详情模块。

1. 补齐正式英文 catalog，复用完整 key 与模板参数验证；数量模板按英文提供 `one / other`，嵌套消息使用相同机制。保留中文默认与无效输入降级。
2. 保持引擎的消息描述与渲染分离，检查 `display_message` 在聊天和活动层的覆盖。只在缺口处补消息描述，不改变活动状态或重新推断生命周期。
3. 为管理错误和 Monitor 自有详情标题补充可选消息 key、参数或稳定语义字段。保留旧 `error`、`display_label`、标题等兼容字段和原始诊断，不依赖对最终中文句子反向匹配。
4. `ControlError` 的稳定 code 保留；为需要上下文的错误保留参数与更具体的消息 key。CLI 的人类提示按当前语言渲染，GUI 接口继续输出结构化 JSON。
5. 将 CLI 自有的硬编码帮助说明纳入资源，检查命令前／`watch` 后的 `--lang`、转发参数 `--` 边界、非法语言和机器输出行为。
6. 扩展 GUI 偏好读写接口，仅增量合并语言字段并返回可供界面使用的值；不更改登录启动、接入或观察租约。与管理操作共用现有锁／原子写入边界，避免丢字段。

退出条件：正式英语资源完整；终端可真实渲染英语；新消息字段对旧读取方可忽略，旧字段仍可消费；管理错误与详情能提供语言无关的展示依据。

## P2：Swift 共享消息格式化与兼容解码

主要落点：`MonitorModel/Snapshot.swift`、`Timeline.swift`、`Management.swift` 及轻量本地化组件和资源。

- 在 `MonitorModel` 层提供显式语言类型、消息描述和纯格式化入口，使模型侧无需依赖 `MonitorApp` 或全局可变语言。共享活动／模型展示资源由该层持有，App 专有视图文案继续放在 App 资源中。
- Python 活动 catalog 作为核心活动语义及译文的来源；通过确定性的构建前导出生成 Swift 可读取的活动资源。生成物可检查、可重复，不在 GUI 运行时启动 Python 翻译，也不另维护一份活动译文。Swift 特有状态和视图资源按各自 key 管理。
- 为当前使用的 `{name}`、数值格式、`one / other` 和嵌套消息实现有界、明确的格式化。只支持所需的已知模板形式，不能用静默丢参数掩盖不支持的格式。补充跨语言样例检查，未知消息按当前语言回退。
- 快照和详情新增字段采用可选解码；旧字段继续保留。将 `Chat.title`、管理状态、时间线 kind/status、协作目标说明和辅助功能句子转为接收显式语言的展示接口，保留稳定的模型语义。
- 所有新 GUI 路径优先使用结构化消息；旧数据按需求第 3 节降级。不得从本地化标签建立身份、主子关系或活动状态。

导出入口纳入 `bin/build-gui` 并提供过期检查；直接 `swift build/test` 使用已生成的资源，不要求插件启动 Python 或写源码。资源与导出工具一同提交，CI／定向验证能够检测源资源变化后未重新导出的情况。

退出条件：相同快照和时间线能在 Swift 中按两种语言渲染，来源内容保持一致；核心活动译文无人工双份维护；不新增采集器语言状态。

## P3：GUI 即时切换与界面接入

主要落点：`MonitorApp/Localization.swift`、`DashboardStore.swift`、`DashboardView.swift`、`Main.swift`、`BackendClient.swift`、时间线／详情视图及中英文资源。

1. 以 store 持有可观察的当前语言，默认中文；有效保存值加载后采用保存值。统一资源入口按显式语言选择 bundle，处理 `String(localized:)`、`NSLocalizedString` 与 SwiftUI 隐式系统 locale 路径，避免系统语言绕过选择。
2. 视图依赖语言值重新计算文案，模型格式化显式接收该值。窗口、浮层、AppKit 绘图、Help、辅助功能及菜单栏提示都接收刷新；不借助重建聊天／时间线 store 来刷新。
3. 顶部齿轮增加语言子菜单及选中标记。点击立即更新展示，异步持久化；连续快速切换以最后一次用户选择为准，旧保存结果不得覆盖新状态。
4. 偏好保存与登录启动保存互相保留字段。读失败默认中文、写失败提示未保存，使用者可以重试；只读预览和隔离测试使用内存或隔离文件。
5. 已存储的错误／通知尽可能保存消息描述和原始诊断，切换后重新渲染，避免只有新错误变为英语。系统原始错误保留其自身语言。
6. 替换本轮可控硬编码及直接使用核心中文标签的入口；启动阶段缺少正常 store 时，也使用同一语言解析和安全默认规则。原生对话框由 Monitor 设置的标题、正文与按钮纳入资源。
7. 核对资源 bundle 与打包元数据：`defaultLocalization` 保持中文，英文资源被复制到实际 App，构建脚本不会遗漏新增模型资源 bundle。GUI 自有文本不依赖用户修改系统语言。

退出条件：主面板与独立窗口同时切换，重新打开菜单／对话框语言正确；当前阅读、选中、缩放与跟随状态保留；不发起接入或采集操作。

## 技术风险与处理

| 风险 | 实施要求 |
| --- | --- |
| 两端模板语法或参数格式不同 | 限定格式化能力并用同一批跨端样例验证；导出检查发现不支持格式应失败，不能发布半英文界面。 |
| 中文资源 key、原始内容与文案混在一起 | 按来源与调用路径盘点；不得以“所有中文字符消失”作为整体通过条件。 |
| 并发偏好写入或旧异步响应覆盖当前语言 | 合并字段、串行保存／代次处理，并覆盖快速切换与登录选项并发场景。 |
| 可观察状态变化没有触及 AppKit／独立窗口 | 显式传递语言和失效标记，实测已打开表面，不依赖关窗重开。 |
| 英文较长，紧凑面板与轨道名称挤压 | 优先使用清楚的短句、合理换行和 Help；保留关键操作和完整辅助功能描述，不改变时间比例。 |
| 新 GUI 读取旧核心，无法恢复动态消息语义 | 使用已知语义字段或当前语言通用提示，保留来源诊断，不猜译旧标签。 |
