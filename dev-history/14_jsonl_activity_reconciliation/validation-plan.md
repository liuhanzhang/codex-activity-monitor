# 验收计划

日期：2026-10-22。状态：本轮定向测试、隔离 collector、原始来源与有限日常检查已执行，逐项证据及边界见[实施结果](implementation-results.md)。本章保留产品修复验收要求，不将全部场景解释为自然使用均已覆盖。[修复前可行性实验](feasibility-results.md)的 9 个场景仍单独记录。

## 1. 主要通过条件

Codex JSONL 已明确保存同一活动的完成记录时，即使实时完成事件缺失、面板一直关闭，Monitor 也能自动停止该活动的运行中状态。快照、当前活动汇总和时间线采用同一完成事实，观测缺口与不能恢复的速度继续保留。

不能通过超时自动判成功、清空质量标记、隐藏异常线程或重启后丢失内存状态来满足此条件。

## 2. 定向场景

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| V01 | 实时命令开始和输出、缺少完成；JSONL 含同一 canonical item 的完成记录 | 后台合并后 `active=false`，状态、退出码和源时间正确；列表、总速度与时间线不再把它当作运行中 |
| V02 | 面板从未打开；collector 持续运行，JSONL 后追加完成记录 | 校正不依赖 timeline 查询；条件满足时两个成功后台刷新周期内生效 |
| V03 | 实时先完成，JSONL 延迟追加或只有更早开始记录 | 立即展示实时完成，后续补齐字段；不回退为运行中，不在落盘瞬间重复新增活动 |
| V04 | 重复读取、重连重放、完成后迟到开始事件 | 终止状态不被重新打开；活动 ID、数量、完成时间和用量计数稳定 |
| V05 | 相同名称／命令文本，不同 scope、thread、turn 或 item | 只校正完整身份匹配的活动；其他项不变 |
| V06 | JSONL 仅有 raw 参数完成或外层 `exec` 调用返回，内部进程仍在运行 | 参数／执行阶段仍分别处理；不由参数完成或外层返回推断进程结束 |
| V07 | 回合已完成但后台进程可靠地持续运行；稍后才取得命令完成记录 | 回合与命令分别显示；命令自身终止后结束，不提前结束，也不改变原 turn 归属 |
| V08 | 旧回合活动结束，当前同线程有新回合正在生成 | 旧活动被纠正，新轮仍活跃且速度按自身覆盖计算 |
| V09 | gap 后未取得任何终止证据 | 显示状态未知，保留未决身份；不继续声称已知运行，不报成功完成，也不把未知总速度变成零 |
| V10 | 历史已确认完成，但该活动曾有 gap；另有一个完整观测的新流 | 旧缺口保留且不影响新流汇总；新流按原口径显示速度 |
| V11 | 校正一条旧命令后，另有未关联事件或未知活跃流 | 仅移除已结束活动的影响；全局总速度仍可为 `—`，不批量清除无关质量原因 |
| V12 | JSONL 缺失、读失败、部分末行、header 身份不符、文件替换／截断 | 不误配、不把暂缺当完成；缓存失效和重试正确；完整追加后能够再校正 |
| V13 | 大量重复 child relation 仅指向少数不同线程，某线程首次索引很慢 | 同一线程后台任务去重；不在实时事件锁内读文件；其他线程和快照保持可服务 |
| V14 | 历史墙上时间、现有单调时钟、跨重启补读、很久以前的完成记录 | 无巨大／负耗时，不用读取时刻结束活动，不重新延长最近完成窗口，不产生虚假当前速度 |
| V15 | 两来源出现互相矛盾的终止信息，或历史缺少某字段 | 冲突保留来源；缺失字段不覆盖有效补充，不凭到达顺序选择结果 |
| V16 | 完成记录读取后，打开所选轮次与独立活动详情 | 同一命令状态一致；phase ID、所有权、源时间、原始参数／结果及截断说明保持 |
| V17 | collector 重启，旧快照含残留活动，恢复时 JSONL 已有完成事实 | 不把恢复快照永久作为权威；无需重新运行命令即可校正，重载缺口仍如实保留 |

优先在现有 `test_history.py`、`test_engine.py`、`test_overview.py`、`test_timeline.py`、`test_timeline_query.py`、`test_runtime.py` 及独立的 `test_reconciliation.py` 中增加有实际失败条件的测试。Swift 仅在 DTO 或展示字段变化时补充对应兼容测试，不重复无关 GUI 构建。

## 3. 固定来源对照

从本机私有证据中提取一个最小脱敏场景：一个回合、一条具有 process 身份的命令、开始／输出、观测缺口、回合完成，以及只存在于 JSONL 的命令完成记录。保留 canonical 类型和字段形状，替换私人内容与身份；不把原始会话、272 万字符输出或数据库复制进测试仓库。

固定时钟和来源后，对照以下变化：

- 允许变化：命令状态、退出码、源结束时间、固定耗时、当前活动数、该活动对总速度不可用的贡献。
- 必须保持：稳定活动 ID、thread／turn 所有权、原始阶段区分、历史缺口、其他活动状态、既有用量归属和原始详情来源。
- 无其他未知来源时，总速度可恢复为已知零或已观测新流的汇总；存在其他未知来源时，继续显示 `—` 才是正确结果。
- 历史返回的数据不能被计为新的实时 delta；补读完成记录的时刻不能出现在当前速度峰值或最近完成时间中。

确认问题来源仍然可读，再做本机对照。原始本机路径可能失效；若不可用，保留脱敏复现并明确缺少真实来源对照，不能改称已经验证实际那条命令。

## 4. 隔离运行与日常检查

先在独立 runtime 中持续提供实时心跳并发布快照，故意省略命令的实时完成事件，再向 fixture JSONL 追加其 canonical 完成记录。整个过程不发起 timeline 查询，核对后台自行结束残留活动。另测慢读、未完成末行、缺文件后出现、重连和新回合并行场景。

隔离通过后，再对日常 Monitor 做有限检查：记录实际 collector／GUI 加载身份；面板关闭期间取得更新后的快照，随后打开面板核对同一命令完成状态及来源时间。只有确实受字段变化影响时才回归菜单动画、原生详情与选择状态，不重复完整布局验收。

若日常旧线程已过期或因重载消失，不能把“现在看不到那条命令”作为修复通过证据。优先使用仍可读取的原始来源和受控漏完成场景，分别记录各自证明范围。
