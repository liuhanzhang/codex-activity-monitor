# 历史观测缺口与当前速度展示实施结果

更新：2026-10-25。起始代码基线：`1a49f46`。**代码、受控验证和日常 GUI／collector 更新已完成。** 产品规则与验收范围见[本章入口](README.md)。驻留 bridge 的新日志分类及完整自然回合验收仍有边界。

## 已实现行为

- 按独立生成流判断当前窗口，再统一形成会话速度和 overview。会话历史 `observation_gap` 保留，但不再整轮排除已经恢复的当前读数。
- 状态栏及展开面板使用 `observed_subtotal`。部分覆盖有有效数字时继续显示数字；`generation_rate` 仍只表示完整覆盖合计，未知部分不补零。部分覆盖为零也不会触发全局空闲动效。
- 状态栏没有有效数字时统一显示 `—`，包括正常首次计数；不显示 `Generation`／“生成”等文字占位。正常采样仍保持健康连接且不告警。
- 跨缺口的旧流重新建立接收与计数代际，等到新连续区间覆盖窗口且计数有效才恢复。前代任务迟到不能覆盖新结果，其内存继续计入原预算。缺口后的新流使用自己的完整基线。
- 恢复后的局部文本计数不会冒充整个 item 的累计 token；权威终态全文可以重新计算完整数量，但不会补造缺失的接收历史或全程接收速度。官方 Output／Reasoning 用量保持原有来源规则。
- 会话新增可选 `generation_rate_coverage`、`generation_rate_issues`。仅当前受影响的会话显示小提示图标，帮助文字区分观测缺口、身份冲突、计数失败、资源限制及断连；历史缺口已恢复时不显示当前告警。终端保留数字并提示当前不可用部分。
- 时间轴与独立 Activity Viewer 继续按各自活动证据判断，没有更改 JSONL 或推断未知时间。会话缺口不会成为时间轴的全局展示开关。
- backend 保留最多 16 条缺口原因、接收时刻及作用范围。累计丢弃数不再把同一次显式缺口在下个心跳重复报告。已明确识别为发出消息／帧的超长日志单独计数；无法识别的旧 `oversized_diagnostic` 继续保守处理。

核心路径是 `metrics.py`、`engine.py`、`overview.py`、`menu_presentation.py`、Swift `Snapshot` 和 `ChatRowView`。旧客户端可以继续按完整覆盖保守显示；新客户端对新增会话字段采用可选解码。

隔离 collector 实际观测到以下序列：

| 阶段 | 覆盖 | 当前观测合计 | 当前会话提示 |
| --- | --- | --- | --- |
| 初始正常流 | 完整 | 80 T/s | 无 |
| 注入缺口 | 不可用 | 无 | 缺口 |
| 新流完整、旧流仍未知 | 部分 | 25 T/s | 缺口 |
| 旧流终态已确认，仅剩历史缺口 | 完整 | 25 T/s | 无 |
| 同一条流再次跨越缺口 | 不可用 | 无 | 缺口 |
| 新连续区间尚未覆盖一秒 | 不可用 | 无 | 缺口 |
| 同一条流完成恢复 | 完整 | 40 T/s | 无，历史缺口仍保留 |

原生合成状态还确认：历史缺口已恢复显示 `100 T/s` 且无当前提示；部分覆盖仍显示 `100 T/s` 并在受影响会话保留提示；部分覆盖为零显示 `0 T/s`，模式仍为速度展示。原生验证不证明物理屏幕像素、自然模型时延或长期稳定性。

隔离验收脚本首次读取状态时遇到 socket 尚未创建的启动竞争，已改为有截止时间的就绪等待后重跑通过。原生 Preview 在受限进程环境中首次提前退出，随后在图形登录会话中完成验证；未修改日常采集配置。

## 日常切换与剩余边界

日常 GUI 与 collector 已按用户授权正常退出并更新重启。GUI 实际 build 与候选包一致，collector 实例已改变、37 个启动时模块指纹全部匹配当前源码；两次新 nonce 探测健康、状态序号前进，生命周期锁由新 collector 持有。签名验证通过。

4 个既有 bridge 的身份与 PID 保持，Codex Desktop 及其原版后端没有重启。它们仍加载旧 bridge 源码，新日志分类需等对应接入进程下次加载后才能生效；旧未知丢弃没有被重解释为无害。GUI／collector 的当前速度恢复与汇总逻辑已经更新，不依赖这些 bridge 立即升级。

当前聊天跨越了切换。短时实测已经看到：一部分会话仍有当前缺口时，状态栏继续显示有效读数，正常会话没有当前异常提示，异常定位在受影响会话。实测中的一个状态为 `46 T/s`，不将该瞬时数字当作性能基准或完整自然回合证据。原始 PID、聊天身份、快照和完整 GUI 诊断留在忽略的私有目录，公开证据只保留归纳结果。

仍待完成的是驻留 bridge 加载新分类代码，以及从开始到结束不中断的完整自然回合验收。本次不宣称已定位先前缺口的具体原始报文，亦不宣称超长日志与内存峰值的完整因果链已解决。

## 状态栏文字占位修正

首次计数时曾沿用一秒测速初版的 `Generation`／“生成”占位。根据用户对顶部菜单栏的反馈，已删除这个分支：显示仅使用有效速度数字或 `—`，不会为了文字占位扩大宽度。模型与原生 App 测试通过；原生中英文实测确认正常采样仍无异常提示，采样与普通三位速度的状态栏宽度相同。

修正后已重新构建并重启日常 Monitor。实际 GUI build 与候选一致，新 collector 状态健康、序号递增，已记录的日常标题只有速度数字或 `—`。验证和新 build 记录见[占位修正证据](evidence/statusbar-no-placeholder.json)；此前的原生展示和首次切换文件保留其原始版本边界。
