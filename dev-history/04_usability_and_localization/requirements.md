# Monitor 易用性与多语言准备：需求

日期：2026-10-13。状态：本轮实现与相关验收已完成；英文资源后续补齐。结果与运行边界见 [实施结果](implementation-results.md)。随后确认的文件编辑需求与结果见 [文件编辑补充](file-editing-supplement.md)。

本轮调整终端看板的文案、名称与刷新体验，并为后续英文界面和用户切换语言准备结构。实现步骤见 [实现计划](implementation-plan.md)。此前的生命周期规则继续作为基础，见 [事件消费与展示决策](../03_event_lifecycle_and_progress_display/event-display-decisions.md) 和 [工具生命周期与审批状态](../03_event_lifecycle_and_progress_display/tool-lifecycle-and-approvals.md)。

## 1. 已确认的产品需求

| 编号 | 需求 | 本轮目标 |
| --- | --- | --- |
| R1 | 统一准备与执行文案 | 命令和普通工具使用 `准备中 · 名称`、`运行中 · 名称`。MCP 名称包含产品与工具。 |
| R2 | 命令只显示命令名 | 去掉可执行文件路径、参数、flag；识别 shell 包装后的实际命令。 |
| R3 | 显示刷新降为 1Hz | 看板每秒定时刷新一次；事件仍实时接收，按键即时响应。 |
| R4 | 耗时精确到整秒 | 去掉小数秒；不足一秒不显示，依次使用秒、分钟、小时格式，例如 `12s`、`1m02s`、`1h02m03s`。 |
| R5 | MCP 名称面向用户 | 按统一规则取得最面向用户的产品 / 工具名称；缺失时回退可识别短名，不设置产品或工具特例。 |
| R6 | 为多语言准备结构 | 集中管理中文文案，分离状态与语言，准备语言配置、持久化选择和切换机制；完整英文资源后续补齐。 |
| R7 | 文件编辑显示目标文件 | `apply_patch` 生成阶段与正式文件修改共用文件展示：尚无完整文件名为 `编辑文件`，已知文件名为 `编辑中 · 文件名`；多文件、结果与执行证据见补充文档。 |

默认界面继续保留聊天 / 项目、当前活动、耗时、生成速度四列。专门的动作文案，例如思考中、修改文件、搜索网页、自动审核中、压缩上下文，沿用已有语义并纳入文案资源。

## 3. 活动文案与状态边界

### 3.1 统一格式

| 情况 | 目标展示 |
| --- | --- |
| 正在生成命令输入，已识别命令名 | `准备中 · python` |
| 已确认命令实际执行 | `运行中 · python` |
| 正在生成 MCP 调用输入，已识别产品与工具 | `准备中 · 产品展示名 · 工具展示名` |
| 已确认 MCP 工具调用开始 | `运行中 · 产品展示名 · 工具展示名` |
| 正在生成普通工具输入 | `准备中 · 工具名称` |
| 已确认普通工具调用开始 | `运行中 · 工具名称` |
| 输入仍在生成，尚无可靠名称 | `准备中` |
| 输入已生成，但实际执行状态尚未确认 | `处理中 · 已知名称`；无名称时为 `处理中` |
| 最近完成的命令 | `刚完成 · python` |
| 活动详情中的已完成命令 | 活动列显示 `python`，状态列显示 `完成`。 |

表中的产品 / 工具名称是格式占位符，具体值由可获取的元数据决定，不指定任何产品改名映射。

### 3.2 语义规则

- 生成参数适用于模型直接发起的普通函数、自定义工具等调用，不是终端专属；参数较短时，准备阶段可能不会被某次 1Hz 刷新采样到。
- Code Mode 中识别出的内部名称只表示脚本中计划调用的工具。外层脚本生成、内部工具执行和后台命令生命周期仍按各自证据处理。
- 参数生成完成、审批通过或计时增长均不能单独证明实际执行；延续已有进程、启动与输出证据门槛。
- 确认 MCP 服务正在启动时，可以展示准备状态；没有启动证据时，不把“执行未确认”解释为确定正在等待。
- 准备与运行采用统一格式；已有明确动作的专门活动继续使用原来的动作语义。
- 已结束活动使用名称与真实结果，不出现 `刚完成 · 运行中 · python` 或详情中“运行中”与“完成”并列的冲突。
- 审批、用户输入、断连、观测缺口、失败、后台进程等既有语义继续保留。名称和语言调整不改变关联身份、去重、阻塞范围和速度可信度。

## 4. 命令名称

### 4.1 展示规则

| 输入示例 | 显示的命令名 |
| --- | --- |
| `.local/venv/bin/python script.py --verbose` | `python` |
| `/usr/bin/python3 -c "print(1)"` | `python3` |
| `/bin/zsh -lc 'rg --files src'` | `rg` |
| `DEBUG=1 .local/venv/bin/python task.py` | `python` |
| `env DEBUG=1 python task.py` | `python` |
| `cd project && python task.py` | `python` |
| `git status --short` | `git` |
| `git status && pytest -q` | `git` |

具体命令名保持原样，不把 `python3` 合并成 `python`，也不把 `git status` 的子命令作为名称保留。简单定位操作、环境变量和可安全识别的 shell / 启动包装先剥离，再取可执行文件 basename。

一个 shell 活动包含多个命令时，主行使用首个可可靠识别的实际命令；这不证明后面的命令已执行。独立的命令活动各自显示名称，沿用已有并行活动计数与详情。

### 4.2 解析边界

- 列表和普通活动详情均不展示路径、参数、flag 或命令正文。
- 名称必须来自已收到的完整命令 token；不把 `.local/venv/bin/py` 等尚未结束的前缀直接当成 `py`。
- 首个命令 token 已完整、参数仍在生成时，可以显示名称，不必等整段输入完成。
- 遇到动态表达式、未知包装、截断或不能可靠解析的 shell 语法时，使用通用状态 / 工具名称，不展示原参数作为回退。
- 沿用现有有界扫描，不执行 shell 或 JavaScript，不读取脚本内容来推断操作，也不尝试实现完整 shell 解释器。
- 现有诊断摘要可以按原边界保留；本轮不扩大正文、完整参数或生成代码的落盘范围。

## 5. 刷新与耗时

- 终端看板每秒进行一次定时数据刷新，`watch --json` 和非 TTY 的连续快照输出也改为每秒一次；`--once` 仍只输出一次。
- 用户选择聊天、展开详情或切换语言后立即更新界面；这些主动操作不必等待下一次定时刷新。
- 事件实时接收与指标内部时间精度继续保留；1Hz 不通过丢弃事件或延迟处理事件实现。
- 已知耗时不足一秒时，耗时单元格留空，不显示占位文案。其余秒数向下取整：小于一分钟使用 `Ns`，达到一分钟使用 `NmSSs`，达到一小时使用 `NhMMmSSs`。未知耗时继续显示 `—`。
- 时间边界示例：`1s` → `1s`，`59.9s` → `59s`，`60s` → `1m00s`，`3599.9s` → `59m59s`，`3600s` → `1h00m00s`，`3723s` → `1h02m03s`。
- 生成速度仍显示现有精度，例如 `≈24.6 token/s`；本次整秒要求仅针对耗时。
- 短操作继续保留在活动详情 / 最近活动中，不通过伪造运行时长来让它出现在主行。
- 完成后的耗时冻结；断连、快照过期和观测缺口继续使不可信的运行状态与速度失效。

## 6. MCP 产品名与工具名

产品名与工具名分别解析，并与协议身份分开保存。候选名称按以下顺序选择：

1. 提供方明确给出的面向用户的展示名称 / 标题，例如同一调用的 `appContext.appName/actionName`，或有可靠身份关联的产品、插件、服务与工具目录展示元数据。
2. 没有展示名称 / 标题时，使用提供方声明的名称。
3. 前述元数据不可用时，使用清理后的实际服务短名与工具短名；仍缺失时省略缺失部分，最终回退到通用状态。

所有 MCP 使用同一套优先级和清理规则，不维护手工产品别名表、不硬编码特定服务的改名规则。

工具优先使用已有标题 / 动作名称，无此信息时保留 `js` 等真实工具短名。产品名、命令名和工具标识不由界面语言自动翻译；工具提供方已有的展示标题按原值使用。

需要覆盖直接 MCP 调用和 Code Mode 中识别出的 MCP 名称。只看到生成脚本中的名称时，仍按准备阶段展示。产品名后来补齐可以更新展示，不创建新活动、不重新开始计时。

当前生命周期事件不保证每个工具都带产品名或展示标题。实现必须有可靠回退，不从长描述猜品牌，不使用无关联的目录记录补齐，不为取名主动向正在使用的 app-server 注入请求。

## 7. 多语言范围

### 7.1 本轮交付

- 中文文案集中管理，包括表头、活动 / 结果状态、空状态、连接状态、页脚按键提示、CLI 用户提示以及时间与数量表达。
- 内部使用稳定的状态值和消息 key；数量、名称等作为参数传递，不拼接中文来表达复数。
- 默认语言为 `zh-CN`；界面设置与采集器 / Codex 配置分开。
- 准备 `watch --lang <语言代码>` 的显式选择、保存的用户偏好和可用语言切换机制，切换只影响展示。
- 语言资源可扩展到 `en`；完整英文翻译不属于本轮必需交付。

### 7.2 实现约定

- 可用语言列表只包含已经完整提供资源的语言。英文资源未补齐时，不提供一个实际仍显示中文的“English”选项。
- 显式 `--lang` 作为本次启动覆盖；未指定时读取保存偏好，再回退到中文。用户在看板中主动切换的选择持久化。
- 建议预留 `l` 为切换语言按键；有至少两种可用语言时才在页脚提供入口。
- 不支持的显式语言代码给出清楚的错误；旧偏好引用已不存在的语言时回退中文，不影响采集。
- 快照字段、活动 ID、状态值、模型名和诊断协议不随语言变化。已有中文标签可作为旧快照兼容字段，新的看板优先使用结构化消息。

英文资源补齐后的目标示例为 `Preparing · python`、`Running · Product name · Tool name`。这些是后续语言示例，不是本轮已实现结果。
