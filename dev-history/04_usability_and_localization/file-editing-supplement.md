# 文件编辑展示补充

日期：2026-10-13。实现与相关回归已完成；精简证据见 [补充验证记录](file-editing-validation.json)。这是原易用性实施之后的增量，原验证文件保留其当时版本的源码指纹。

## 需求与范围

用户希望看到正在编辑的文件，替代 `准备中 · apply_patch`。支持直接 `apply_patch` / `functions.apply_patch` 的补丁输入，以及 `exec` / `functions.exec` 中静态的 `tools.apply_patch(...)` 字符串参数。

| 情况 | 展示 |
| --- | --- |
| 工具已识别，文件名尚未完整生成 | `编辑文件` |
| 正在生成一个文件的补丁 | `编辑中 · first.py` |
| 已生成两个文件头，当前编写第二个文件 | `编辑中 · second.py（另 1 个）` |
| 输入完整，但正式执行还未确认 | `编辑中 · first.py（另 1 个）`；内部仍为 `tool_ready` |
| 正式文件修改事件开始 | `编辑中 · first.py（另 1 个）`；内部为 `tool` |
| 已结束详情 | `编辑文件 · first.py（另 1 个）`，结果另列显示完成 / 失败等真实状态 |

“编辑中”涵盖编写补丁与应用修改，不据此宣布落盘成功。审批、观测缺口、断连与失败继续按原状态显示。其他终端脚本或 MCP 只有既有明确的文件修改事件才采用文件展示，不从任意脚本猜编辑目标。

## 实现步骤与实际结果

1. `tool_labels.py` 新增有界补丁文件头识别。只有完整换行结束的 Add / Update / Delete / Move 文件头才提供名称，生成中的文件名留空。准备阶段跟随最近完整文件头；重命名使用目标文件名。
2. Code Mode 沿用已有字符串、注释与调用扫描器。只解析最近可识别直接工具调用的静态补丁字符串；变量、拼接、模板插值、假调用与 MCP 同名工具使用保守回退。后续出现命令调用时恢复该命令展示。
3. 引擎保留 `file_edit_preview` 和显式 `call_id` 元数据；生成速度依旧从原始模型输入统计，快照仅保留有界文件名、数量和当前目标，不保存补丁正文。
4. 正式 fileChange 开始建立执行时间，重复开始不重置时间；晚到的模型输入完成不能把正式执行降回准备，也不能重开已结束的文件修改。仅收到完成事件时不补造执行时长。
5. 直接调用的输入活动与正式文件修改 ID 不同时，只有明确匹配的 call_id 才隐藏重复准备行。Code Mode 外层沿用已有执行期间的隐藏规则；观察到正式编辑后仍未结束的外层准备上下文使用 `处理中`，不宣称它的内部编辑全部完成或仍在编辑。
6. 文案使用现有多语言资源机制，主行、详情、最近完成项和旧快照回退共用文件展示。定时刷新继续 1Hz，采集器内部节奏不变。

扫描预算为 64 KiB，保留文件数最多 64、文件名最多 160 字符。超过预算、动态表达式、控制字符和不完整路径保守回退；这些情况可能只显示 `编辑文件`，不运行生成代码取名。

## 验证与运行边界

相关检查覆盖补丁分块、Code Mode 字符串转义、多个文件、重命名、正文伪文件头、动态输入与预算、明确身份去重、乱序完成、审批 / 并行、失败、完成耗时冻结、旧快照、既有命令 / MCP 展示与生成计数。具体用例、运行数量和源码指纹见补充验证记录。

合计 94 个不同用例通过。首轮运行 90 项，运行恢复检查 2 项，补充状态检查运行 75 项，最后文件头解析检查运行 24 项，其中存在重复用例；数量以去重后的测试 ID 为准。运行快照采样不计入测试数量，也不替代原生界面验收。

采集器通过原控制接口重载，Codex App 保持运行。日常连接恢复和真实文件编辑的观测结果分别记录；未把单元测试或合成渲染当作原生界面验收。

一次短采样未捕获编辑阶段；随后对本轮真实文档修改采样，观察到 Code Mode 输入生成阶段的 `编辑中 · file-editing-supplement.md`、正式 fileChange 的结束记录，以及外层准备上下文退为 `处理中` 并隐藏。两次采样的界限如实记录，运行记录只包含状态与文件名，不保留补丁正文或聊天内容。直接 freeform 调用、多文件和乱序边界的验证来自过滤器 / 引擎用例；没有扩大为所有调用方式的自然使用结论。
