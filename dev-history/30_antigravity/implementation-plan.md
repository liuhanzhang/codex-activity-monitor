# Antigravity 只读接入方案

方案日期 2026-11-15，Monitor 基线 `d319ffb`。本章记录待实现方案。首轮目标是在本机独立版 Antigravity Desktop 提供可见正文速度、会话用量、实时 Agent 活动、历史时间线和可用的活动详情。字段覆盖与验证边界见 [实验与结果](experiments.md)。

## 发现后端与会话

1. **识别本机 Language Server。** 为 Antigravity 增加独立的数据来源。识别当前用户下由已安装 Antigravity 启动的桌面 Language Server，核对可执行文件及监听端口归属。采用包内证书验证回环 TLS，在进程内使用该服务的临时本地 CSRF 值。服务 PID、端口轮换后重新识别，采集端只连接同用户的本机服务。调试日志记录连接结果与计数即可。
2. **维护会话目录。** 读 `GetAllCascadeTrajectories` 获取轨迹、状态和工作区等摘要，定期更新目录。启动时查已有会话，同时发现新会话及从空闲转活跃的会话。目录查询频率与订阅回收时机由短回合和后台场景的实测确定。若目录刷新发现新会话过晚，继续验证原生只读的会话发现信号。
3. **独立订阅。** 对要观察的会话用各自的 `subscriberId` 调用 `StreamAgentStateUpdates`，保存 `conversationId`、`trajectoryId` 和 `stepsUpdate.indices`。订阅生命周期由 Monitor 管理，支持后台会话和并行会话。连接恢复后先接收当前快照，再继续计量新到达的内容。

产品采集调用只读 RPC 和本地历史读取，可接入已经运行的 Desktop。测试 Hook 用于实验对时，`--vmodule=stream_helpers=2` 用于上游对照。两者均为实验手段。 [只读发现与订阅复测](experiments.md#只读发现与订阅复测)

## 实时速度和终态用量

- 以来源、会话、轨迹、步骤标识正文流。正文按快照更新，重复帧不进入计数。观察期间的第一段新正文开始计量。中途接入或重连时，以首次看到的现有正文作为基线。快照发生改写、截断或回退时重设基线，保留时间线中的观察缺口。
- 对同一步骤的累计正文分词。以单调时钟记录接收时点，在刷新时计算最近一秒两端的累计计数差。完整观测窗口没有新正文时为该窗口零到达量。断线等未观察区间可复用 Monitor 的覆盖和不可用提示。展示口径标为估算的正文接收速度。
- 按实际模型选择已验证的分词器。对 `gemini-4-argon`，Gemma 4 在当前中文样本中比 `o200k_base` 更接近服务端用量，可作为首轮近似分词候选。实时报数保留估算属性，其他模型或 tokenizer 不可用时按实际覆盖展示。分词使用现有资源预算和异步计数机制，确认离线资产能随桌面分发。 [分词对照](experiments.md#token-计数和分词误差) · [现有计数器](../../src/codex_activity_monitor/metrics.py)
- 完成后读取 `metadata.modelUsage`。可用时优先使用 `responseOutputTokens`、`thinkingOutputTokens` 及输入和缓存用量字段做会话统计。可见正文、思考和总输出保持源字段的口径。同一步骤重复出现时更新同一条用量记录。请求起止边界有依据时再把终态用量与对应耗时配对，用于每轮平均速度。已经展示过的实时窗口保留当时的估算值。 [Monitor 平均速度的计量口径](../24_average_token_speed/README.md)
- 思考摘要可用于活动详情。思考用量以模型步骤终态为准。实时 tok/s 首轮覆盖可见正文，逐秒思考量和工具参数生成速度分别保留待验收状态。

## 活动、历史和 Monitor 集成

| 数据 | 采集和展示方式 |
| --- | --- |
| Agent 和回合 | 将已确认的用户输入、模型步骤、运行状态和空闲信号绑定到对应会话与回合。按实际收到的步骤类型和状态更新活动。状态流只给出 `GENERIC` 时，暂用通用的步骤状态。 |
| 工具 | 按会话、轨迹和步骤索引跟踪等待、运行和结束。优先使用帧中可确认的工具信息。对于通用步骤，用只读 `GetCascadeTrajectorySteps` 从对应步骤索引查询类型与详情。类型、参数和输出在读取到后再补入同一条活动。已验证完成后查询，运行中可获得的字段待验收。 |
| 历史和用量 | 只读索引 `~/.gemini/antigravity/brain/<conversationId>/.system_generated/logs/transcript.jsonl`。用会话及步骤索引补齐已落盘的消息、工具调用和用量，与独立订阅的活动去重。默认路径之外按实际应用数据目录定位。SQLite 在实验中用作终态交叉验证。 |
| 标识与时间 | 在采集端保留应用来源、会话 ID、轨迹 ID、步骤索引和有依据的回合关联。重启后的新连接有独立的观察区间，历史身份按稳定会话和步骤关联。持久化的创建、完成时间与本机观测时间分别记录，历史只回补存有依据的字段。 |
| 子 Agent | 找到稳定的父子关系字段后，将子 Agent 纳入相应会话的独立时间线。并行打开两个会话只验证了会话隔离，父子轨迹身份需用实际子 Agent 场景验收。 |

实现 Antigravity 的接收和历史读取入口，在进入 Monitor 的速度、活动和用量模型前转换为一套共用语义。现有 `Engine.ingest` 的输入含 Codex app-server 约定，历史定位依赖 Codex rollout，接入时先区分数据来源和协议映射，再复用后续展示、时间线和计数逻辑。Antigravity 的启停与 Codex 启动集成各自管理。概览和诊断显示活动所属的应用与连接状态。实时详情按收到的数据展示，完成的详情由对应历史读取入口提供。只在 Monitor 自有目录保存必要的索引、状态和诊断。 [实时入口](../../src/codex_activity_monitor/engine.py) · [历史读取](../../src/codex_activity_monitor/history.py) · [Codex rollout 定位](../../src/codex_activity_monitor/history_source.py) · [Antigravity transcript 路径](https://antigravity.google/docs/hooks/)

## 实施顺序与验收

| 顺序 | 要交付的能力 | 验收场景 |
| --- | --- | --- |
| 1 | 只读发现、订阅和重新连接 | 在正常已运行的 Desktop 上发现旧会话、新会话和已开始生成的会话。验证从目录发现到收到首帧的时延，覆盖短回合、并行和切到后台。重启 Monitor 和 Desktop 后重新识别端口，检查已收到的正文和用量没有重复计入。 |
| 2 | 估算速度和实际用量 | 英文、中文和跨过一秒的正文间隔。覆盖重复快照、非追加修改、中途订阅、断线重接和终态补齐。按轮对照状态流、历史和桌面用量拆分。 |
| 3 | 活动时间线及历史详情 | 复跑命令等待、运行、结束。在运行中读取同一步骤，验证具体工具名、参数和输出最早何时可见。覆盖失败、取消、审批和其他主要工具，检查 JSONL 新增及字段缺失时的显示。 |
| 4 | 协作场景和版本验证 | 主 Agent 与真实子 Agent、多个并行会话、两种应用同时运行、长时间空闲、连接失败和应用升级。确认关系和来源正确归属，缺口可识别。 |

当前只读发现复测时目录里的会话全部空闲。实际新会话出现到首次订阅的时延是首个验收项。完成前三项后即可核对核心功能，工具覆盖、子 Agent 关联和不同 Antigravity 版本的兼容性以对应验收结果为准。
