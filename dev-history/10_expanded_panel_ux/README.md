# 展开面板：信息结构与交互重设计

日期：2026-10-19。状态：已实现，完成定向测试与本机原生检查，已加载到日常 Monitor。源码基线为 `36ff3bf`；本轮改动与证据见[实施结果](implementation-results.md)。

## 目标

用户打开 Monitor，先掌握哪些聊天正在工作、各自在做什么，再查看某个聊天的轮次进展，最后按需检查具体活动。连接、聊天、轮次、活动和统计各有归属，避免全部平铺、视觉权重相同。

本轮仅修改最新设计图 1 对应的展开面板，沿用已经完成的时间线。图 2 的单聊详情页取消，图 3 对应的独立活动窗口保持现状。

## 本轮确认的决定

| 编号 | 决定 |
| --- | --- |
| D01 | 以“聊天 → 轮次 → 活动”组织内容；聊天与轮次信息全部在展开面板内组织，点击活动继续打开已有独立窗口。 |
| D02 | 正在运行的聊天默认展开，直接看到本轮时间线与简要统计；最近完成分组默认收起。 |
| D03 | 多个运行中的聊天都可展开；不新增单聊详情页，也不保留“查看详情”跳转或返回概览入口。 |
| D04 | 同一次打开面板期间，用户手动收起后，刷新不能重新展开；手动展开同样保持。 |
| D05 | 展开控件位于标题左侧，优先使用 SwiftUI 原生 `DisclosureGroup`；标题区域整体响应原地展开／收起。 |
| D06 | 轮次切换、时间线、简要统计与模型／数据说明留在每个聊天的展开区，按轮次归组。 |
| D07 | 时间线之后的统计区采用[聊天详情概念图](assets/chat-detail-concept.png)中的两列排列：左列输出及其包含的推理用量，右列推理均速；标签在上，突出数值在下。模型和数据口径放在次级说明中。 |
| D08 | 统计必须说明所属轮次，缺失或无法可靠归属时显示未知；不能把当前轮数值挂到所选历史轮次下。 |
| D09 | 独立活动窗口的布局、控件和行为本轮不改；面板继续调用既有单项／多项查看入口。 |
| D10 | 时间线位置、缩放、短线、命中、选区、结果图标及来源语义沿用第 09 章，不重新设计。 |
| D11 | 聊天与轮次容器使用中性原生分组，不以大面积蓝／紫底表示运行或本轮；时间线内既有活动选区保留。 |

最新范围限定优先于早期“三屏流程”设想。最新图 1 中的“查看详情”文字入口也取消；图 2 的独占页面和图 3 的窗口改造退出本轮范围，但 `chat-detail-concept.png` 的统计区排列继续作为本轮局部设计依据。概念图是视觉参考，最终行为以上表和设计说明为准。

标题、原生尺寸和动效参数属于实施建议，需用实际 macOS 控件验证；本章不把生成图中的像素当作已经确认的原生参数。

## 本轮改动范围

- 概览中的工作分组、聊天摘要、默认展开和连接异常层级。
- 聊天与轮次的视觉归属、统计摘要和补充说明。
- 原生展开控件、标题点击、悬停、键盘和辅助功能。
- 中性背景、清晰分组和既有活动窗口的调用入口兼容。

本轮不新增面板内页面路由，不改造独立活动窗口，也不删除或迁移该窗口原有的时间线、参数／结果、分页、复制及窗口复用功能。

不新增任务百分比、ETA、聊天控制、审批或用户输入操作，不修改菜单栏动画、采集与用量计算、历史身份关联、配置恢复及观察租约。历史统计不可用时先诚实降级，不为界面重构建立一套新账本。
