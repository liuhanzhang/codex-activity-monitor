# 实施计划

日期：2026-10-20。状态：P0–P5 的代码、定向检查与日常更新已执行；自然运行的父聊天结束转换仍有观察边界，详见[实施结果](implementation-results.md)。基线：`728af1e47d84`。问题编号与诊断范围见[本章说明](README.md)。

## 1. 修复完成后的行为

| 场景 | 预期 |
| --- | --- |
| 子智能体给父级或同级发送消息 | 对象显示正确，不生成新的父子层级或额外聊天组 |
| 三个子任务先后完成、过期，只剩一个仍在快照中 | 已确认的父子关系保持，不因可见线程数量变化而改变方向 |
| 最近完成数量达到上限 | 上限作用于十个主聊天组，不能先截断子线程再把它们提升为主聊天 |
| 已知是子智能体，但父信息尚不可用 | 保留“归属待确认的子任务”提示及可用历史入口，不计入独立主聊天数，不猜父级 |
| 所选范围的所有工作轮已明确终止，仅个别阶段记录缺失 | 组显示相应结束状态，同时提示部分活动记录不完整；阶段本身保持未知 |
| 同一子智能体被追加任务 | 使用追加轮的明确父轮归属，完整身份及已有展开、选中状态保持 |
| 创建、发消息、追加任务具有明确调用证据 | 在已有阶段显示协作动作与对象，不创建额外执行条或改变参数生成所属模型轨 |
| 明确的全局等待／目标缺失的等待 | 分别显示“等待子智能体消息”／“对象未知”，不把全局等待虚构成当前所有 child 的对象集合 |

保留现有按轮查询、默认轮次、来源时间、phase ID、原始参数／结果、用量与速度定义、420 pt 面板，以及面板和独立活动窗口的两种布局模式。单项工具失败不自动等同于整个轮次失败。

## 2. 关系与身份：分开处理三个问题

### 2.1 父子层级

建立按 `(scope_id, thread_id)` 索引的层级元数据，明确区分 `user / subagent / unknown` 来源和父身份的来源、有效性。优先使用已校验 session header 的 `source.subagent.thread_spawn.parent_thread_id`，或已有真实协议样本能证明的创建关系。先验证 header 的 `payload.id`，再接受有界、非自身的完整父 ID；父级查找限定同一 scope。冲突、循环、错误类型、文件替换或身份失败必须产生质量说明并失效旧缓存，不能静默选择一个父级。

普通 `send / interacted / wait / completed` 对象关系不建立父子层级；`subAgentActivity.kind=started` 也不能脱离创建调用或 header 证据单独解释为 spawn。`subagents` 不能继续兼任“通信对象集合”和“真实后代集合”。Python 汇总与 Swift 回退采用一致的证据规则，已确认的结构边不能被低置信通信回边抵消。

### 2.2 父轮与活动所有权

线程的父身份只决定层级，不决定某个 child turn 属于哪个父轮。已有 `parent_turn_id`、明确创建调用与初始子轮的受限规则继续约束工作引用；复用缺少父轮归属时仍为未知。不能因 header 指向某父线程，就把子线程所有历史轮次挂到当前父轮。

层级筛选负责排除父级／同级通信对象；明确协作引用负责确定本轮实际关联的工作。历史与实时路径都执行这一判定，并保留非层级的对象引用供协作详情使用。

### 2.3 协作对象

协作对象是调用引用，可为父级、同级或子级；对象出现在一次消息中不意味着必须加入 `agents[]` 成为独立轨道。关联使用相同 scope、调用线程、调用轮次下的明确 ID：canonical `item_id` 或 raw phase 的 `call_id` 与结构化事件调用 ID 对齐。名称、路径尾段、代码文本和相邻时间不参与身份匹配。

已有 relation 元数据和旧 sidecar 继续保留。查询时依据已验证层级及操作类型分类，旧 `interacted/completed` 记录不再直接用于建立层级。优先通过现有记录和查询派生字段完成修复，不迁移 SQLite 表结构、不清库、不重写 Codex JSONL；确有新增持久元数据时，只扩展 metadata allowlist 并验证旧记录兼容。

## 3. 快照与最近完成列表

快照增加或完善可选的线程角色、父身份来源及关系质量信息，Swift `Chat` 解码这些信息。旧字段缺失时保守回退：只采用有明确创建语义的已知结构边，不再从普通通信对象猜父级；旧快照无法确认的对象不冒充已验证层级。

列表按以下顺序计算，正在进行和最近完成共用同一归组结果：

1. 对完整候选集合解析同 scope 的层级，形成主聊天及后代组。
2. 按组内实际活动判定进行中状态；组内最近活动时间取可确认成员时间，不为延长显示期限制造新时间。
3. 保留现有十分钟最近完成窗口，按组排序，对最近完成主组取十组；子线程不占独立聊天名额。
4. 形成列表行与数量，子智能体的活动轨继续在主聊天详情中展示。父上下文暂缺时保留明确父引用和必要的上下文，状态无法确认则显示未知；不能因筛选、过期或数量上限把 child 提升成普通主聊天。
5. 不能恢复父级的已知子任务使用单独的“归属待确认的子任务”提示和可展开入口，不混入主聊天计数；身份后补全时按完整 ID 归组，保留可迁移的选择与阅读状态。

检查 Python `Engine.tick()` 的线程过期和 collector 的重启快照恢复路径：仍被可显示后代引用的父身份只保留必要元数据，不长期保留其完整 activities；重启恢复不能重新采信旧的错误父子边。列表计数、菜单会话数和图标模式使用相同的真实主聊天归属，生成总速度仍按独立流计算，不能改成对子组行求和。

身份补充不能在 collector 持有事件锁时调用完整历史解析或每 250 ms 全目录扫描。复用现有已定位路径和身份缓存，增加只读 header 元数据读取；缓存未命中在有界后台工作中解析，失败／缺失退避重试，快照先降级。查询仍保持每个不同线程每请求至多加载一次，不能为了查一个协作对象名称再次扫描其完整会话。

## 4. 组状态与阶段记录质量

`scoped_status` 仍只观察所选父轮明确引用的 turns／phases，不使用子线程其他轮次的最新全局状态。将轮次状态与阶段记录完整性分开输出，增加可选的活动质量字段；具体字段命名可随实现调整，语义固定如下：

| 证据 | 组状态 | 记录提示 |
| --- | --- | --- |
| 没有明确关联的工作轮 | 未知 | 关联不完整 |
| 有可靠的 active／waiting 阶段，包括确证仍运行的后台工作 | 活动中／等待中 | 保留其他阶段自身质量 |
| 所有被引用轮次都有可靠终止状态和结束记录，仅剩缺少 item end 或未保留内容的阶段 | 已结束／已停止／失败，按轮次终止状态聚合 | 部分活动记录不完整 |
| 有未终止的关联轮次，但没有可靠的当前阶段 | 沿用未知降级 | 当前活动证据不足，不假定正在思考或等待 |
| 来源身份、观察中断或生命周期证据冲突，无法确认引用范围已终止 | 未知 | 明确相应缺口或冲突 |

明确完成记录可以结束该轮的组状态，但不能补造阶段的 `end_ms`、耗时或内容。可靠后台活动与终止记录并存时，先保留真实活动证据；无法判断是否滞后的冲突记录不能直接按结束覆盖。多个 child turns 必须全部满足终止条件，不能在追加轮仍运行时因首轮完成就显示结束。

主组和子组都能展示记录不完整提示；当前主组 `partial=false` 的固定值需要调整。阶段 `unknown / missing_item_end` 及详情的 `not_retained / source_truncated / unavailable` 等含义保持，不用组完成状态“修复”为阶段完成。已有测试中“完成轮含缺失阶段必须整体未知”的断言需要按本章规则有针对性地更新，仍保留断连与真正活跃阶段的防误报测试。

## 5. 协作动作和等待文案

将展示投影从仅 canonical `collabAgentToolCall` 扩展到有明确协议证据的 raw 调用阶段。使用正式 namespace／name（或其已验证的完整工具名）、匹配的结构化调用 ID 和对象 ID，覆盖本次实际的 `spawn_agent / send_message / followup_task`，分别显示派发、发送消息、追加任务。不能因为任意 `exec`、字符串、同名普通工具或注释里出现 collaboration，就把它识别成协作。

投影只添加动作、目标和目标范围等展示元数据。raw 参数生成仍属模型轨、保留原 kind 与颜色；canonical 执行阶段仍属工具轨。已有输入与执行都有记录时保留其各自含义，禁止由 `subAgentActivity` 合成一条执行时长为零的新工具阶段。bundle、detail、辅助功能描述使用一致语义；对象不在轨道组内时仍可按完整 ID 展示，不为取得名称创建虚假子组。

等待目标范围区分三态：

| 范围 | 所需证据 | 展示 |
| --- | --- | --- |
| 指定对象 | 明确结构化接收对象 ID | 等待及具体对象名称／数量 |
| 全局等待 | 原始正式等待调用结构明确表达未指定对象；本次 `collaboration.wait_agent` 只有超时参数即属此类 | 等待子智能体消息 |
| 未知 | 只有空对象列表，缺少可确认调用语义或来源尚不可用 | 协作等待／对象未知 |

不能仅凭 `receiverThreadIds=[]` 就判全局等待，也不能把全局等待自动绑定到当时所有 child。旧 DTO 缺少范围字段时沿用保守未知。原始参数／结果及其分页、复制保持原状。
