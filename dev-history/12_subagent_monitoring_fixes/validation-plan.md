## 2. 固定来源对照

使用相同来源副本、观察元数据与固定查询时间对照修复前后结果，按实际应变化的字段核对：

- F01 允许移除错误父／同级子组、修正父关系及列表根数；此前错误归入的非本轮工作允许被排除。正确主视角已有活动的 owner、ID、时间不能因此变化。
- F02 允许组状态与质量提示变化；阶段的 `status / start_ms / end_ms`、缺失内容状态保持，不为通过测试补齐时间。
- F03／F04 允许新增动作、对象、范围及文案；原有阶段的数量、ID、thread／turn 所有权、track／kind、来源时间、原始参数／结果保持。模型参数生成仍画在模型轨。
- 本次最初工作轮的参考样本为 190 个活动阶段和 1 个用户输入标记，Fermat 有两个明确子轮；只有固定同一来源快照时才比较这一计数，不能把数字写成所有查询的固定预期。
- 当前轮没有 child 时仍只显示当前轮活动；切回最初工作轮仍能看到三个 child。此项是防越界回归，不实现新的历史提示或默认轮次策略。

速度继续按独立流计算，用量继续使用官方所属 turn。列表主组计数变化不能改变生成流集合或重复累加 token。

## 3. 原生定向检查

先用脱敏 fixture 检查 420 pt 浅／深色面板中的正常主组、回信子任务、父上下文缺失、归属待确认入口、结束＋部分记录以及三类等待。再验证键盘展开、活动选择、滚动位置、刷新后归组和主／子状态提示，保存实际截图与交互结果。

只检查共享文字与布局受影响的独立活动窗口：原始参数／结果、分页、复制和既有选择功能。没有尺寸／生命周期改动时，不重复完整窗口验收；出现兼容失败再扩大范围。合成截图不作为自然运行证据，也不声称覆盖整个 VoiceOver 流程。

## 4. 性能与运行边界

保留重复关系只加载不同线程一次的现有回归，补充列表身份缓存、未知身份退避及 collector 事件处理不被 header 扫描阻塞的检查。以同机相同样本记录首次／后续查询、目录查找次数、header 读取次数和快照新鲜度；不复用旧版本延迟数字作为新实现成绩，不扩大为通用性能基准。

推荐复用仓库 `.local/venv` 运行所选 Python 用例，避免系统 Python 缺依赖造成无关失败。Swift 先执行受影响模型／App 用例，原生构建沿用现有脚本。具体命令及实际通过数已在实施结果中记录。

## 5. 日常真实场景与交付

实施并按既有流程更新日常版本后，进行一次有限的真实运行：创建三个 child，让其中一个完成后接一次追加任务，并发生 child 向父回信；任务内容保持只读或使用隔离临时数据。核对运行中状态、追加轮归属、全部结束后的“最近完成”主组及协作详情。自然等候过期不是必需前置步骤，先用可控时间 fixture 验证过期边界，真实运行只补充可观察证据。

真实验收同时保存脱敏快照／查询元数据和原生画面；数据链路正确不能代替画面验收，画面正常也不能代替工作归属与原始详情核对。若存在其他聊天，使用明确 scope／thread／turn 隔离本次结果，不能从全局计数变化猜本次行为。

完成后新增 `implementation-results.md`，至少记录实际文件范围、命令与通过数、数据／原生／自然运行分别覆盖什么、构建与加载指纹、性能样本、接入恢复记录是否保持及未验证限制。Git 只保存脱敏必要证据，完整会话和运行数据库留在忽略目录。没有真实验收时明确标记尚未验证，不以“测试通过”代替整体交付。
