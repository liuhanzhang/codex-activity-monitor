实现方向

先使用现有接收层日志，由旁路进程按聊天和调用聚合指标；保持原始 harness、tool mode、请求及认证路径。
正文与工具参数分别统计累计字符/UTF-8 字节、最近 1–2 秒接收速率、最后一次事件距今时长。
结合 app-server 的命令执行、工具完成、等待审批等事件，区分生成工具参数和实际执行工具。
API usage 用于完成后的精确用量；实时 token/s 在缺少准确 tokenizer/逐 token 数据时应标为估算或采用字符/s。
日志不能覆盖的连接才考虑同时支持 HTTPS/SSE 和 WSS 的本地代理。
普通网络抓包只能看到 TLS 加密流量；连接保活也不能充当模型生成进度。

边界

RUST_LOG 是官方文档公开的配置；具体接收日志文本并不是稳定监控协议，升级后需要兼容性检查。
本次 trace 日志约 48 MB，包含重复的协议帧诊断和其他聊天预热事件，不适合原样长期开启。
正式采集应仅保留需要的事件指标、限制日志量，并测量 I/O 和延迟开销。
这次没有做性能开销基准；不能宣称开启 trace 完全没有运行时影响。
